> ⚠️ **两处口径冲突，动前端前先读**：
> 1. **基座自带契约 ≠ 本项目契约**。基座自带 `src/views/system/dict` 等示例页与 `/dict/*` 之类的接口约定；本项目既有契约是 `/authority/*`（如 `pd-admin-ui/src/api/Dictionary.js`）。**方向固定为「契约优先、基座适配后端」，禁止为迁就基座新建第二套后端服务或第二张业务表。**
> 2. **D-28 文本里的目标版本（Vue 3.4 / Vite 5 / Pinia 2 / Router 4 / ECharts 5）是拍板当时的基座版本**，实际拉取的基座已滚动到上表实测值。版本以本表实测为准，D-28 的迁移**方向**不变。

## 5. 版本基线与硬约束（2026-10-08 全栈升级后）

> 🔴 **本节为改写后的现行约束。** 本节原题为「版本锁死与硬约束」，其中「JDK 1.8 锁死 / 不升级依赖 / 安全 CVE 暂不处理 / 管理端 Vue3 不做 / 网关不换 Zuul」**五条已于 2026-10-08 全部废止**（定案 D-28 / D-29 / D-32）。若你（或大模型）在其它文档里读到这些旧表述，**一律以本节与《需求文档/12-ClaudeCode开发纪律与红线.md》为准，旧表述作废**。

| 约束 | 现行说明 |
|------|----------|
| **JDK 固定 21 LTS** | Eclipse Temurin。升级前为 1.8；`Lombok 1.18.x 依赖，升级 JDK 会崩` 的旧说法已证伪 —— 真因是 Lombok 需 ≥1.18.30，属可解 |
| **依赖锁定在升级后基线之上** | 目标是 D-29 的 16 项（SB 3.3 / SC 2023 / MP 3.5 / Shiro 2.0 / Drools 8 等）。**"不升级依赖"已废止**；但升级只走这一份清单，**不得在任务里夹带计划外版本变动** |
| **安全 CVE 随升级解决** | FastJSON→FastJSON2、Shiro→2.0、Spring→3.3 本身即消解已知漏洞；旧的"暂不处理、上线前重评"表述作废 |
| **不引入新中间件**（仍有效） | MongoDB / HBase / ES / RocketMQ / XXL-JOB / Sentinel 等属路线图，**非本期**；新增中间件须走变更评审 |
| **不过度设计**（仍有效） | 复用既有能力与契约，禁止为假想需求预建抽象 |
| **MySQL 5.7.44（迁移前环境事实）** | 不支持窗口函数（`ROW_NUMBER()` 语法报错），批量脚本需用用户变量。**升 8.0（D-29 ⑬）后此限制解除**，脚本改动以升级周计划为准 |
| **管理端 = Vue3 + vue3-element-admin 基座** | 禁止从零设计 UI，必须套基座模板改业务页（D-32）；迁移适配见《需求文档/16-管理端Vue3升级专项实施规范.md》 |
| **移动端 uni-app（Vue3 + Vite）** | 先 H5 + 微信小程序，App 原生后置（D-32） |
| **架构拆分：权限中心 / 物流业务两项目** | D-33；落地节奏为"先在一个项目里跑通，后拆两仓"，本期仍是单仓 |

> ⚠️ **迁移未完成，改代码前先看当前处于哪一步**：`pom.xml` 实测仍为 JDK 1.8 / SB 2.2.5，`pd-admin-ui/` 仍为 Vue 2.6，`pd-admin-ui-vue3/` 是刚就位的新基座。所以"目标基线"是**写新代码的规范**，"升级前基线"是**读旧代码时的事实**，两者并存属正常状态，不是矛盾。
