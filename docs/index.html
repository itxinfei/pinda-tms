核心亮点

为什么是心飞物流TMS

商业 TMS 太贵、旧开源 TMS 太老。心飞想做第三个选择：开源免费、全链路闭环、技术前沿、四端协同。

四端协同

管理端 + 客户端 + 快递员端 + 司机端，覆盖全角色。多数开源 TMS 只有管理端，心飞一步到位。

前沿技术栈

JDK 21 + Spring Boot 3.5.7 + Spring Cloud 2025 + Vue 3.5 + uni-app，同类开源 TMS 中最新的组合。

Drools 智能调度

规则引擎驱动调度与运费计算，规则可视化、可热更新，不用改代码发版，替代 if-else 硬编码。

Netty 轨迹接入

xf-netty 独立微服务自建 TCP 通道，不依赖第三方 SDK，支撑高并发车载终端位置上报。

Sa-Token 多租户

SaaS 化就绪，一套代码服务多个租户，多租户认证与鉴权开箱即用，多数开源 TMS 仍单租户。

清晰的演进路线

Kafka → TDengine / 鹰眼 → OR-Tools → Spring AI 规划落地中，不是做完就停的项目。

解决什么

行业痛点 → 心飞解法

物流行业车辆、司机、线路散落难管，运输不透明，调度与计费靠人工——心飞把这些问题逐一对齐。

车辆 / 驾驶员 / 线路分散，难以统一考核
基础数据集中管理 + 多维统计报表，人车线一目了然
调度靠人工、配载凭经验
定时调度 + 路径规划自动生成运输任务与车次分配
运输过程黑盒，在途不可见
GPS 车辆定位 + 轨迹回放，在途状态实时可查
运费计算不透明、易出错
Drools 动态规则引擎，计费规则可配置、可追溯
客户查件无渠道、签收无留证
客户端 App 查物流 + 电子签收 / 回单留证
数据孤岛、统计靠手工
数据聚合 + 实时分析，经营报表自动产出

快速开始

5 分钟跑起来

Docker Compose 一键起中间件，建库后启动服务即可体验完整业务闭环。

1

克隆仓库

从 Gitee 拉取最新代码（推送到 GitHub 后同样适用）。

# 克隆仓库 git clone https://gitee.com/itxinfei/xinfei-tms.git cd xinfei-tms
2

启动中间件

一键拉起 MySQL / Redis / RabbitMQ / Nacos 等基础设施。

# 起中间件 docker-compose up -d
3

初始化数据库

执行 docs/sql 建库脚本，一键得到 xinfei_tms 单库 + 种子数据（54 张表）。

# 建库脚本在 docs/sql 目录（重构v2 全量脚本 + 演示种子数据） mysql -u root -p < docs/sql/重构v2/00_create_database.sql
4

启动服务与前端

按序启动 xf-auth → xf-gateway → 业务微服务，再启动管理端与移动端。

# 后端（每个微服务目录下） mvn spring-boot:run # 管理端前端 cd pd-admin-ui-vue3 && pnpm i && pnpm dev # 移动端：HBuilderX 导入 pd-mobile 运行 uni-app

代码规范

后端遵循《阿里巴巴 Java 开发手册》，前端遵循 ESLint + Prettier + Stylelint 约束。

提交格式

type(scope): description，如 feat(oms): 新增拆单接口 / fix(dispatch): 修复路线规划空指针。

工程约束

不过度设计、禁止硬编码（cron / 阈值 / 地图 Key / 状态数字一律外部化配置）；所有请求走网关，禁止直连微服务。
