## 2. 第一步：轮换（唯一不可省的动作）

删文件、清历史都收不回"已经被别人拉走"的事实，只有轮换能让旧值失效。

1. **云效 / RDC**：重置该私有仓库的账号口令或访问令牌；随后更新两处引用——
   - 机器上 `/data/m2/settings.xml`（Maven 拉包用，CI 挂载的就是它）
   - `.gitea/workflows/deploy.yml` 里的 `<servers>` 段（该文件只存在于内网 gitea，不入公开仓库）
   验证：`docker exec <job> mvn -B -s /tmp/ci-settings.xml -pl pd-base dependency:resolve` 能过。
2. **Gitea 管理员口令**（`pinda/pinda***`）：Gitea 面板 → 用户设置；改完同步
   - 机器上 `/etc/pinda-gitea-cred`（root 0600，部署状态页读它）
   - 你本地各 remote URL：`git remote set-url gitea http://pinda:<新口令>@192.168.20.130:3000/pinda/pinda-tms.git`
3. **RabbitMQ 口令**：`rabbitmqctl change_password pinda <新口令>`，再更新 `/data/deploy/middleware/.env` 里的 `RABBITMQ_DEFAULT_PASS`（**先改队列账号再改 .env**，否则下次重建中间件会出现"新密码连旧库"）。
4. MySQL root / SSH 口令 `123456`：这台机只在内网且你说过不关注内网安全项，自行决定；若换，记得同步 `.env` 的 `MYSQL_ROOT_PASSWORD`。

## 3. 第二步：清 gitee 历史（可选，做完第 2 步再评估）

**先决条件**：所有协作者（含你另一个工作副本、任何 agent 的副本）都停止推送，否则脏历史会被带回来。

```bash
# 0) 备份（必做）
git clone --mirror https://gitee.com/itxinfei/pinda-tms.git ~/pinda-tms-mirror-backup.git

# 1) 工具：Ubuntu 上 pip install git-filter-repo（或 apt 装）
# 2) 在一份独立克隆里操作，不要在主工作区
git clone https://gitee.com/itxinfei/pinda-tms.git ~/purge && cd ~/purge
git filter-repo --path .gitea --invert-paths          # 整个 .gitea 目录从历史中抹掉
# 若还要抹掉当前树里的明文口令（第 2 步做完后其实已无必要）：
# git filter-repo --replace-text <(echo 'pinda***==>REMOVED-PINDA-PASS')

# 3) 确认历史里再无凭据串
git log --all -p | grep -c -E "ioo7***|pQ2P***"     # 期望 0

# 4) 强推（会改写所有 commit sha）
git remote add origin https://gitee.com/itxinfei/pinda-tms.git
git push --force --all origin && git push --force --tags origin
```

**代价（务必知情）**：
- 全部 commit sha 变化 → 你本地与服务器上的每个副本都要 `git clone` 重来或 `git fetch && git reset --hard origin/master`，**不能简单 pull**。
- 已提的 issue/PR 里引用的 commit 链接失效。
- Gitee 服务端可能仍缓存旧对象（fork / 已拉取的人不受影响），必要时提工单请求清除；**但只要有人已经 clone 过，就当它已永久外泄**，所以第 2 步优先于本步。
- 内网 gitea 是另一套历史，不受这次强推影响；但**别把清理后的分支再推回 gitea**，否则会把 gitea 上仍在用的 `.gitea/workflows/deploy.yml` 一起删掉，流水线立刻停摆。

## 6. 执行结果（2026-10-07 已做完第 3 节，实测记录）

**已清除**：gitee `master` 从 `c801f3e` 重写为 `c7bca81`，`.gitea/`、`settings.xml`、`docs/settings.xml` 从 174 个提交的全部历史中抹掉。校验：`git log -p master | grep -cE 'ioo7***|pQ2P***'` = **0**；提交数不变（174）；新旧树文件清单完全一致（1617 个文件，`diff` 为空）→ 只动历史，不动内容。备份镜像：`C:\Users\itxinfei\pinda-tms-gitee-backup-20261007.git`（234M）。

**清除不掉的三处（已实测确认，不是没做）**：

| 残留 | 实测 | 能否处理 |
| --- | --- | --- |
| `refs/pull/1/*`、`refs/pull/2/*`（两个已 closed 的 PR） | 各含凭据 4 处；`git push` 被服务端拒：`! [remote rejected] (deny updating a hidden ref)` | **客户端无法删除**。关闭 PR 也不删 ref（这两个 PR 本来就是 closed）。只能提 Gitee 工单请求清除 |
| 548 个 fork | 早于本次清除的 fork 已各自持有旧历史 | **不可收回**。这是"必须轮换"的决定性理由 |
| 794 star / 2021 年建仓 | 用"删除重建仓库"来清 ref 的代价 | **不建议**，代价远大于收益 |

**好消息（也实测过）**：默认 `git clone` 只取 `refs/heads/master`，凭据串出现 **0 次**；必须显式 `git fetch origin "+refs/pull/*/head:..."` 才会拿到那 4 处。所以普通访问者拿不到，但**任何懂行的人都能拿到**，且 fork 里本来就有。

**因此第 2 节（轮换）从"建议"升级为"必须"**：历史清除只能防止新增外泄，收不回已扩散的部分。
