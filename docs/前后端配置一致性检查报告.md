## 五、统一整改方案（目标规范 + 改动 + 验证 + 回滚）

### 目标规范（一句话）
**所有微服务统一 `active=prod`；所有 profile 的 Nacos 地址统一占位 `${NACOS_SERVER_ADDR:192.168.20.130:8848}`；该变量由 compose 统一注入；dev/test 不写外网真实 IP。**

### 具体改动
1. **pd-work、pd-web-manager**：
   - `bootstrap.yml`：`active: dev` → `active: prod`；
   - `bootstrap-prod.yml`：`192.168.1.80:8848` → `${NACOS_SERVER_ADDR:192.168.20.130:8848}`（2 处/服务）。
2. **pd-gateway、pd-auth-server**：
   - `bootstrap.yml`：`active: test` → `active: prod`；地址占位统一为 `${NACOS_SERVER_ADDR:192.168.20.130:8848}`（或保留 NACOS_IP 但 compose 同时注入，二选一，建议统一到 NACOS_SERVER_ADDR）。
3. **docker-compose.app.yml**：
   - 在 `x-nacos-env` 增加 `NACOS_SERVER_ADDR: 192.168.20.130:8848`（让占位显式生效，不靠默认值）。
4. **清理外网 IP**：dev 的 `101.43.184.54`、test 的 `47.94.207.39` → 本地用 `127.0.0.1` 或统一占位；`.env.docker` 多租户改 `false`。

### 验证（改完必做）
1. 提交 push 触发 CI，构建部署后：`docker ps` 全 Up、Nacos pinda/pinda-tms 仍为 14 服务；
2. 抽查 jar：`docker cp <svc>:/app.jar` 后用 python zipfile 确认 active=prod、地址=20.130 占位；
3. 页面 `http://192.168.20.130:8080` 登录、菜单、一次下单全流程正常。

### 回滚
- 全部为配置文本改动，git 可整体 revert；镜像 tag 固定（git 短提交号），异常时 `docker compose up -d` 指定上一个 TAG 即可退回。

### 注意
- 整改会触发**全量重建 14 镜像 + 前端镜像**（CPU 密集、约数十分钟）。当前机器 load 已偏高（上一轮 CI 在跑），**建议等其跑完、load 回落到个位数再提交整改**，避免叠加卡死。
