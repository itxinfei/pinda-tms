# 品达物流 TMS — 部署与二次开发指南

> 本文档提供品达物流 TMS 的 Docker Compose 部署、数据库初始化、二次开发指引与排障要点。
> 详细实测步骤见 [部署文档.md](部署文档.md)（Ubuntu 24.04 + Docker）与 [品达TMS-开发测试环境手册.md](品达TMS-开发测试环境手册.md)。
> 技术栈版本与约束见 [技术栈说明.md](技术栈说明.md)。

---

## 1. 环境准备

| 组件 | 要求 |
|------|------|
| 操作系统 | Ubuntu Server 24.04（实测）或其他支持 Docker 的 Linux |
| JDK | 1.8（构建用） |
| Maven | 3.3+（构建用） |
| Docker / Compose | 部署方式（推荐 Docker 27+） |
| 内存 | 实测 15G 内存可跑 15 个容器化服务 + 6 个中间件（注意堆外占用） |

---

## 2. 中间件部署

中间件由 `deploy/middleware/docker-compose.infra.yml` 编排：

```bash
docker compose -f deploy/middleware/docker-compose.infra.yml up -d
```

| 中间件 | 镜像 | 端口 | 备注 |
|--------|------|------|------|
| MySQL | mysql:5.7 | 3306 | 业务库，按服务分库 |
| Redis | redis:5 | 6379 | 验证码 + J2Cache L2（淘汰策略 `volatile-lru`） |
| Nacos | nacos/nacos-server:1.4.1 | 8848 | 命名空间固定 ID，group `pinda-tms` |
| Zookeeper | zookeeper:3.5 | 2181 | Kafka 元数据 |
| Kafka | bitnami/kafka:2.6.0 | 9092 | topic `tms_order_location` |
| RabbitMQ | rabbitmq:3.8-management | 5672 / 15672 | 调度事件 |

> ⚠️ **挂载与持久化**：Kafka / Nacos 配置库 / RabbitMQ / ZK 的部分数据在无卷或匿名卷中，删除容器可能丢数据；备份需显式覆盖这四处（详见 [部署文档.md](部署文档.md) §2.1）。

## 3. 数据库初始化

```bash
# 1) 建 7 个业务库
for db in pd_base pd_oms pd_work pd_users pd_dispatch pd_aggregation; do
  docker exec -i mysql57 mysql -uroot -p${DB_PASS} -e "CREATE DATABASE IF NOT EXISTS $db ...;"
done

# 2) 导入各模块建库脚本（目录含中文：mysql/TMS项目建库脚本）
# 3) 导入权限库 + 初始数据
docker exec -i mysql57 mysql -uroot -p${DB_PASS} pd_auth < pd-authority/pd_auth.sql
# 4) 导入种子数据与机构主表（见 docs/sql/）
# 5) 各业务库建 Seata undo_log 表（7 库均需）
```

> 种子数据脚本：`docs/sql/种子数据初始化_FR00.sql`、`docs/sql/pd_agency_建表与初始化.sql`。MySQL 默认 `autocommit`，`ROLLBACK` 无效，执行前请读脚本头部"试跑验证的正确方式"。

## 4. 微服务部署

```bash
# 镜像 tag 取 git 短提交号
TAG=<短提交号> docker compose -f deploy/apps/docker-compose.app.yml up -d --remove-orphans
```

- **必注入地址**（容器内 `127.0.0.1` 指向自身）：Nacos（`NACOS_IP/PORT/ID`）、Redis（`SPRING_REDIS_HOST` / `J2CACHE_LETTUCE_HOSTS` / `REDIS_HOST` 三个都指宿主机 IP）。
- **启动顺序**：Nacos → MySQL/Redis → Kafka/RabbitMQ → 各微服务 → 网关 → 管理端。
- **端口分配**：网关 8760；pd-auth-server 9000；pd-base 8185；pd-oms 8186；pd-work 8187；pd-user 8189；pd-dispatch 8190；pd-aggregation 8191；pd-netty 8192；pd-web 8161~8164；pd-admin-ui 8080→80。

| 入口 | 地址（示例） | 说明 |
|------|--------------|------|
| 管理端 | `http://<host>:8080/#/login` | pd-admin-ui |

## 6. 二次开发指引

### 6.1 模块结构

- 后端按域拆分（`pd-oms` / `pd-dispatch` / `pd-work` / `pd-base` / `pd-netty` / `pd-user` / `pd-authority`）。
- 跨服务接口契约集中在 `pd-service-api`（Feign 接口 / DTO / 枚举）。
- 前端管理端 `pd-admin-ui`（Vue 2.6 + Element UI）；移动端规划 uni-app（Vue3 + Vite）。

### 6.2 新增接口暴露方式

- 数据层在内部服务 → 由 `pd-web-manager` 聚合 Controller 暴露 → 注册到 `pd_auth_resource`。
- **内部 Feign 服务网关无路由**，不聚合则前端调不到。
- 接口**必须走网关** `:8760/api`，禁止直连 `pd-web-*` 端口。

### 6.3 扩展点（受约束功能的等价实现）

| 外部能力 | 本项目等价实现 |
|----------|----------------|
| AI 告警 / 费用异常 | 规则 + 统计阈值（均值±2σ），`@Scheduled` 扫描 |
| 电子围栏 | 现有 `scope` 多边形 + 轨迹点判定，不引付费地图 API |
| 实时推送 | Kafka/RabbitMQ + 轮询 + Spring WebSocket，不引新中间件 |
| 报表 / BI | 固定报表 SQL + ECharts 前端渲染 |

### 6.4 硬约束（不可变更）

- JDK 1.8 锁死；不升级依赖；不引入新中间件。
- 管理端 Vue 2.6 不迁移；移动端 uni-app（Vue3）。
- 不对接外部厂商 API。
- 状态变更走状态机 + 校验器，禁止裸 `setStatus()`。

## 7. 排障速查

| 现象 | 根因 / 处置 |
|------|-------------|
| 网关 401 | 直连 `pd-web-*` 端口；必须走 `:8760/api`，JWT 头为 `token` |
| 配置读不到 | 命名空间 / group 未对齐（`pinda-tms`）；Nacos 默认账号 `nacos/nacos` |
| Seata `no available service` | TC 必须注册到 `DEFAULT_GROUP`（非 `SEATA_GROUP`） |
| Kafka 连不上 | `KAFKA_ADVERTISED_LISTENERS` 必须是宿主机 IP |
| MySQL `Too many connections` | Druid `max-active` 合计超 `max_connections`；已调服务端至 500 |
| 数据丢失 | 见 §2 挂载说明；删除容器前核对 `.Mounts` |

> 完整排障见 [部署文档.md](部署文档.md) 与各运维文档；[需求文档/环境故障排障手册.md](需求文档/环境故障排障手册.md) 提供故障速查表与 Mermaid 流程。

## 8. 生产环境注意事项

- ⚠️ 本仓库文档中的账号口令（业务演示账号与中间件口令）均为**开发测试弱密码**，**严禁用于生产**。
- 上线前须重评安全 CVE（FastJSON / Shiro / Spring 已知漏洞，当前决策暂不处理）。
- 对外暴露端口需经防火墙（ufw）显式放行；Docker 发布端口由 Docker 直写 iptables。
- 生产部署建议参考 [产品差距与商业化升级路线图.html](产品差距与商业化升级路线图.html) 一期"安全 / 可观测 / 高可用"改造。
