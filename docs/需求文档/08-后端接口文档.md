## 一、阅读须知（必读，避免 401 / 404）

| 项 | 事实 |
|---|---|
| **唯一入口** | `http://<host>:8760/api`（Zuul 1.x，`stripPrefix=true`） |
| **严禁直连** | 禁止直连 `pd-web-*`(8161~8164) / `pd-oms` / `pd-work` 等各服务端口。`pd-web-*` 全部注册 `TokenAuthInterceptor`，缺 `userid` 头即 **401**；网关负责注入 `userid/name/stationid`，业务侧用 `RequestContext.getUserId()`。 |
| **JWT 头字段** | 固定 **`token`**（不是 `Authorization`）；实测有效期 **7200s**；**无 refreshToken**，401 即清 token 重登。 |
| **登录已存在** | `pd-auth-server` 的 `POST /anno/login`（需验证码）+ `GET /anno/captcha?key=`。三端一律复用，**严禁新建登录服务**。 |
| **内部 Feign 服务不可外部直连** | `pd-oms / pd-work / pd-base / pd-dispatch / pd-aggregation / pd-user` 共 **154** 个接口**未注册网关**（`ignored-services:'*'`），只能由 `pd-web-*` 聚合层 Feign 调用，前端/移动端不可经 `:8760/api` 直连，否则 404。 |
| **返回结构不统一** | `pd-web-*` 混用 `Result{code,msg,data}`（成功 `code=0`）/ `R` / `PageResponse<T>` / 裸 `VO` / 裸 `List` / `Object`；`pd-auth-server` 用 `R<T>`（失败 `code=-1/-2`）。**统一以 `code===0` 判成功**，但每个接口的实际返回类型见下文标注，不可想当然。 |
| **轨迹接口免鉴权** | `pd-netty` 无拦截器，`/netty/push`、`/trace/*` **完全无鉴权**，存在信息泄露风险（见 §10）。 |

> ⚠️ **网关前缀（已核实，Nacos 实测）**：`pd-gateway-test.yml` 中 **`/auth/**` 与 `/authority/**` 两条路由并存**，都指向 `pd-auth-server`。即 `POST /api/auth/anno/login` 与 `POST /api/authority/anno/login` **均可用**——联调实测 `GET /api/auth/anno/captcha` 能到达服务（仅因 Redis 故障返 500，非路由问题）。**三端任务卡使用的 `/api/auth/anno/login` 是正确的，无需修改**；本文下文统一用 `/api/authority/...` 表述，两者等价。

## 十、已知缺口与风险（接口层）

1. **（✅ 已闭合）轨迹按订单号查询**：由 pd-web-customer 聚合接口 `GET orderTrace/trace?orderId=` 解决（§7 注）。
2. **（✅ 已具备）快递员附件上传**：快递员端有独立 `POST attachment/upload`（`/api/web-courier/attachment/upload`，D-07，POD 照片独立留证，无需借道 customer/driver）。
3. **内部服务未注册网关**：任何"前端直连 `:8760/api/order/...`"的想法都会 404，必须经 `pd-web-*`。
4. **netty 免鉴权**：`/netty/push`、`/trace/*` 无鉴权，建议加来源限制或鉴权，防轨迹遍历泄露。
5. **返回结构不统一**：`Result`/`R`/`PageResponse`/裸 VO 混用，前端网络层必须按接口归一化。
6. **`/authority` 与 `/auth` 前缀并存**：Nacos 网关两条路由（`/auth/**`、`/authority/**`）均指向 `pd-auth-server`，`/api/auth/anno/login` 与 `/api/authority/anno/login` 等价可用（§1 注）。
7. **司机/快递员加登录口必 401**：两模块 `TokenAuthInterceptor` 对 `/**` 全量注册且无 exclude，登录只能放 `pd-auth-server /anno/*`。
8. **`/address/page` 分页参数 `pageSize` 驼峰**：与其他接口 `pagesize` 不一致，易踩坑。
9. **`@GlobalTransactional` 下单链路**：`pd-web-customer/MailingController.save` 串联多内部服务，任一不可达则下单整体失败（内部服务可用性关键点）。
10. **Seata 1.2 仅依赖未启用（B5）**：各服务 pom 已引入 Seata 依赖（`seata-spring-boot-starter` 等）但**未启用**（无 TC/配置中心 Seata 配置、未建 undo_log 表、容器无 seata-server 正常实例）——即当前 `@GlobalTransactional` **实际是"假分布式事务"**（本地注解不生效，回滚仅靠本地事务）。
   - **影响**：P0 跨服务写场景（下单：order→cargo→agency→user；调度：dispatch→work→base）在部分失败时**无全局回滚**，会出现脏数据；当前靠接口幂等 + 补偿（状态机同步桥 MQ 补偿）兜底。
   - **处置**：① 一期维持现状（幂等+补偿兜底，不启 TC）；② 若出现跨服务写脏数据问题再评估启用 seata-server（镜像与排障见环境侧历史）；③ **不在本期引入新分布式事务方案**（与 §6.12/开发规范第 1 章一致）。

## 十三、合规约束（P0 后端专项 · 依据《合规开发优先级清单》）

> 以下为**上线前闸口级**合规要求，落在后端/网关；前端任务卡（司机/快递员/客户/管理端）已对应引用本节的编号。
> 法规出处见《10-物流行业合规与监管要求.md》R1~R11；排期与验收见《合规开发优先级清单》#1~#7。

### R2-3 轨迹真实性校验（pd-netty）
- `POST /netty/push` 上报须带**设备标识 + 时间戳**；后端做连续性/跳变校验，异常轨迹（瞬时大位移、无设备标识、坐标系非法）告警。
- ✅ **R2-1 P0 最小改造已落地**：`LocationRecord` 已加 `coordSystem`+`source`，`pd_truck.online_status`/`last_heartbeat_time` 心跳字段同步就位；落库前校验坐标系合法（呼应多端契约"轨迹同源"）。

### R6-1 数据分类分级目录（pd-base / pd-user 扩展，不引新中间件）
- 明确 TMS 内**重要/敏感数据**：货运车辆全域定位数据集、规模驾驶员敏感信息集合、客户订单/地址/联系方式（最低一般 3 级，千万级判重要数据）。
- 形成分级目录配置（重要或敏感），作为 R6-4 脱敏、R6-5 加密的前置；审计证据可导出。

### R6-5 接口防越权遍历（网关 + 各 pd-web）
- 订单/轨迹/司机等查询接口**强制鉴权**，按 `userid`/角色限定数据范围，**禁止**越权遍历他人数据（呼应多端契约红线）。
- 高等级数据静态/传输加密；位置/个人信息境内存储。netty 当前免鉴权（§1 风险项），建议后续对 `/trace/*` 加鉴权或白名单来源。

### R2-2 排班 / 派车校验（pd-dispatch）
- 排班/派车接口校验车辆**监控设备在线**，离线/故障车辆**拒单**；前端司机端 D-10、管理端车辆页同步展示在线状态。

### R2-4 视频数据直传不中转（pd-netty / 司机视频接入）
- 司机视频（盲区预警 / 驾驶员状态）须**直传监管平台或本平台**，不得经不可控中间转发（GB/T 28181 / JT/T 1078，或云厂商 RTC 直传）；原始视频流路径须可审计、不落地非授权节点（依据 R2/R11）。

### R3-1 车辆技术等级 / 新能源字段（pd-base 车辆档案）
- 车辆档案扩展 `energyType`（柴油/天然气/电动/氢能）、`techLevel`（二级以上）、`inspectCycle`、`batteryStatus` 字段；提供新能源预警（依据 R3）。

### R4-1 电子运单强制填报（pd-work 运单 / pd-dispatch 调度，条件 P0）
- 每趟次发车前须完成**电子运单真实填报**（驾押人员、装卸货地址），未填报**禁止执行任务**；运单随车 APP 或打印备查。自营 TMS 虽非网络货运平台，但电子运单真实填报、随车备查是通用良好实践（依据 R5 通用部分 + R4 理念）。

### R5-1 车证人证一致校验（pd-dispatch 派车派司机）
- 派单接口校验**车辆营运证在有效期、司机从业资格证 / 驾照有效**；失效**禁止派单**（依据 R5 通用部分）。

### R5-2 数据留存策略（全链路）
- 运单 / 轨迹 / 结算数据留存 **≥3 年**（涉税资料 10 年）；操作日志留存 **≥6 个月**（与 R6-3 合并）。过期归档须可恢复、不可篡改（依据 R5 通用部分）。

### R5-3 轨迹运单真实可核验（pd-netty + pd-work）
- 杜绝"空转走单 / 虚假轨迹"；业务数据（运单、轨迹、结算）真实一致，呼应多端契约"轨迹同源"与税务监管"五流合一"精神（依据 R5 通用部分）。

### R6-4 前端脱敏展示（各 pd-web + 管理端）
- 面单手机号 / 地址、司机姓名 / 证件、轨迹经纬度在**前端脱敏**（如 `138****1234`）；管理端导出须审批（依据 R6/R7/R8）。后端可提供脱敏视图字段或通用脱敏组件，避免各端散写。
