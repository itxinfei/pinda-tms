# 物流行业合规与监管要求（2026 新增）

> 文档定位：基于 2024–2026 年最新物流行业法律法规与管理方法，把"合规要求"转译为**可落地的需求项**，作为《多端数据打通》《各任务卡》的上位约束。
> 适用模型：**自营 / 加盟运输管理 TMS**（非网络货运撮合平台）。凡仅适用于"网络货运平台/对外承运撮合"的条款，已明确标注"不适用边界"，避免误把平台监管当成本项目需求（与"不对接外部厂商"硬约束一致）。
> 资料来源：交通运输部 / 税务总局 / 国家邮政局 / 网信办 / 人社部公开规章与政策解读（2024-01 ~ 2026-09），详见 §1 清单。

## 2. 适用性边界声明（重要，避免误用）

- **本项目 = 自营 / 加盟运输管理**：有自有/加盟车队与司机，业务闭环在内部，不对外撮合货主与承运商，**不对接外部三方物流 API**（硬约束）。
- **完全适用的合规要求**：快递投递确认（R1）、北斗动态监控（R2）、车辆技术管理（R3）、数据安全（R6/R7/R8）、绿色物流（R9）、司机健康/运价透明（R10 中通用部分）。
- **边界适用 / 仅通用部分适用的要求**：
  - R5 网络货运承运平台：其"撮合/税务套利/三流合一监管"针对平台企业，**本项目不适用**；但其**通用良好实践**（电子运单真实填报、轨迹真实可核验、运单数据留存≥3 年、车证人证一致）适用于本 TMS，已并入对应需求。
  - R4 危货规范：仅在项目**实际开展危险货物运输**时强制；电子运单、动态监控、双重预防理念可通用预埋。
  - R10 抽成"阳光行动"：针对平台撮合抽佣，**本项目无抽佣**，但运价透明、运费保障、驾驶健康通用。

## 4. 分域需求细化

### 4.1 快递配送合规（R1，P0）
- **法规要求**：未经用户同意，不得擅自使用智能快件箱、快递服务站等方式投递；违者由邮政管理部门责令改正，最高处 3 万元罚款（《快递市场管理办法》）。
- **需求 R1-1（P0）**：派件前必须确定投递方式。支持"上门 / 智能柜 / 驿站"三种，且**上门为默认、改投需用户二次确认**（客户小程序或短信/微信确认）。
- **需求 R1-2（P1）**：客户地址簿增加"投递偏好"字段（默认方式 + 是否允许柜/驿站），下单时带出，快递员端派件页展示并强制选择/确认。
- **需求 R1-3（P1）**：投递结果回写（柜号/驿站名称/上门时间），客户可在小程序查看，作为纠纷免责证据。
- **落地位置**：快递员端任务卡派件页 + 客户小程序下单/地址簿页。

### 4.2 北斗动态监控合规（R2/R11，P0）
- **法规要求**：总质量 12 吨及以上普通货运车辆、牵引车、危货车辆必须安装符合 JT/T 794/808/809 的卫星定位（北斗）装置，接入监控平台，保持实时在线；装置故障不能保持在线的车辆**不得安排运输经营**；企业落实动态监控主体责任。
- **需求 R2-1（P0）**：复用以规划 BDS 需求——`LocationRecord` 加 `coordSystem`(WGS84/GCJ02/BD09/CGCS2000) + `source`(北斗车载/手机GPS/网络)；统一坐标转换。
- **需求 R2-2（P0）**：新增"车辆监控在线状态"：车辆档案标记监控设备状态；**离线/故障车辆禁止进入调度排班与运输任务**；排班时校验。
- **需求 R2-3（P0）**：轨迹真实性——上报位置需带时间戳与设备标识，后端做连续性/跳变校验，异常轨迹告警（呼应多端契约"轨迹同源"）；禁前端/接口伪造坐标。
- **需求 R2-4（P1，R11）**：司机视频接入须**数据直传监管/平台，不得经中间转发**（GB/T 28181/JT/T 1078 或云厂商 RTC），盲区预警/驾驶员状态监测结果可落库用于 OPS-5 驾驶行为。
- **落地位置**：pd-netty `LocationRecord` 改造 + 调度排班校验 + 司机视频接入（IOT②）。

### 4.3 车辆技术管理（R3，P1）
- **需求 R3-1（P1）**：车辆档案增加"能源类型（柴油/天然气/电动/氢能）""技术等级（二级以上）""检车周期（5 年以上半年检）""新能源电池检测状态"字段。
- **需求 R3-2（P1）**：在既有证照/年检/保险预警（§10.5）基础上，扩展新能源专属预警（电池安全双保险）。
- **落地位置**：pd-base 车辆档案 + OPS-3 车辆司机看板。

### 4.4 危险货物（R4，条件适用）
- **边界**：仅当开展危货业务时启用。
- **需求 R4-1（P1，危货条件升 P0）**：电子运单每趟次真实填报（含驾押人员、装卸货地址），发车前完成，随车 APP 或打印备查；未填报不得执行任务。
- **需求 R4-2（P2）**：双重预防机制（风险分级管控 + 隐患排查）看板；驾驶员心理疏导/职业健康记录。
- **落地位置**：运单管理 + 调度，条件启用。

### 4.5 网络货运通用良好实践（R5 通用部分，P1）
- **需求 R5-1（P1）**：派车/派司机时校验**车证一致、人证一致**——车辆营运证在有效期、司机从业资格证/驾照有效，否则禁止派单。
- **需求 R5-2（P1）**：运单、轨迹、结算数据**留存策略 ≥3 年**（涉税资料 10 年）；操作日志留存 ≥6 个月（与数据安全合并）。
- **需求 R5-3（P1）**：轨迹与运单**真实可核验**，杜绝"空转走单/虚假轨迹"（呼应税务监管"五流合一"精神，即便自营也须保证业务数据真实）。

### 4.6 数据安全与个人信息保护（R6/R7/R8，P0）
- **法规要求**：《网络数据安全管理条例》(2025-01-01) 必要性原则 + 单独同意 + 大规模个人信息合规审计；《交通运输数据安全管理办法》数据分类分级（核心/重要/一般三级，敏感个人信息最低一般 3 级，100 万条以上个人信息最低一般 3 级，千万级判重要数据），全生命周期管控，日志留存 ≥6 个月，脱敏去标识，境内存储；GB/T 45574-2025 敏感个人信息处理安全要求。
- **需求 R6-1（P0）数据分类分级**：明确 TMS 内**重要/敏感数据**——货运车辆全域定位数据集、大规模驾驶员敏感信息集合、客户订单/地址/联系方式。建立分级目录。
- **需求 R6-2（P0）最小必要 + 单独同意**：移动端采集位置/行程/车牌等敏感信息须**单独授权**（隐私政策 + 运行时动态授权），不超范围采集人脸等。
- **需求 R6-3（P0）权限最小化 + 审计**：内部查询按最小权限；所有涉及个人信息/轨迹的查询、导出操作**留痕，日志留存 ≥6 个月**。
- **需求 R6-4（P1）脱敏展示**：面单手机号/地址、司机姓名/证件、轨迹经纬度在前端**脱敏**（如 `138****1234`）；管理端导出需审批。
- **需求 R6-5（P0 上线前闸口）境内存储 + 加密 + 防越权**：位置/个人信息境内存储；高等级数据静态/传输加密；订单/轨迹查询接口**强制鉴权防遍历越权**（呼应《后端接口文档》§10 安全项与多端契约）。
- **落地位置**：数据治理（新增）/ 移动端授权 / 接口安全 / 管理端脱敏。

### 4.7 绿色物流（R9，P2）
- **需求 R9-1（P2）**：车辆档案"能源类型"字段（与 R3 合并）；统计电动/氢能占比，呼应"十五五"零碳运输走廊与新能源重卡渗透率目标。
- **需求 R9-2（P2）**：在 OPS-4 趟次成本/油耗基础上，扩展**能耗与碳排放统计**（按线路/车辆），支撑绿色物流指标核算。
- **落地位置**：pd-base + OPS-4。

### 4.8 司机权益（R10 通用部分，P1/P2）
- **需求 R10-1（P1）运价透明 + 运费保障**：运费计算规则透明可查（呼应 §10.4 价格固化防暗箱）；结算保障/垫付机制（呼应 COD/结算）。
- **需求 R10-2（P1）健康与安全**：驾驶行为监控（OPS-5）+ 疲劳驾驶管控（§10.5）+ 排班防超时。
  > 说明：R10-2 **不另立独立合规约束子节、不占 19 项待补编号**——该能力已由既有规划覆盖（OPS-5 司机绩效/驾驶行为 + 需求分析 §10.5），属"已覆盖"而非"待补"，避免被误读为遗漏项。
- **需求 R10-3（P2）参保/健康记录**：司机档案增加"参保状态/互助保障"字段，便于关怀与合规备查。
- **落地位置**：结算/价格 + OPS-5 + 司机档案。

## 7. 落地建议

- **P0 合规项应进入第一批开发**（尤其 R1 投递确认、R6 数据安全），否则上线即面临邮政/网信处罚风险。
- **R2/R4/R5 通用项**与既有 BDS、视频、运单、调度任务卡天然融合，建议在对应任务卡内加"合规约束"子节，避免另起炉灶。
- **R6 数据安全**建议独立成"数据治理"微服务/模块（本项目不引新中间件，可用现有 pd-base/pd-user + 网关鉴权扩展），重点：分类分级目录、脱敏组件、审计日志表。
- **边界条款（R5 撮合/税务、R4 危货）**：明确写进"不做清单"，仅在业务拓展时再启用，避免误实现。
- 审计证据：所有合规动作（投递确认、电子运单、轨迹、授权、审计日志）须**可导出留痕**，应对监管检查。
