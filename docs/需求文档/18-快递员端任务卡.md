## 0. 总纲与红线（不可逾越）

本任务卡只做**快递员端前端（App / 小程序均可，以 App 为主做重操作）+ 复用既有取派/签收接口**。
> ❗登录接口**已存在**（`pd-auth-server` `POST /anno/login` + `GET /anno/captcha`），**严禁新建登录服务**。
> ❗**禁止把登录口加在 `pd-web-courier` 上**：该模块 `ConfigurationSupport` 对 `/**` 全量注册 `TokenAuthInterceptor` 且**无 exclude 配置**，登录请求无 `userid` 头 → **必然 401**。移动端免密入口须加在 `pd-auth-server`（`/anno/*` 已在网关放行）。
- 升级/改动任何后端依赖、JDK、技术栈（红线 §1.x）；
- 引入任何新中间件、新 UI 库、第二套组件体系（红线 §12.x / UI §7）；
- 新建平行后端服务或重写既有 `pd-web-courier` 接口（§5 已盘点，必须复用）；
- 页面随意写 `<div>`+`<style>`、硬编码色值、自创间距（UI §7 禁止清单）。

**快递员端核心价值 = POD 电子签收**（扫码 + 手写签名 + 拍照 + GPS 水印），按 spec POD 要求纳入第一期。所有页面套用 `13-UI设计规范与页面模板.md`，快递员端强调「扫码为主操作 + 大按钮」（角色化 UI §5）。

### C-5 · 电子签收 POD `pages/courier/pod/sign.vue`（**核心**）
- **模板**：**POD 签收页（UI §4.6，自定义大按钮布局）**
- **路由**：`pages/courier/pod/sign?tranOrderId=&orderNumber=`
- **调用**：
  - `POST /api/web-courier/attachment/upload`（拍照 + 签名图，`businessType=courier`，出参附件 id/url）
  - `PUT /courier/delivered/{tranOrderId}/{status}`（`"1"`签收 / `"0"`拒收；该端点**不接收 location**，GPS 只用于端上水印）
- **交互**：
  1. `uni.scanCode` 或手动选任务进入；
  2. **拍照**：`uni.chooseMedia` 拍签收照片；
  3. **手写签名**：`<canvas>` 手写 → `pod.signToImage()`；
  4. **GPS 水印**：`uni.getLocation` 取点 → `pod.addGpsWatermark()` 在签名/照片叠加坐标+时间；
  5. 上传附件 → 调 `delivered` 置为已签收 → 返回列表并刷新。
- **DoD**：签收照片 + 手写签名均上传成功并关联；签名字片含可读 GPS 水印；状态流转为已签收；断网入离线队列、恢复补传。
- **红线**：水印在端上完成；照片/签名经 `attachment/upload`，禁止 base64 直塞业务请求体；经纬度来自定位服务禁手填；不引第三方签名/水印库。
- **合规约束（R6-4 · P1 · 依据《合规开发优先级清单》#15 /《物流行业合规与监管要求》R6）**：POD 页展示收件人姓名/电话等须**脱敏**（如 `138****1234`），完整信息仅授权角色/导出审批后可见；轨迹经纬度展示同样脱敏处理。
- **合规约束（R1-1 · P0 上线前闸口 · 依据《物流行业合规与监管要求》R1 /《合规开发优先级清单》#1）**：
  - **投递方式确认**：进入 C-5 派件签收前，**必须先确定投递方式**（上门 / 智能柜 / 驿站），且**「上门」为默认**；若现场或客户偏好需改为柜/驿站，**须经客户二次确认**（客户小程序确认弹窗 / 短信 / 微信回调），确认记录随 POD 一并留痕。
  - **改投留证**：改投结果（柜号 / 驿站名称 / 上门时间）回写，作为邮政纠纷免责证据（R1-3 回写在阶段 1 补，但"二次确认"动作本身为 P0 闸口）。
  - **不接受**"未确认即投柜/驿站"的交互；该动作缺失即视为合规不达标，**禁止上线**（见《联调就绪检查清单》合规 checklist）。
- **合规约束（R1-3 · P1 · 依据《合规开发优先级清单》#8 /《物流行业合规与监管要求》R1）**：派件**结果须回写**——妥投后记录投递方式、柜号 / 驿站名称 / 上门时间，随 POD 一并落库，客户可在小程序查看。该回写记录是邮政纠纷的**免责证据**，须与 R1-1 二次确认记录一并可导出留痕。
- **拒收/逆向流业务口径（P1-11 逆向流规格业务口径 · 2026-10-08 用户业务拍板：拒收退款策略）**：
  - 本端 `delivered status="0"` 拒收登记 → 订单转 23010 拒收终态后，**系统自动按原支付渠道退款**给寄件/付款客户，快递员端无需发起退款；拒收同时触发退回件回收流程（P1-11 细化：退回揽收责任与退回运费承担）。
  - **边界说明**：本端 `delivered` 仅支持"1签收/0拒收"二态；**部分签收（部分包裹拒收）与破损不自动全额退**——破损/货损需先登记异常（P1-11 破损上报入口）后**按比例折算或转人工核定退款**，不得由快递员端直接置"拒收"即触发全额退款。

- **调用**：`POST /courier/verifyIdCard`（form 参数 `orderNumber`、`code`；旧 GET 版本已 `@Deprecated` 改名 `verifyIdCardByGet`，新前端勿用）。端点含归属校验（须为本人负责的非取消任务），身份证号仅首次可写
- **交互**：输入/扫订单号 + 核验码 → 调接口 → 展示核验结果（通过/不通过）。
- **DoD**：核验结果正确展示；异常给错误态。
- **红线**：身份证号由后端在核验时写入会员档案 `pd_member.id_card_no`（**仅首次可写、拒绝覆盖**），前端**不得额外本地缓存或打印日志**；页面仅回显核验通过/不通过状态。

### C-9 · 路由/轨迹 `pages/courier/task/route.vue`
- **模板**：**地图页（UI §4.4）**
- **路由**：`pages/courier/task/route?id=`
- **调用**：`GET /courier/route?id=`（路由节点，返回 `RouteDTO{agencyName, arrivalTime}` —— ⚠️ 与客户端 `RouteDTO{msg,time,status,quantity}` **字段完全不同**，不可复用时间轴组件）；
  轨迹 `GET /trace/latest?businessId={courierId}&type=courier`（每 10s 轮询，❗**无 `orderId` 参数**）
- **交互**：`<map>` 标点（经 `coord.wgs84ToGcj02` 转换后端 WGS84 坐标）；展示路由节点与当前位置。
- **DoD**：地图偏移 < 50m；轮询 10s；无网络降级缓存点。
- **红线**：只轮询 latest，禁止改 WebSocket；坐标先转换。

### C-10 · 个人中心 `pages/courier/profile/index.vue`（tabBar）
- **模板**：门户类
- **路由**：`pages/courier/profile/index`
- **调用**：`GET /user/profile`
- **交互**：展示快递员资料；入口：我的任务、退出登录。
- **DoD**：资料来自接口；退出清 token 跳 login。

### C-11 · 异常上报 `pages/courier/exception/report.vue`（**P0 · 2026-10-09 补入**）
- **模板**：表单页（异常类型单选 + 拍照 + 备注，参照 C-5 POD 的拍照交互）
- **路由**：`pages/courier/exception/report?tranOrderId=&orderNumber=&transportTaskId=`（从任务详情 C-4 或 POD 页 C-5 带入上下文，也支持首页独立进入）
- **调用**：
  - `POST /api/web-courier/attachment/upload`（现场照片，出参附件 id 列表）
  - `POST /courier/exception/report`（body `ExceptionReportFeignDTO`）
- **字段映射（D-46「类型 + 照片 + 备注」三要素，缺一不可）**：
  - `exceptionType`：仅三选一 **`GOODS_DAMAGED` 货物破损 / `REJECTED` 客户拒收 / `ADDRESS_ERROR` 地址错误**（对应 `ExceptionType.isCourierScoped`，禁上报车辆故障等司机侧类型）
  - `attachmentIds`：**必填、至少 1 张**，照片先传 attachment 再以返回 id 填入
  - `remark`：**必填、非空**
  - `transportTaskId`：可选，由路由带入；`longitude/latitude`：可选，端上定位取点用于水印与落库
  - ⚠️ `reporterId` 服务端从 token 取、`courier` 由服务端固定，**前端不要传这两个字段**
- **交互**：选异常类型 → 拍照/相册（可多张）→ 填备注 → 提交；提交成功返回上一页并刷新；断网照片与表单入离线队列、恢复补传。
- **DoD**：三类异常均可上报；未传照片或备注为空时前端拦截并提示；落库返回告警记录 id；上报后管理端告警中心可见该人工记录。
- **红线**：异常类型用 `ExceptionType` 枚举映射、禁硬编码字符串/数字；照片走 attachment/upload，禁止 base64 直塞；经纬度来自定位禁手填；与 C-5 拒收（`delivered status=0`）区分——妥投拒收走 C-5 触发终态，**过程中的破损/地址异常走本页登记、不直接改订单状态**。

## 5. 后端新增任务卡（P0-0，唯一允许的后端改动）

### P0-0 · 快递员端登录（❗ 2026-10-05 修正：**鉴权体系已存在，不是从零新建**）

> **修正说明**：实测 `pd-auth-server` 已有 `POST /anno/login` + `GET /anno/captcha?key={uuid}` + JWT 体系。
> P0-0 真实范围 = 「对接既有登录」+（如确需）「免验证码移动端入口」。

- **首选方案（零新建，推荐）**：调 `POST /anno/login`（`{account, password, key, code}`），验证码取 `GET /anno/captcha?key={uuid}`。快递员账号由管理端在权限系统预置。
- **备选方案**：在 `pd-auth-server` 的 `LoginController` **同目录内**新增 `POST /anno/loginMobile`（`{account, password}` 或 `{phone, smsCode}`），**复用 `AuthManager.login()`**，只跳过验证码。
- **位置**：`pd-web/pd-web-courier`（**不新建模块**）或 `pd-auth-server`。
- **实现约束（严格遵守红线）**：
  1. 短信/微信能力用现有 `EntCoordSyncJob.loadJSON` 同款 `HttpURLConnection` + 超时，不引新依赖。
  2. **JWT 复用 `AuthManager` / `JwtTokenServerUtils`**，禁止自造签名。
  3. 请求头固定 `token: <token>`；网关注入 `userid`，业务侧 `RequestContext.getUserId()`。
- **DoD**：端能登录拿 token；`GET /user/profile` 带 `token` 头返回正确资料；`mvn -o -q compile`（JDK 21 LTS）通过。
- **红线**：不得引入 Spring Security/OAuth 新依赖；不改 JDK/依赖版本；不引新 ORM；**不得实现 refreshToken**，401 即重登。
- **POD 后端**：`courier/delivered` 与 `attachment/upload` 已存在，POD 落库（签收图/签名）若需新增字段，按 spec POD 走最小化后端扩展（不引新依赖），不在本卡 P0-0 范围。
