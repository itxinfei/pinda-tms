## 0. 总纲与红线（不可逾越）

本任务卡只允许做**客户小程序（C 端）前端**（登录接口**已存在** `POST /anno/login`，**严禁新建登录服务**，仅做移动端适配），不得：
- 升级/改动任何后端依赖、JDK、技术栈（红线 §1.x）；
- 引入任何新中间件、新 UI 库、第二套组件体系（红线 §12.x / UI §7）；
- 新建平行后端服务或重写既有 `pd-web-customer` 接口（§5 已盘点，必须复用）；
- 页面随意写 `<div>`+`<style>`、硬编码色值、自创间距（UI §7 禁止清单）。

**所有页面必须套用 `13-UI设计规范与页面模板.md` 的对应模板**，设计 Token 全部来自 `uni.scss` + `common/styles/variables.scss`，禁止页面内写死颜色/尺寸。

## 3. 公共能力任务卡（P0 级，先于页面）

### P0-1 · 网络层 `common/request/index.ts`
- 封装 `uni.request`，**baseURL 固定为 `http://192.168.20.130:8760/api/web-customer`**（开发与生产**统一走网关**；禁止直连 8164，`TokenAuthInterceptor` 缺 `userid` 头即 401，8164 仅供健康检查）。
- 请求拦截：自动附加 **`token: <token>`**（取自 Pinia / `uni.getStorageSync('token')`）。❗**禁止用 `Authorization: Bearer`** —— 网关 `authentication.user.header-name: token`，用错则全部请求 401。
- 响应拦截：`code===0 || code===200` 视为成功，返回 `res.data`；否则 `uni.showToast` 报错；`code===401` 跳转 login。
- 若阶段 0 实测 `Result` 与 `R` 字段不同，在此层归一化为 `{code, data, msg}`。
- **红线**：禁止在页面里裸调 `uni.request`，一律走此封装。

### P0-2 · 用户态 `stores/user.ts`（Pinia）
- state：`token`、`memberId`、`profile`、`openid`。
- actions：`login(code)`（调 P0-0 接口）、`fetchProfile()`（GET /user/profile）、`logout()`。
- 持久化：`uni.setStorageSync` 存 token；App 启动 `onLaunch` 检查本地时间戳，过期即清 token 跳 login（**后端无 refreshToken，无"静默刷新"能力**）。

### P0-3 · 坐标转换 `common/utils/coord.ts`
- 实现 `wgs84ToGcj02(lng, lat)`（标准公式，约 30 行），所有要在 `<map>` 上标点/画线时先转换（后端统一存 WGS84，见 BA-19 2026-10-09 修订）。
- 原因：后端统一存储 **WGS84（GPS/北斗原始）**（2026-10-09 修订，原"存百度 BD-09"口径废止，见 BA-19）；微信小程序 `<map>` 组件固定腾讯 GCJ-02，须做 WGS84→GCJ-02 转换，不转换会偏移数百米。

### P0-4 · API service 层 `common/api/*.ts`
- `mailing.ts`、`address.ts`、`agency.ts`、`goodsType.ts`、`common.ts`、`user.ts`、`trace.ts`，每个方法对应 §7 契约表的一个端点，入参/出参类型据 DTO 标注。
- 禁止在页面里拼 URL，页面只调用 service 方法。

### P0-5 · 全局 UI 壳（引用 UI §3）
- 统一 `u-navbar`（标题 + 返回）、`u-tabbar`（仅 3 个 tab）、三态组件 `AppStateLoading/Empty/Error`（加载中骨架 / 空态插画 / 错误重试）。
- 所有页面顶部必须有 `u-navbar`，禁止绕过。

## 4. 页面任务卡（按优先级排序，逐张执行）

> 每张卡字段：ID / 模板 / 路由 / 调用接口 / 字段映射 / 交互 / 验收 DoD / 红线提醒

### P1-1 · 登录页 `pages/customer/login/index.vue`
- **模板**：自定义（表单/按钮类，套 UI Token，单按钮大操作）
- **路由**：`pages/customer/login/index`
- **调用**：P0-0 新增 `POST /member/wxlogin`（入参 `{code}` → 出参 `{token, memberId, openid}`）
- **交互**：进入即 `wx.login()` 取 code → 调登录 → 存 token → 跳 home。已登录则直接进 home。
- **DoD**：冷启动无 token 自动登录并拿到 token；断网给出错误态重试；不出现明文密码输入框。
- **红线**：禁止自建账号密码体系；token 仅存 `uni.setStorageSync` + Pinia，不落日志。
- **合规约束（R6-2 · P0 上线前闸口 · 依据《合规开发优先级清单》#5 /《物流行业合规与监管要求》R6/R7/R8）**：采集位置/行程/运单等敏感个人信息前，**须有隐私政策告知 + 运行时单独同意**（最小必要，不超范围采集人脸等生物特征）。首次进入应触发隐私授权弹窗，拒绝则仅提供必要功能；授权状态本地留存可查。授权范围与《数据分类分级目录》（R6-1，见《后端接口文档》§13）保持一致。

### P1-2 · 首页 `pages/customer/home/index.vue`
- **模板**：首页/门户类（大入口卡片 + 状态色）
- **路由**：`pages/customer/home/index`（tabBar）
- **调用**：无（纯导航）；可展示 `GET /mailing/count` 的"进行中/已完成"数。
- **交互**：三大入口——「我要寄件」→ mailing/create；「查快递」→ mailing/list；「我的」→ profile。
- **DoD**：三个入口可达；进行中订单数正确展示；无硬编码色值。
- **红线**：禁止堆砌无关功能；保持极简三步可达核心。

### P1-3 · 寄件表单 `pages/customer/mailing/create.vue`
- **模板**：**表单页**（UI §4.3）
- **路由**：`pages/customer/mailing/create`
- **调用**：
  - `GET /goodsType/all` —— 物品类型下拉
  - `GET /agency/page` —— 网点**仅供展示/自提参考**，⚠️ **下单网点不可由前端指定**：`MailingSaveDTO` 无 agency 字段，后端在 `save()` 里用发件地址调百度地图**自动计算** `currentAgencyId`。**不要做「选网点回传 id」的页面**。
  - `GET /address/page?page=&pageSize=&keyword=` —— 地址簿选择（跳 address/list，选中回传）。⚠️ 该接口**无 `type` 参数**；且分页参数名是 **`pageSize`（驼峰）**，其余接口是 `pagesize`（全小写），不可混用
  - `POST /mailing/totalPrice`（入参 `MailingSaveDTO`）—— 实时运费试算
  - `POST /mailing`（入参 `MailingSaveDTO`）—— 提交下单
- **字段映射（MailingSaveDTO）**：
  `sendAddress`(发件地址簿id) / `receiptAddress`(收件地址簿id) / `pickUpTime`(取件时间) / `pickupType`(取件方式 **1网点自寄 / 2上门取件**，见 `OrderPickupType.java`) / `payMethod`(1预结2到付) / `goodsType`(物品类型id) / `goodsName` / `goodsWeight`
- **交互**：选地址簿 → 选网点 → 填物品 → 实时显示试算运费（防抖 300ms 调 totalPrice）→ 提交。提交成功跳 mailing/detail。
- **DoD**：运费随输入实时刷新无误；提交后生成订单并跳详情；表单校验用 uview-plus `u-form` + 规则；地址/网点从列表选，不手填经纬度。
- **红线**：试算与提交共用同一 DTO；禁止把坐标写死或手填经纬度（由地址簿/网点提供）。
- **P2 扩展（参照联云 TMS · 2026-10-06 并入）**：**历史地址智能记忆**——下单页地址输入时按最近使用频率智能排序/联想（复用现有地址簿接口 `GET /address/page?keyword=` 的 keyword 模糊查询，前端本地记忆最近 5 条 + 高频地址置顶，不新开接口）；已选地址自动带入上次收/发件人信息。
- **合规约束（R1-1 · P0 上线前闸口 · 依据《物流行业合规与监管要求》R1）**：寄件表单须支持**收件投递方式偏好**带出（默认"上门"，可选智能柜/驿站）；若收件人地址簿有"投递偏好"字段则自动带出（地址簿编辑页 P1-8 负责采集，见 R1-2）。**禁止**后端/前端默认"投柜/驿站"而不经用户选择——派件端据此执行并二次确认（详见快递员端 C-5）。
- **合规约束（R6-4 · P1 · 依据《合规开发优先级清单》#15 /《物流行业合规与监管要求》R6）**：地址簿/我的运单/轨迹页展示的收件人姓名、电话、详细地址须**脱敏**（如 `138****1234`、地址隐去门牌），完整信息仅本人查看；下单回显时同样脱敏，避免敏感信息明文泄露。

### P1-5 · 运单详情 `pages/customer/mailing/detail.vue`
- **模板**：**详情页**（UI §4.2，含时间轴）
- **路由**：`pages/customer/mailing/detail?id=xxx`
- **调用**：
  - `GET /mailing/detail?id=` → `CustomerOrderDetailDTO{id,status,tranOrderId,planPickUpTime,actualDispathedTime,cancelTime,name,mobile,avatar}`
  - `GET /mailing/route?id=` → `RouteDTO[]{msg,time,status,quantity}`（时间轴节点）
- **交互**：展示订单号/状态/运单号/取派时间/收件人；时间轴展示 route 节点；底部「查看实时轨迹」→ track 页；「取消」(status 允许时)→ `PUT /mailing/cancel/{id}`；「去支付」→ `PUT /mailing/pay/{id}`。
- **取消与退款业务规则（2026-10-08 用户业务拍板：客户取消规则 + 拒收自动退款）**：
  - **取消可见性**：仅"发货前（订单状态=23000 待取件/未取件）"可取消——「取消」按钮此时可见可用，取消后**全额退款（按原支付渠道退回）**；一旦已取件（23001 及以后，含运输中/派送中/已完成）**取消按钮隐藏或置灰不可用**，客户需走客服/逆向申诉而非自助取消。
  - **拒收自动退款（P1-11 逆向流规格业务口径）**：末端派送被收件人拒收（订单→23010 拒收终态）后，系统**自动按原支付渠道退款**，无需客户单独申请；部分签收/破损的退款**不自动全额退**，按已送达比例折算或转人工核定后处理（边界规则在 P1-11 逆向流规格细化）。
- **DoD**：详情与轨迹节点均来自接口；状态用状态色；取消/支付按钮按当前状态显隐；时间轴按 `time` 升序。
- **红线**：status 为枚举（见后端 `OrderStatus`），页面用映射表转文案+色，禁止魔法数字。

- **DoD**：地图正确显示当前位置（偏移 < 50m）；轮询间隔 10s 且不泄漏请求；无网络降级为最近一次缓存点。

### P1-7 · 地址簿列表 `pages/customer/address/list.vue`

### 9.1 需求背景与目标用户

#### 9.1.1 触发源与量化痛点

客户端小程序现状（2026-10-05 源码实测）：后端 `pd-web-customer` 已有 7 个 Controller 共 42 个接口，但前端代码 = 0；客户寄件/查件/支付/轨迹全靠电话客服人工处理。由此产生 4 项可量化痛点：

| 痛点 | 当前表现 | 业务影响 | 量化口径 |
|---|---|---|---|
| 客户无法自助下单 | 寄件必须电话联系客服，客服手填工单录入 pd_oms | 客服人力成本高，下班后无服务能力 | 日均客服电话中"我要寄件"类占比 ≥50%，夜间 22:00-8:00 完全无服务 |
| 客户无法自助查件 | 凭 `Order.id` 查轨迹无解（§1 实测项 12）；查件电话问询为主 | 客户体验差，客服重复劳动 | 月度客户咨询中"车到哪了/包裹到哪了"类占比 ≥40% |
| 状态滞后看不到运输中（已于 2026-10-07 落地：真实提货链路 `CargoController.pickUp` 已回写 `Order.status=23005`，见 `CargoController.java:519`；此前误把 pd-work 的死方法 depart() 当真实发车链路） | 旧表现：司机发车后客户看不到运输中 | 客户现可正常看到运输中状态 | 状态滞后率应降为 ≤1%；唯一残留缺口是"凭订单号查轨迹点"端点（见 §9.4.1） |
| 微信免密登录缺失 | `POST /anno/login` 是账号+验证码，小程序无 `code2Session` 免密口 | 微信生态用户每次都要输账号密码，转化低 | 微信小程序标准登录能力缺失率 = 100% |

行业对标（顺丰"丰巢"小程序、京东物流小程序、菜鸟裹裹）：客户凭微信一键登录 + 运单号全程可视化 + 在线下单支付，是 C 端物流的基础体验。

#### 9.1.2 目标用户与角色权限矩阵

客户端小程序面向 2 类角色（客户 + 客服），各自操作范围与数据可见性不同：

| 角色 | 主要场景 | 可见数据范围 | 可执行操作 | 不可执行 |
|---|---|---|---|---|
| 个人客户（寄件人/收件人） | 微信小程序下单/查件/支付/查轨迹 | 本人 `Order.memberId = JWT userid` 的订单与轨迹 | 下单/取消/支付/查件/查轨迹/管理地址簿/退出 | 看到他人订单；指定下单网点（后端自动算） |
| 客服（内部） | 协助客户排查订单异常 | 全部订单（走管理端权限，非小程序入口） | 管理端查订单/轨迹/状态联动日志（走 pd-web-manager） | 不在小程序内操作 |

> **数据隔离实现**：客户查订单/轨迹只凭 `Order.id`，后端按 `Order.memberId = JWT.userid` 鉴权（网关 `TokenContextFilter` 注入 `userid`）；非本人订单返回 403。下单网点由后端调百度地图按发件地址自动算 `currentAgencyId`，前端无该字段（D-02 红线扩展）。

| # | 场景 | 角色 | 触发条件 | 系统响应 |
|---|---|---|---|---|

- **登录层（P0-0）**：`pd-web-customer`（或 `pd-user` 的 `MemberController` 增方法）新增 `POST /member/wxlogin`，入参 `{code}`；用 `HttpURLConnection`（或 `RestTemplate`，不引新依赖）调微信 `code2Session` 拿 `openid` → 查/建 `Member`（复用 `IMemberService`）→ JWT 必须复用 `AuthManager`/`JwtTokenServerUtils`（D-15），禁止自造签名。**不得实现 refreshToken**（后端无该字段），401 即重登。
- **网络层（P0-1 §3）**：`common/request/index.ts` 封装 `uni.request`，baseURL 固定 `http://192.168.20.130:8760/api/web-customer`；请求拦截自动附加 `token: <token>`（D-16，非 `Authorization: Bearer`）；响应拦截 `code===0 || code===200` 视为成功，`code===401` 清 token 跳 login；归一 `Result{code,msg,data}` 与 `R` 两套响应为 `{code,data,msg}`。**禁止页面裸调 `uni.request`**。
- **用户态（P0-2 §3）**：Pinia `stores/user.ts` state 含 `token`/`memberId`/`profile`/`openid`；`uni.setStorageSync` 持久化 token；App `onLaunch` 检查本地时间戳，过期即清 token 跳 login（后端无 refreshToken，无静默刷新）。
- **坐标转换（P0-3 §3）**：`common/utils/coord.ts` 实现 `wgs84ToGcj02(lng, lat)` 标准公式约 30 行；后端统一存储 **WGS84**（2026-10-09 修订，原"存百度 BD-09"口径废止），微信小程序 `<map>` 固定腾讯 GCJ-02，不转换偏移数百米（D-12）。
- **API service 层（P0-4 §3）**：`common/api/*.ts` 每个方法对应 §6 契约表一个端点，入参/出参类型据 DTO 标注；禁止页面拼 URL。
- **UI 壳（P0-5 §3）**：统一 `u-navbar`（标题+返回）+ `u-tabbar`（仅 3 个 tab：home/mailing-list/profile）+ 三态组件 `AppStateLoading/Empty/Error`；所有页面顶部必须有 `u-navbar`，禁止绕过。
- **页面模板（§4）**：10 页全部套 `13-UI设计规范与页面模板.md` 对应模板（表单页/列表页/详情页/地图页/门户类）；设计 Token 全部来自 `uni.scss` + `common/styles/variables.scss`，禁止页面内写死颜色/尺寸；品牌色 `#2B6CFF`（D-10）。
- **轨迹页依赖（P1-6 §4）**：`/trace/order/{orderId}` 端点**当前不存在**（`GpsTraceController` 仅支持 businessId 查询，全库无 OrderTraceController）；后端新增该端点并加 memberId 归属校验前，此页继续隐藏入口，禁止前端伪造 orderId 参数。注：订单 23005「运输中」状态已由 `CargoController.pickUp` 回写（`CargoController.java:519`），状态档位不缺，仅缺轨迹点查询端点。
- **下单网点不可由前端指定**：`MailingSaveDTO` 无 agency 字段，后端 `save()` 用发件地址调百度地图自动算 `currentAgencyId`；不要做"选网点回传 id"的页面。
- **分页参数差异**：`/address/page` 用 `pageSize`（驼峰），其余接口用 `pagesize`（全小写），不可混用。
- **隐私授权弹窗（R6-2）**：首次进入触发隐私授权弹窗，拒绝则仅提供必要功能；授权状态本地留存可查；不超范围采集人脸等生物特征。
