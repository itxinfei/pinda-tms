## 2. 联调前置条件（★ 必须清除，否则全链路 401/500）

### ★ 前置①：网关 j2cache 配置修正（阻断 B）—— ✅ 已于 2026-10-06 16:15 解除

> ⚠️ **原判断"重启即可"不准确，真正根因是 j2cache 配置文件路径写错**（已修正，无需重启）。

- **根因（实测确认）**：网关 `j2cache.config-location` 指向 **`classpath:/j2cache-absent.properties`**，该文件在仓库中**不存在**。
  - `pd-gateway` 依赖 `pd-tools-j2cache`（pom.xml:50），该模块只有 `pd-tools/pd-tools-j2cache/src/main/resources/j2cache.properties` 一个配置文件；
  - auth-server 用的正是 `classpath:j2cache.properties`（正常工作，可作对照）。
  - **故障链**：j2cache 找不到配置文件 → 缓存通道初始化异常 → `cacheChannel.get(...)` 抛错 → `AccessFilter` 返回 **500 `pre:AccessFilter`**。
- **修法**：将 Nacos `pd-gateway-test.yml` 的 `config-location` 改为 `classpath:j2cache.properties` 并推送。**Nacos 推送即触发刷新，无需重启**（实测 `/api/authority/menu/router` 立刻 500 → 200）。
- **改动前备份**：`.workbuddy/nacos-backup/20261006-161223-before-cleanup/pd-gateway-test.yml.before-j2cache-fix`

#### ⚠️ 重要提醒：「接口 200」≠「鉴权生效」，阻断 C 仍需处理

读 `AccessFilter.java:78-86`，关卡1（需鉴权资源清单）被 `if (resourceNeed2Auth != null)` 包裹：

```java
List<String> resourceNeed2Auth = (List<String>) resourceNeed2AuthObject.getValue();
if (resourceNeed2Auth == null) {
    resourceNeed2Auth = resourceApi.list().getData();   // Feign 拉取
    if (resourceNeed2Auth != null) { cacheChannel.set(...); }
}
if (resourceNeed2Auth != null) {                        // ← 为 null 则整段跳过
    long count = resourceNeed2Auth.stream().filter(r -> permission.startsWith(r)).count();
    if (count == 0) { errorResponse(UNAUTHORIZED...); return null; }   // 判"未知请求"
}
```

- 当 Feign 拉取清单返回 null 时，**关卡1 整段被跳过 → 所有请求直接放行到下游**。
- **实测证据（注册前的诊断快照）**：已注册的 `/authority/menu/router`、未注册的 `/authority/nonexistent`、未注册的 `/web-driver/user/profile` 三者返回**完全一致**（均 `{"code":40005,"msg":"解析token失败"}`），说明均未被关卡1 拦截 → 当时网关处于"鉴权未真正生效"状态。
- **✅ 已闭环（2026-10-06 复核）**：前置②资源注册落地（48→90 条 + 三端角色）后，用真实登录 token 复测，driver 端 `GET /user/profile` 经网关 **5/5 返回 200**——关卡1 已按资源清单放行已注册接口。**判断鉴权是否真工作**：对比**已注册接口**（200）与**未注册接口**（"未知请求"拒绝）的返回差异，二者一致才说明鉴权未生效。

- **日常验证动作**：
  1. `curl -s -o /dev/null -w "%{http_code}" "http://192.168.20.130:8760/api/authority/menu/router"` → 应 **200**（不再 500）。
  2. 浏览器重新登录管理端，Network 面板确认 `/api/authority/menu/router`、`/api/authority/loginLog/...` 不再 500。
  3. ⚠️ 若又现 500：先查 `j2cache.config-location` 是否被改回 `j2cache-absent.properties`，再查 Nacos 配置是否真正下发。

## 3. 认证与登录联调

- **验证码**：`GET /api/auth/anno/captcha?key={uuid}` → 返回图片 + 服务端缓存 code（key 自生成 UUID）。
- **登录**：`POST /api/auth/anno/login`，body `{account, password, key, code}` → 返回 `{user, token:{token, expire}, permissionsList}`，**无 refreshToken**。
- **JWT 头字段 = `token`**（**不是** `Authorization`）：`authentication.user.header-name: token`，实测 expire = **7200s**。
- **网关行为**：`TokenContextFilter` 解析后向下游注入 `userid` / `name` / `stationid`(+`account`/`orgid`)；业务侧用 `RequestContext.getUserId()`。
- **401 处理**：无刷新机制 → 清本地 token 重新走登录，不要再实现 refresh。
- **网关白名单**：`ignore.auth.url=[/anno,/captcha]` 实测生效（登录/验证码免鉴权）。

> `/api/auth/**` 与 `/api/authority/**` 等价，均路由到 pd-auth-server，任务卡里写 `/api/auth/anno/login` 正确，勿改。
