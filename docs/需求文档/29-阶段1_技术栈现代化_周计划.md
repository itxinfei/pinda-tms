# 阶段 1：技术栈现代化 · 周计划

> **周期**：2026-10-09 起，2.5-3 周（约 20-26 人日）
> **目标**：把后端从 JDK 8 + Spring Boot 2.2.5 升到 JDK 21 + Spring Boot 3.3，前端管理端从 Vue2 升到 Vue3 + Vite，中间件同步升级。
> **产出**：全链路可启动、`mvn compile` 通过、docker compose 一键起。
> **依据**：《开源产品化路线图_技术栈现代化.md》§2（**已于 2026-10-08 移入 `_调研归档/`，版本选型以 SRS 第 2 章为准**）、《全局定案》D-28/D-29。
>
> ⚠️ **周次口径声明（2026-10-08 统一，防 AI 排期错）**：本计划 W1–W3 是「**技术栈升级周**」，与《优先级总览》§五 的 **W1–W8「P0-x 抓手交付 Sprint」是两套不同时间轴**，W1 含义不同、**不可互相换算**。功能交付排期以《优先级总览》§五 +《整体项目排期总览甘特》为准；本计划只管技术栈升级线。
>
> 🔴 **2026-10-08 代码实测校正（务必先读《08-Java后端升级方案_实测基线.md》）**：本计划原估算偏乐观，实测发现**两个此前未识别的阻断项**，W1 任务须按下表调整后再执行：
> - **① `pd-authority` 是独立聚合 pom（无 parent）**，版本与主链不一致（SB2.2.2/Hoxton.SR1/SCA2.1.1 vs 主链 2.2.5/SR3/2.2.1）→ **必须先合并基线**，否则 47 个 pom 分裂成两个不兼容世界（原 1.2 的"改版本号"不够）。
> - **② 网关现为 Zuul 1.x**（实测 `spring-cloud-starter-netflix-zuul`，包路径 `com.itheima.pinda.zuul`），**SRS §1.2 原写"现状=Gateway"有误**。Netflix Zuul 自 SC2020.0 已移除、无迁移路径，5 个自定义 Filter 需**重写**为 `GlobalFilter`，原"1.5 路由配置迁移 2-3 人日"**低估**，详见方案 §2.2。
> - **③ Drools 6.5 在 JDK21 下编译期即失败**（依赖已移除的 `javax.xml.bind`），须升 Drools 8.x 并回归运费金额（原 1.6 已含，但须先跑基线金额比对）。
> - **④ javax 实测影响 76 个文件**（870 文件基数）：`javax.validation` 42 / `javax.servlet` 25 / `javax.annotation` 9（`jakarta.*` 现0 处）。
> - **⑤ Lombok 1.18.4/1.18.10 不支持 JDK21**，须≥1.18.30 并改用 `<release>`；构建链 3 处硬编码 JRE8（`deploy/ci/Dockerfile`、`deploy/apps/Dockerfile.base`、`Dockerfile`）。

## 风险登记

| 风险 | 概率 | 应对 |
|---|---|---|
| OpenRewrite 迁移不干净，javax. 残留 | 中 | 全局搜 `import javax.` 手工补；重点查 servlet/persistence/validation/annotation 四个包 |
| Gateway 过滤器重写漏逻辑 | 中 | 对照原 Zuul Filter 逐个迁；登录/鉴权/401 三个关键链路冒烟 |
| Drools 8.x DSL 语法不熟悉 | 高 | 先在测试模块跑通一个规则，再迁全量；保留 6.5 规则参考 |
| MySQL 8.0 数据迁移失败 | 低 | mysqldump 全量导出→导入；字符集 utf8mb4 已有；窗口函数白送 |
| Nacos 2.x 配置导出导入丢配置 | 低 | 导出前备份；导入后逐条核对 35 条配置 |
