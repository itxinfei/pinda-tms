# 品达物流 TMS — 上线差距清单（从 70 分底座 → 真实可商用）

> **这份清单管什么**：按《需求文档 v2.4》及各任务卡做完，得到的是"四端齐全、主干闭环"的 **70 分底座**（智能是规则版、外部能力是 mock、没经过规模化验证）。本清单列出**真正上线/卖给客户前必须补的真实对接与工程项**，每项给现状、要做什么、优先级、粗估工作量、验收方式。
> **怎么用**：按 §5 三阶段推进——**P0 上线最小集**（能真收钱、真开票、真通知、跑不崩、可回滚、有备份）先做；P1/P2 按客户和规模再补。
> **口径说明**：工作量为**1 名全栈开发者的人日粗估（主观，需按实际核实）**；第三方能力的具体接口/费率/资质以**各厂商官方最新文档和当地监管要求**为准，实施前必须核实，本文不替代官方文档。
> **生成日期**：2026-10-07（索引第 35 条）。

## 2. A 域：外部渠道/资质对接（上线绕不开）

### A1 真实支付（P0）
- **现状**：支付走 mock，`platform/send` 是占位，回调不经拦截器。
- **要做**：
  - C 端客户：接**微信支付 / 支付宝**（小程序调起、H5/扫码、退款、对账文件下载）；
  - B 端客户/月结：对公转账 + **银企直连或银行回单**登记（物流 B2B 大量是账期，不一定线上付）；
  - 司机/承运商付款：走对公/代发，**不经过个人钱包**。
- **合规红线**：资金必须走**持牌机构**（微信/支付宝/银联/银行），**不得自建资金池、不得"二清"**（无支付牌照代收代付）；若做网络货运平台撮合结算，需**网络货运道路运输经营资质**，资金流要合规。
- **验收**：真实环境一笔小额支付→回调入账→退款→T+1 对账文件能对上；回调幂等（重复通知不重复入账）；异常可人工对账。

### A2 发票/税控（P0）
- **现状**：`pd_invoice` 有流程，开具是 mock。
- **要做**：对接**数电票（全电发票）**开票能力（电子发票服务平台，或第三方开票服务商/税务 UKey 方案），实现开具→交付（短信/邮件/PDF）→红冲→作废；发票金额与运费单/审计结果一致。
- **验收**：测试环境开出一张真实/测试数电票可查验；红冲留痕；发票与账单金额对得上。

### A4 短信 / 微信通知通道（P0）
- **现状**：`pd_notify_record` 只记录，通道模拟。
- **要做**：接**阿里云/腾讯云短信**（验证码、告警、节点通知签名与模板报备）；小程序接**订阅消息**，公众号接模板消息；通道失败重试+降级（短信失败不阻断主流程）。
- **验收**：验证码/告警/签收通知真实送达；模板审核通过；失败有重试记录。

### A5 地图商用授权（P0）
- **现状**：百度 `location.ak` 占位。
- **要做**：注册**企业认证百度地图账号**、申请正式 ak、按 DAU/并发确认配额、配置 refer/域名白名单防盗用。
- **验收**：正式 ak 无超限报错；配额可监控；ak 不暴露在不安全位置（小程序/前端 key 按官方建议加白名单）。

### A3 电子合同/电子签（P1）
- 对接**腾讯电子签 / e签宝 / 法大大**等：司机承运协议、承运商加盟/运输合同、客户协议在线签，存档可查（福佑即用腾讯电子签）。
- **验收**：发起→实名认证→签署→归档全链路通；合同 PDF 可下载、有法律效力（采用持牌 CA 电子签名）。

### A6 实名认证 / 银行卡鉴权（P1）
- 司机/承运商：身份证+驾驶证+从业资格证 OCR/核验；企业承运商：营业执照+法人核验；客户：手机号实名；银行卡鉴权用于付款账户校验。走第三方实名/核验服务。
- **验收**：实名通过/不通过结果准确；留痕；隐私信息加密存储、最小化采集。

## 3. B 域：硬件 / IoT / 设备

### B1 车载定位终端接入（P1）
- **现状**：靠手机定位 + Netty 上报。
- **要做**：接入**部标 JT/T 808（含 808-2019）**等主流终端协议（可参考 **Traccar** 已支持的大量协议与事件模型），实现注册/鉴权/定位/心跳/告警；统一落到轨迹表，坐标按 `coordSystem` 标识转换。
- **验收**：一台真实/模拟器终端接入，定位连续、断线重连、告警（超速/围栏）能进系统。

### B5 蓝牙打印 / PDA（P1）
- 快递员端接**蓝牙热敏打印机**（面单/取件凭证），PDA/手持机适配（联云 LMS 同类）。
- **验收**：取件详情一键打印面单，格式/条码可扫；主流便携打印机兼容。

### B3 地磅称重（P1）
- 对接地磅系统（串口采集/地磅软件 API/人工录入兜底），重量写入 `pd_iot_weight` 并关联运单，作为计费/核重依据。
- **验收**：过磅重量自动进系统、可关联运单；异常重量（与申报偏差）有提示。

### B4 冷链温控（P1）
- 温感设备/IoT 平台对接，温度定时写入 `pd_iot_temperature`，超温阈值自动告警+通知（参考 oTMS 温控整合）。
- **验收**：温度曲线可查；超温实时告警；断采有提示。

### B2 司机视频（P1/P2）
- 方案二选一：**国标 GB/T 28181 / JT/T 1078** 自建，或**云厂商 RTC**（接入快、成本按用量）。先做 POD/作业场景视频与管理端查看，实时全车监控放后期。
- **验收**：司机端能推流、管理端能看；弱网可降级；录像/截图留存策略明确。

## 4. C 智能深化 / D 工程非功能 / E 数据实施（要点）

### C 智能深化（P2，依赖真实数据积累，**不要在没数据时硬上**）
- **C1 调度 VRP**：用真实车辆路径优化（时间窗/载重/车型/多点取送）替代 DFS，可引入成熟优化库/引擎；先灰度对比人工与算法结果。
- **C2 ETA 机器学习**：积累足够历史趟次后，用实际时长偏差训练，替代固定线路时长。
- **C3 异常/费用智能识别**：在规则/阈值（均值±2σ）之上叠加模型，降低误报、辅助审核。
- **验收**：算法结果可解释、可回退人工；上线前与旧规则 A/B 对比，指标（空驶率/准点率/误报率）有量化提升才切换。

### D 工程 / 非功能
- **D6 CI/CD（P0）**：完善 Gitea Actions：代码→构建→镜像→推送→部署，支持**蓝绿/灰度、数据库变更脚本门禁、失败自动回滚**。验收：一次故意制造失败能自动回滚到上一版本。
- **D4 可观测性（P0）**：统一日志聚合 + 关键指标（QPS/响应/错误率/JVM/容器/中间件）+ 告警值班；补齐链路追踪。验收：故障能在分钟级从告警定位到日志/链路。
- **D5 备份恢复（P0）**：MySQL 定时全量+binlog 增量、Redis/Nacos 配置、关键文件备份，**定期做恢复演练**。验收：从备份成功恢复到演练环境，RPO/RTO 达标。
- **D1 压测容量（P0）**：对登录/下单/调度/轨迹上报/网关压测，得到容量基线与瓶颈，确认同时在线司机/上报 QPS 达标。验收：有压测报告，关键链路在目标并发下 P95/错误率达标。
- **D3 分布式事务（P1）**：评估启用 Seata（AT/TCC）或确认最终一致性+对账补偿足够；跨服务资金/库存类操作必须有补偿。验收：注入故障（宕机/超时）数据最终一致、无悬挂/错账。
- **D7 高可用（P1）**：无状态服务多实例+负载均衡、MySQL 主从、Redis 哨兵/集群、网关/前端冗余。验收：任一实例/节点宕机业务不中断（演练）。
- **D2 等保（P1 二级 / P2 三级）**：按等级保护要求做安全加固（账号/权限/审计/加密/边界/备份），配合测评机构过测。验收：取得相应等级备案/测评报告（周期长，尽早启动）。

### E 数据 / 实施
- **E1 基础数据初始化（P0）**：机构/网点、线路、价格协议、客户、车辆司机、承运商、计费规则等真实数据录入并核对（不是测试数据）。验收：基础数据完整、与实际一致、可支撑下单调度。
- **E3 试点+SOP+培训（P0）**：选 1 个网点/线路真实跑全流程，沉淀作业 SOP，培训调度/司机/快递员。验收：试点期间真实订单全链路跑通、问题闭环。
- **E2 老系统迁移（P1）**：若从纸面/老系统切换，做数据迁移+双跑核对。验收：迁移数据抽样核对一致、数量对平。
- **E4 数据积累与校准（P1，持续）**：真实数据进来后持续校准调度规则、ETA、报表口径、异常阈值。验收：报表与财务实际对得上、调度准点率稳定。

## 5. 三阶段路线（建议顺序）

### P0 上线最小集（能真实跑业务、能收钱、不翻车）
A1 支付 · A2 发票 · A4 通知通道 · A5 地图授权 · D6 CI/CD · D4 基础监控 · D5 备份恢复 · D1 基础压测 · E1 基础数据 · E3 试点跑通+培训
> 目标：小范围真实订单全链路跑通，钱、票、通知是真的，出问题能监控、能回滚、能恢复。

### P1 商用增强（接设备、补合规、可对外交付）
B1 终端 · B5 打印/PDA · B3 地磅 · B4 温控 · B2 视频(基础) · A3 电子签 · A6 实名 · D3 一致性 · D7 高可用 · D2 等保二级 · E2 迁移 · E4 数据校准
> 目标：减少人工录入、补齐对外销售所需资质与稳定性。

### P2 规模化 / 智能化
C1 VRP · C2 ETA ML · C3 智能识别 · D2 等保三级 · 多组织/大规模设备接入
> 目标：从"执行型 TMS"向"经营型/平台型 TMS"演进（对齐 G7/Blue Yonder）。

## 6. "可商用"总验收（DoD）

- [ ] 真实支付/发票/通知/地图全打通，回调幂等、对账能对平（非 mock）。
- [ ] 关键设备（定位/打印，按客户需要的称重/温控/视频）真实接入。
- [ ] 压测有容量基线并达标；高可用演练通过；备份可成功恢复。
- [ ] CI/CD 失败能自动回滚；监控告警能分钟级定位。
- [ ] 资金合规（持牌通道、无二清）；需要的运输/网络货运资质、等保等级齐备。
- [ ] 基础数据真实完整；试点真实跑通、有 SOP 和培训；报表与财务实际一致。

## 7. 风险与依赖提示

- **资质周期长**：支付商户号、短信签名模板、发票/税控、等保测评、网络货运资质都需审核/测评周期，**尽早启动**，不要等开发完才办。
- **硬件依赖现场**：地磅/温控/终端/打印涉及现场设备与网络，需实地联调，远程无法替代。
- **智能项依赖数据量**：没有足够真实历史数据，ML/VRP 无法验证有效，切忌过早投入。
- **本文为工程实施清单**，具体费率、接口、资质条件以各厂商官方与主管部门最新规定为准，落地前逐项核实。
