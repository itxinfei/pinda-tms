# 任务卡 PRD 模块书写模板（统一体例）

> **用途**：新建或补全任何**任务卡**时，PRD 相关段落一律按本模板写，**不要每张卡各造一套字段与标题**。
> **背景**：六份任务卡（客户小程序 / 快递员端 / 司机端 / 管理端业务页 / 运营可视化 / 财务结算）PRD 段落需统一口径，本模板抽出共用骨架，各卡只填内容。
> **依据**：结构提炼自《财务结算与调度运力IoT任务卡》§PRD-1~§PRD-5（当前最完整的一份），并参照《运营可视化与成本管控任务卡》§2.10/§2.11。

---

## 0. 使用规则

1. **只写本卡特有的东西**；通用红线（三端走网关、JWT 头 `token`、状态禁硬编码、配置外部化）一律指向《ClaudeCode开发纪律与红线》，**不复制**。
2. **需求与业务规则以 SRS §6 为准**，本卡只写"实现级细节"（字段/接口/排期/DoD），**不重复** SRS §6 的规则。
3. 标 ✅/🔲/❌/🟡 现状时，**以 Java 后端是否真有实现为准**（前端有而 Java 无 = 🟡，不可标 ✅）。
4. 编号用本卡自有前缀（勿占用 SRS 的 `前缀-nn` 空间）。
5. **DoD 必须可测**：每条含"动作 + 可观察结果"，禁止"基本可用""尽量"等模糊词。

## §PRD-4 接口与数据落地（Module 5）

### §PRD-4.1 接口三层落点（★全项目通用，勿自创）
1. **数据/服务层**：在业务内部服务实现（Feign 互调）；
2. **网关暴露层**：由 `pd-web-manager` / `pd-web-customer` / `pd-web-courier` 聚合 Controller 暴露，路径 `/api/web-manager/<模块>/*`；
3. **权限注册**：注册进 `pd_auth.pd_auth_resource` 并绑角色。

> 内部服务网关无路由（`ignored-services:'*'`），前端**不可直连**内部路径。
