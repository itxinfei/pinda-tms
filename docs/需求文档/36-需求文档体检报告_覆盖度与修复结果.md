### 4. 纠正方向性错误
- **BASE-06 数据字典**：原写"pd-base 零实现，须新建字典服务"。⚠️ 另经代码实测发现三处偏差，已由另一并行 agent 深度订正并留痕：① 实体 `Dictionary`/`DictionaryItem` **实际在 `pd-auth-entity`**；② 落点应为 **`pd-auth`（前端既有契约前缀 `/authority/`）而非 `pd-base`**；③ **只读枚举真源已存在**（`AuthorityGeneralController#/enums` + 网关 `GeneratorController#/dictionary/enums`、`/enums`）→ 真实缺口只是**管理端字典 CRUD**，**禁止新建第二套字典服务或字典表**（`D-32` 基座自带 `/dict/*` 两级契约与既有不一致，按"契约优先"改造）。
- **BASE-07 应用管理**：落点同样是 `pd-auth`；全库 `*Application.java` 均为启动类，**无 `Application` 业务实体** → 确为纯新建。

### 5. 补齐需求要素（23 条）
- **SYS-01~06**（6 条）：竖线单行 → 多行体例，**补优先级**（SYS-04资源管理 P0 等）+ 业务规则 + 验收
- **BASE-01~05**（5 条）：补优先级（P0）+ 业务规则 + 验收（BASE-06/07 已由另一 agent 订正，不动）
- **DIS-01~05**（5 条）：补角色 + 业务规则（业务范围过滤、拒收码值映射 `status=0` vs `SignStatus.REJECTION=2`、越权扫单拒绝、水印防虚假上报、准时率口径）
- **DRV-01~04**（4 条）：补角色 + 业务规则（任务归属校验、上报间隔外部化、`pickUp/finish` 是真实链路而 `depart/arrive/deliver` 是死方法、离线补传幂等）
- **CST-01~02**（2 条）：补角色 + 业务规则（JWT 无 refreshToken、禁传 `transportTaskId`、运费以后端为准、Share Link 最小暴露+可撤销）
- **VID-01**：补验收标准（原先独缺）
- **WMS-01**：补角色 + 业务规则（轻量、不做重型、流水不可改台账）
