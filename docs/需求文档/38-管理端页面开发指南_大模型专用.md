# 管理端业务页面开发指南（大模型专用）

> **目的**：解决"大模型写的页面很垃圾、布局混乱、样式不统一"的问题。
> **方法**：提供**完整的标准页面模板代码**，大模型开发时**直接复制模板，只替换业务字段**，不要自由发挥。
> **强制力**：所有管理端业务页必须套用本指南的模板，禁止从零设计 UI。

---

## 〇、大模型开发铁律（必须遵守）

1. **先复制模板，再改业务** - 不要从零写页面，先复制对应的模板，然后只改业务字段
2. **只用 Element Plus 组件** - 禁止手写 HTML/CSS 替代组件
3. **设计 Token 全部用变量** - 禁止硬编码颜色/间距/字号
4. **页面结构统一** - 所有列表页都是：筛选区 + 表格区 + 分页 + 弹窗
5. **三态必做** - 加载中（v-loading）、空状态（el-empty）、错误（重试按钮）

<script setup lang="ts">

import { ElMessage, ElMessageBox } from 'element-plus'

// ============ 状态定义 ============
const loading = ref(false)

  senderName: [{ required: true, message: '请输入寄件人', trigger: 'blur' }],

// 状态标签类型

    23010: '拒收',

// 查询

  loading.value = true

    // total.value = res.counts        // 总数字段是 counts（非 total）

  }
}

// 重置
const handleReset = () => {
  queryForm.orderNo = ''
  queryForm.status = null
  queryForm.page = 1

}

// 新建
const handleCreate = () => {
  dialogTitle.value = '新建订单'

</script>

### 模板 1：开发列表页

```
请在 vue3-element-admin 项目中开发【订单管理】页面。

要求：
1. 直接复制《管理端业务页面开发指南》中的标准页面骨架
2. 业务字段：
   - 表格列：订单号、寄件人、收件人、状态、金额、下单时间、操作
   - 筛选区：订单号（输入框）、状态（下拉框）
   - 弹窗表单：订单号、寄件人、收件人
3. 接口：
   - 列表：POST /api/web-manager/order-manager/order/page
   - 新建：POST /api/web-manager/order-manager/order
   - 编辑：PUT /api/web-manager/order-manager/order/{id}
4. 状态枚举（🔴 严禁硬编码 1/2/3——订单状态是 23000~23011 五位码、共 12 级）：
   - 统一引用后端枚举 `OrderStatus`，码值与中文对照以《07-数据字典与枚举口径.md》§1 为准；前端集中维护一份 code → {文案, el-tag type} 映射表，不在页面里写裸数字
   - 映射示例：23000 PENDING 待取件(info) ｜ 23005 IN_TRANSIT 运输中(primary) ｜ 23009 RECEIVED 已签收(success) ｜ 23010 REJECTION 拒收(danger) ｜ 23011 CANCELLED 已取消(info)
   - 状态下拉选项由枚举常量生成，值用真实 code（如 23005），不得自造 1/2/3
5. 样式要求：
   - 主色 #2B6CFF
   - 页面背景 #f5f6f8
   - 卡片阴影 none
   - 表格带边框、斑马纹

不要自由发挥布局，严格按照模板来。
```

## 三、页面类型对照

| 页面类型 | 用哪个模板 | 示例 |
|---|---|---|
| **列表页**（有表格 + 筛选 + 分页 + 弹窗） | 第一章标准骨架 | 订单列表、运单列表、车辆列表、司机列表 |
| **详情页**（信息展示 + 时间轴） | 模板 2 | 订单详情、运单详情、任务详情 |
| **表单页**（纯表单） | 简化版骨架（去掉表格区） | 新建客户、新建车辆 |
| **看板页**（卡片 + 图表） | Dashboard 模板 | 首页 Dashboard、调度看板 |
| **地图页**（地图 + 列表） | 地图模板 | 在途监控、调度一张图 |

## 四、大模型开发检查清单（写完后自检）

写完页面后，大模型必须自己检查以下项：

- [ ] 页面结构是否符合标准骨架？（筛选区 + 表格区 + 分页 + 弹窗）
- [ ] 是否只用了 Element Plus 组件？（没有手写 div 布局）
- [ ] 颜色是否用了设计 Token？（没有硬编码 hex）
- [ ] 是否有加载中状态？（v-loading）
- [ ] 是否有空状态？（el-empty）
- [ ] 表格是否有边框和斑马纹？（border stripe）
- [ ] 分页是否完整？（total, sizes, prev, pager, next, jumper）
- [ ] 表单是否有校验规则？（rules）
- [ ] 弹窗是否有取消和确定按钮？
- [ ] 状态标签是否用了 el-tag？（没有手写颜色）

## 五、常见错误（大模型容易犯的错）

| 错误 | 正确做法 |
|---|---|
| 手写 `<div style="margin: 10px">` 做布局 | 用 el-row / el-col 栅格布局 |
| 硬编码 `#409EFF` 蓝色 | 用 CSS 变量 `var(--c-primary)` |
| 表格没有分页 | 必须加分页组件 |
| 弹窗没有表单校验 | 必须加 rules |
| 加载状态忘了做 | 必须加 v-loading |
| 空状态忘了做 | 必须加 el-empty |
| 操作按钮太多 | 最多 3 个（详情、编辑、删除） |
