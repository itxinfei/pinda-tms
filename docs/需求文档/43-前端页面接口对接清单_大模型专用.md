## 🔴 分页与返回结构（本项目不统一，必须逐接口看）

原文档"分页参数统一 page/pagesize、返回统一 items/counts"的说法**是错的**。实测存在三套口径：

| 口径 | 适用接口 | 请求参数 | 返回结构（成功 code=0） |
|---|---|---|---|
| **A 管理端** | `/web-manager/**` 的所有分页 | `page` + **`pageSize`（驼峰大写 S）** | **裸 `PageResponse`**（无 Result 包裹）：`{ items, counts, pages, page, pagesize }` |
| **B 司机/客户端** | `/web-driver/business/cargo/wait`、`/history`；`/web-customer/mailing/page` | `page` + **`pagesize`（全小写）** | `Result`，分页体在 `data`：`{ code:0, data:{ items, counts, pages, page, pagesize } }` |
| **C 告警查询** | `GET /netty-service/alarm` | `page` + **`pageSize`（驼峰）** | `Result`，分页体在 `data`，但计数字段叫 **`total` 不是 `counts`**：`{ code:0, data:{ items, total, pages, page, pageSize } }` |

> ⚠️ **三大静默陷阱（写错不报错，只拿到 undefined）**：
> 1. 参数名 `pageSize` / `pagesize` 混用 → 后端收不到，返回首页/全量。
> 2. 管理端返回是**裸 PageResponse**（直接 `res.items`）；司机/客户端是 `Result` 包 `data`（`res.data.items`）。
> 3. 计数字段管理端/列表叫 `counts`，告警叫 `total`。
>
> 📌 改任何分页代码前先 curl 验证一次真实结构，不要凭记忆。

## 〇、全局约定

| 项 | 约定 |
|---|---|
| **基础路径** | `http://192.168.20.130:8760`（开发环境）；下表路径均含 `/api` 网关段，拼接 `基础路径 + 路径` 调用 |
| **唯一入口** | 必须走网关，**禁止直连 pd-web-*（8161~8164）/ pd-netty(8192) 业务端口**（直连会被 `TokenAuthInterceptor` 401 拒绝；8192 仅限联调排障） |
| **请求头** | **`token: <JWT>`**（三端）；⚠️ 管理端历史遗留 OAuth2 用 `Authorization: bearer`（仅 Vue3 专项内处理） |
| **成功码** | `code === 0`（数字）。`pd-auth-server` 用 `R<T>`（失败 `code=-1/-2`，含 `isSuccess` 布尔） |
| **失败处理** | `code!==0` 弹错；**401 清 token 跳登录**（无 refreshToken，禁止静默刷新） |
| **状态数字** | 🔴 **禁止硬编码**（如 `status==23005`），一律查《07-数据字典与枚举口径.md》 |

# 二·B、快递员端页面接口（前缀 `/api/web-courier`）

> 分页为口径 **B**：`page`+`pagesize`，`Result.data` 为 PageResponse。

# 四、常见错误对照

| ❌ 错误 | ✅ 正确 |
|---|---|
| 凭印象写路径（`/api/order/list`、`/task/my-tasks`、`/order/create`） | 逐接口查本文；管理端 `/web-manager/...`，下单 `/mailing` |
| 分页一律写 `page/pagesize` 或一律 `page/pageSize` | 管理端 `pageSize`，司机/客户端列表 `pagesize`，告警 `pageSize`——逐接口看顶部三口径 |
| 管理端分页读 `res.data.items` | 管理端是**裸 PageResponse**，读 `res.items`；司机/客户端才读 `res.data.items` |
| 计数一律读 `counts`（或一律 `total`） | 列表读 `counts`，**告警读 `total`** |
| 请求头用 `Authorization: Bearer`（三端） | 三端用 **`token: <JWT>`**；管理端 OAuth2 遗留例外 |
| 成功判 `code==="00000"` | `code === 0`（数字） |
| 取登录 JWT 用 `res.data.token` | JWT 在 **`res.data.token.token`** |
| 登录传 `username/captcha` | 传 **`account/code`**（+key/password） |
| 直连服务端口（:816x / :8192） | 一律走 `:8760` 网关 |
| 硬编码状态数字 | 查《07》，禁硬编码 |
| 401 后静默刷新 token | 无 refreshToken，直接清 token 跳登录 |
| 快递员端用 `GET /courier/verifyIdCard` | 已 `@Deprecated`，改用 **`POST /courier/verifyIdCard`**（form/query 参数） |
| 快递员/司机异常上报走 `/api/netty-service/alarm/report` | 该入口**免鉴权**且 `reporterId` 由调用方自填，可冒名；必须走 `POST /api/web-courier/courier/exception/report`（D-41）/ `POST /api/web-driver/business/cargo/exception/report`（D-57） |
| 客户端与快递员端共用 `MailingSaveDTO`/`RouteDTO` 的 TS 类型 | 两端**类名相同、字段不同**，必须各定义一份 |
| 快递员列表页读 `receiver.phone` | 列表 DTO 的 `receiver`/`sender` 只是**姓名字符串**，联系方式只在详情 `AddressInfoDTO{...phoneNumber}`（字段叫 `phoneNumber` 不是 `phone`） |
