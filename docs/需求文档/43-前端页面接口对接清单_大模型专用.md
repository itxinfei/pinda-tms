# 前端页面接口对接清单（大模型专用）

> **目的**：按"页面→接口"的方式整理，让大模型开发时直接查这个清单，不要瞎编接口路径。
> **配套文档**：《08-后端接口文档.md》（完整接口清单）、《39-核心业务页面设计示例_大模型专用.md》（管理端页面）、《42-移动端核心页面设计示例_大模型专用.md》（移动端页面）
> **强制力**：前端开发时必须按本文档的接口路径调用，禁止自己编接口路径。

> 🔴 **分页与返回结构（2026-10-08 源码实测订正，本文原先写错已改）**：
> - **参数名**：本项目后端分页参数**统一为 `page` + `pagesize`（全小写）**。源码证据（`pd-web-manager`）：`PageResponse.builder().page(page).pagesize(pagesize)`（见 `AgencyController`/`BusinessHallController`/`DriverJobController` 等）。
>   ⚠️ **写 `page`/`pagesize` 会让后端收不到分页参数** → 返回全量或首页数据。**本文下方表格凡写 `page`/`pagesize` 的均已订正为 `page`/`pagesize`**。
> - **返回结构**：`PageResponse` 的字段是 **`items` / `counts` / `pages` / `page` / `pagesize`**（**不是 `list`/`total`**）。示例：`{ code:0, data:{ items:[...], counts:100, pages:10, page:1, pagesize:10 } }`。
>   ⚠️ 部分接口返回裸 `Result{code,msg,data}` 或 `R<T>`（`pd-auth-server` 失败码为 `-1/-2`），**逐接口看《08-后端接口文档.md》**。
> 📌 **红线**：分页参数名/返回字段名写错，前端会拿到 `undefined` 而不报错——**属静默失败，最难查**。改任何分页相关代码前先curl 验证。

## 〇、全局约定（所有页面通用）

| 项 | 约定 |
|---|---|
| **基础路径** | `http://192.168.20.130:8760/api`（开发环境，**必须走网关，禁止直连 pd-web-* 8161~8164**） |
| **请求头** | `token: <JWT>`（移动端与三端）；⚠️ **管理端历史遗留 OAuth2 用 `Authorization: bearer`，见 SRS §7 硬事实第 2 条** |
| **成功码** | `code === 0`（数字，不是字符串）。⚠️ **返回结构不统一**：`pd-web-*` 混用 `Result{code,msg,data}` / `R` / `PageResponse<T>` / 裸 `VO` / 裸 `List`，**不可想当然**，见《08-后端接口文档》第 17 行 |
| **失败处理** | `code !== 0` 时弹错误提示；401 时清 token 跳登录（**无 refreshToken，禁实现静默刷新**） |
| **分页参数** | 🔴 **`page` + `pagesize`（全小写）**——源码实测统一用这套；写 `pageNum`/`pageSize` 会**静默失效**（后端收不到分页参数） |
| **分页返回** | `PageResponse` 字段为 **`items`/`counts`/`pages`/`page`/`pagesize`**（**不是 `list`/`total`**）；⚠️ 部分接口返回裸 `Result{code,msg,data}` 或 `R<T>`，逐接口看《08-后端接口文档.md》 |
| **状态数字** | 🔴 **禁止硬编码**（如 `status == 23005` ❌），一律查《07-数据字典与枚举口径.md》 |

## 一、管理端页面接口清单

### 1.1 登录页

| 功能 | 接口路径 | 方法 | 参数 | 返回示例 |
|---|---|---|---|---|
| 获取验证码 | `/authority/anno/captcha?key={key}` | GET | key（时间戳随机串） | 直接返回 PNG 图片流 |
| 登录 | `/authority/anno/login` | POST | `{ username, password, key, captcha }` | `{ code: 0, data: { token: "xxx", user: {...} } }` |

**注意事项**：
- 验证码接口直接返回图片，前端用 `<img :src="url">` 展示
- key 是前端生成的随机串，登录时和验证码一起传给后端
- 登录成功后，token 存 localStorage，后续请求都带上

## 四、常见错误对照

| 错误 | 正确做法 |
|---|---|
| 接口路径写错（如 `/api/order/list`） | 管理端是 `/api/web-manager/order-manager/order/page` |
| 请求头用 `Authorization: Bearer xxx` | 管理端/三端用 `token: xxx`（⚠️ 管理端历史遗留 OAuth2 例外，见 SRS §7 硬事实第 2 条） |
| 成功判断用 `code === "00000"` | 用 `code === 0`（数字） |
| 分页参数用 `pageNum` / `pageSize` / `page`+`size` | 🔴 用 **`page` + `pagesize`**（全小写，源码实测）——写错**静默失效**，不报错 |
| 分页返回读 `data.list` / `data.total` | 🔴 `PageResponse` 字段是 **`items` / `counts` / `pages`**，读 `list/total` 得 `undefined` |
| 直接调用内部服务接口（如 `/api/pd-oms/order/list`） | 内部服务不暴露网关，必须走 `/api/web-manager/` 聚合层 |
| 轨迹接口带 token | 轨迹接口免鉴权，不用带 token |
| 硬编码状态数字（如 `status == 23005`） | 🔴 查《07-数据字典与枚举口径.md》，禁止硬编码 |
| 401 错误后静默刷新 token | 没有 refreshToken，401 直接跳登录页 |
