# 第二份竞品对标补充分析（G7易流 / 路歌 / 科箭）

> **来源**：《40-头部TMS竞品对标_G7路歌科箭.md》（2026-10-08，与《37-联云科技 TMS》并列的**第二份对标源**）
> **目的**：联云对标覆盖了"TMS 必备功能"，但**漏掉了"运营细节类"功能**。本档补齐这部分，并给出取舍结论。
> **核查方式**：逐条 grep SRS §6 验证是否真缺（不凭印象）。

---

## 〇、结论速览

| 结论 | 内容 |
|---|---|
| ✅ **与联云对标重合** | 订单/调度/在途/回单/结算/司机端 —— 三家共同核心功能，功能清单与差距判定见《40》§〇 与 §五 5.1，本档不重述 |
| 🔶 **联云对标漏掉的 4 项可借鉴功能** | 车辆自动打卡、电子出厂证、运费审批流、车辆维修保养/保险 | 
| ⚠️ **1 项已在 SRS** | 驾驶行为分析 → 已在 `CMP-02`（急加速/急刹车/疲劳），不重复补 |
| ❌ **明确不做** | 5 项，逐项判定与出处见 §三（与《40》§5.3 / §2.2 / §3.2 / §4.2 结论一致） |

**与联云对标的差异**：联云是**产品功能清单**视角（有什么功能）；G7/路歌/科箭给了**运营管理细节**视角（车怎么管、钱怎么批、证怎么打）——后者更贴近"少发货主/司机日常运营"，是前者没覆盖的盲区。

## 一、4 项补入 SRS 的功能（✅ 已核实确缺）

### 1. GPS 到场自动打卡（P1 · 路歌）
- **竞品做法**：见《40》§3.2（路歌「GPS 500 米自动打卡」）。
- **我方现状**：SRS 全文 `自动打卡` / `500米` **均 0 命中** —— 完全没有此能力。
- **价值**：解决"司机到了没点签收"的扯皮与漏报，直接提升轨迹真实率与 POD 效率。
- **建议**：并入 `TRK-01 电子围栏`（复用围栏判断逻辑），或新增 `TRK-04 到场自动打卡`。

### 2. 电子出厂证/到达凭证（P1 · 路歌"电子出厂证"）
- **竞品做法**：见《40》§3.2（路歌「电子出厂证」：替代手写出厂证、自动打印发车）。
- **我方现状**：`出厂证` **0 命中**。
- **价值**：减少纸张流转、避免签收环节造假；与我方 `POD-01` 电子签收同源。
- **建议**：并入 `POD-01`（同一套凭证机制），作为"出厂/装货环节"凭证类型。

### 3. 运费在线审批流（P1 · 路歌"运费在线审批"）
- **竞品做法**：见《40》§3.2 / §六（路歌运费在线审批：申请→调度审核→财务审批→打款，本期守 `D-27` 审批通过≠打款）。
- **我方现状**：`运费审批` / `运费申请` **0 命中** —— 我方 `POD-05 司机结算`只做了"算工资"，**没有审批流**。
- **价值**：财务合规留痕（合规 R5 系列要求可导出留痕）；缺审批流则工资支付无管控。
- **建议**：新增 `POD-08 运费申请与审批流`（P1）。

### 4. 车辆维修保养 / 保险管理（P1 · G7 车队管理）
- **竞品做法**：见《40》§2.1（G7 车队管理含车辆/司机档案、维修保养、保险管理）。
- **我方现状**：`维修保养` / `保险` **0 命中** —— `BASE-01 车辆管理` 只有档案与状态。
- **价值**：维修保养到期提醒属**合规刚需**（与 `CMP-01 证件到期` 同类）；保险到期漏保是运输企业常见风险点。
- **建议**：并入 `CMP 合规风控域`（`CMP-03 车辆维修保养与保险到期提醒`，P1）。

## 三、明确不做的（❌，避免范围蔓延）

> 5 项不做的逐项理由见《40》§2.2 / §3.2 / §4.2 / §5.3（车货匹配撮合、司机社区、物联保险、多租户 SaaS、AI 驾驶行为分析），本档不重述。关键定位约束补充如下：
> - **车货匹配/在线撮合**：`D-xx` 已定"自营/加盟运输管理，不是撮合平台"，不接外部运力。
> - **多租户 SaaS**：`§1.4` 已定"不建多租户 SaaS"，开源版单租户，商业版另议。
> - **AI 驾驶行为分析**：软件侧告警统计已覆盖于 `CMP-02`，AI 模型依赖车载终端硬件后置。
