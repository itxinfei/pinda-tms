# 技术栈与项目架构优化建议（大模型开发专用）

> **目的**：梳理当前技术栈和架构的现状，列出可以优化和完善的点，开发时注意。
> **配套文档**：《03-全局定案与待确认项清单.md》（D-29/D-32/D-33 定案）、《06-开发规范与需求规格说明书.md》
> **强制力**：本文档是建议，不是定案；开发时如果有更好的方案可以提出来，但必须先在文档里记录。

## 三、项目架构现状与优化点

### 3.1 微服务划分（现有）

| 服务 | 职责 | 优化建议 |
|---|---|---|
| pd-auth-server | 认证 + RBAC | ✅ 合理 |
| pd-gateway | 统一网关 | ✅ 合理 |
| pd-base | 基础数据（车辆/司机/线路/货物类型） | ✅ 合理 |
| pd-oms | 订单管理 | ✅ 合理 |
| pd-work | 运单与执行 | ✅ 合理 |
| pd-dispatch | 调度 | ✅ 合理 |
| pd-user | 用户（客户/快递员） | ✅ 合理 |
| pd-aggregation | 聚合查询 | ⚠️ 可以合并到对应服务 |
| pd-netty | 轨迹接收 | ✅ 合理 |
| pd-web-manager | 管理端聚合层 | ✅ 合理 |
| pd-web-driver | 司机端聚合层 | ✅ 合理 |
| pd-web-courier | 快递员端聚合层 | ✅ 合理 |
| pd-web-customer | 客户端聚合层 | ✅ 合理 |

### 3.2 数据库划分（现有）

| 数据库 | 说明 | 优化建议 |
|---|---|---|
| pd_auth | 权限中心 | ✅ 合理 |
| pd_base | 基础数据 | ✅ 合理 |
| pd_oms | 订单 | ✅ 合理 |
| pd_work | 运单与执行 | ✅ 合理 |
| pd_dispatch | 调度 | ✅ 合理 |
| pd_users | 用户 | ✅ 合理 |
| pd_aggregation | 聚合视图 | ⚠️ 可以去掉，用视图代替 |

### 3.3 架构优化建议

| 优化点 | 说明 | 优先级 |
|---|---|---|
| **服务合并** | pd_aggregation 可以去掉，用视图或 Feign 聚合代替 | P2 |
| **数据库合并** | pd_users 可以合并到 pd_base（用户量不大） | P2 |
| **缓存策略** | 热点数据（字典/线路/车辆类型）用 Redis 缓存，不要每次查数据库 | P1 |
| **接口幂等** | 支付/取消等重要接口必须做幂等，防止重复提交 | P0 |
| **限流熔断** | 网关层加限流熔断（Sentinel），防止被打垮 | P1 |
| **灰度发布** | CI/CD 加蓝绿部署或灰度发布，出问题能快速回滚 | P1 |

## 四、部署架构现状与优化点

### 4.1 现有部署

| 组件 | 部署方式 | 优化建议 |
|---|---|---|
| MySQL | Docker 单实例 | ⚠️ 生产环境要做主从 |
| Redis | Docker 单实例 | ⚠️ 生产环境要做哨兵或集群 |
| Nacos | Docker 单实例 | ⚠️ 生产环境要做集群 |
| Kafka | Docker 单实例 | ⚠️ 生产环境要做集群 |
| 微服务 | Docker 单实例 | ⚠️ 生产环境要多实例 |

### 4.2 部署优化建议

| 优化点 | 说明 | 优先级 |
|---|---|---|
| **数据库主从** | MySQL 主从复制，读写分离 | P1 |
| **Redis 哨兵** | Redis 哨兵模式，高可用 | P1 |
| **Nacos 集群** | Nacos 3 节点集群 | P2 |
| **微服务多实例** | 核心服务多实例部署 | P1 |
| **备份策略** | MySQL 定时备份 + Redis RDB/AOF | P0 |
| **监控告警** | 服务器 CPU/内存/磁盘监控 | P1 |

## 五、开发规范优化建议

| 优化点 | 说明 | 优先级 |
|---|---|---|
| **统一返回格式** | 所有接口返回 `{ code, data, msg }`，不要各写各的 | P0 |
| **统一异常处理** | 全局异常处理器，不要每个 Controller 都 try-catch | P0 |
| **统一日志格式** | 日志格式统一，便于 ELK 收集 | P1 |
| **统一分页格式** | 分页参数统一 `page` + `pagesize`，返回 `{ total, list }` | P0 |
| **统一枚举管理** | 状态码/错误码统一放枚举类，不要散落在代码里 | P1 |
| **统一命名规范** | 表名/字段名/接口名/变量名统一命名规范 | P0 |
