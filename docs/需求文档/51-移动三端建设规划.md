## 一、技术栈与工程脚手架

### 1.1 技术栈（已拍板，SRS §2.3）
| 项 | 选型 | 说明 |
|---|---|---|
| 框架 | **uni-app（Vue3 + Vite 模式）** | 单工程三端分包 |
| UI | **uview-plus**（Vue3 版） | 100% 组件化，禁裸 `<div>`+`<style>` |
| 状态 | **Pinia** | 三端共享登录态/角色 |
| 构建 | **Vite** | 禁 `NODE_OPTIONS=--openssl-legacy-provider`（Vite5 无此问题） |
| 样式 | **SCSS + Token** | Token 真源 `uni.scss` + `common/styles/variables.scss` |

### 1.2 工程结构（单工程三端分包）
```
pinda-uni-app/
├── common/               # 三端共用
│   ├── request/index.ts   # uni.request 封装（JWT自动附加/401清token/统一错误）
│   ├── api/               # customer.ts / courier.ts / driver.ts（路径常量化）
│   ├── utils/             # coord.ts(WGS84↔BD-09 / WGS84↔GCJ-02) / date.ts / offline.ts
│   ├── store/user.ts      # Pinia：登录态 + token + 角色（DRIVER/COURIER/CUSTOMER）
│   └── styles/            # variables.scss（Token）
├── components/            # 地图轨迹、扫码、POD签名、异常上报、离线队列
├── pages/
│   ├── customer/          # 寄件/地址簿/查单/轨迹/回单
│   ├── courier/           # 取派任务/扫码签收/POD/异常上报/实名
│   └── driver/            # 运输任务/位置上报/到站交付/离线队列
├── manifest.json          # 各端Key（高德AppKey、微信AppID、包名）⚠️ 待备
└── pages.json             # subPackages 三端分包 + 条件编译入口
```
- 三端通过 **`#ifdef MP-WEIXIN` 等条件编译 + `subPackages`** 共享登录/地图/扫码/POD
- ⚠️ **强约束**（红线第 12/13/21 条）：① 后端统一存储 **WGS84**，**小程序 `<map>` 需前端做 WGS84→GCJ-02 转换**（`utils/coord.ts`，原"存 BD-09"口径已废止，见 BA-19 2026-10-09 修订）；② 禁裸 `uni.request`，必过 `common/request/index.ts`；③ 手机号/证件**脱敏**展示

## 八、部署与 CI/CD（D-50 定案）

> **强制要求**：三端的 H5 版本都必须通过 CI/CD 自动构建并部署到 Docker 容器中运行，不允许手动部署。

|---|---|---|---|---|
| **司机端 H5** | `dist/build/h5` | Nginx Docker 容器 | 8081 | http://192.168.20.130:8081 |
| **快递员端 H5** | `dist/build/h5` | Nginx Docker 容器 | 8082 | http://192.168.20.130:8082 |
| **客户端 H5** | `dist/build/h5` | Nginx Docker 容器 | 8083 | http://192.168.20.130:8083 |

### 8.2 APP 端发布方式

| 端 | 发布方式 | 说明 |
|---|---|---|
| **司机端 APP** | HBuilderX 云打包/本地打包 | 生成 APK 后手动分发；后台定位必须用 App 原生能力 |
| **快递员端 APP** | HBuilderX 云打包/本地打包 | 生成 APK 后手动分发 |
| **客户端小程序** | 微信开发者工具上传 | 提交审核后发布；不做独立 APP |

### 8.3 CI/CD 流程（H5 端）

```
代码 push → Gitea Actions 触发 → pnpm install → build:h5 → 
打包成 Nginx Docker 镜像 → 推送到服务器 → 停止旧容器 → 启动新容器 → 健康检查
```

**CI/CD 配置要点**：
1. **构建命令**：`pnpm build:h5-<端名>`（driver / courier / customer）
2. **基础镜像**：`nginx:alpine`（轻量）
3. **Nginx 配置**：
   - 静态文件缓存：`expires 7d`
   - gzip 压缩：开启
   - API 反向代理：`/api/` → `http://pd-gateway:8760/api/`
4. **部署脚本**：SSH 到服务器，`docker stop` 旧容器 → `docker rm` → `docker run` 新容器
5. **健康检查**：容器启动后 `curl http://localhost:8081/` 检查是否返回 200

### 8.4 与管理端统一部署规范

> 三端 H5 的部署方式与管理端完全一致，统一走 Gitea Actions CI/CD，Docker 容器化运行。
> - 管理端：端口 80（或 8080）
> - 司机端 H5：端口 8081
> - 快递员端 H5：端口 8082
> - 客户端 H5：端口 8083
