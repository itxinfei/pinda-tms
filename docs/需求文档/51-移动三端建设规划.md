# 移动三端建设规划（客户 / 快递员 / 司机）

> **定位**：三端**从零建设**的执行规划。此前 P0 里三端需求（DIS/DRV/CST 共 11 条）长期"后端有API、前端 0 实现"，是项目最大风险点。
> **实测日期**：2026-10-08 ｜ **依据**：SRS §6.6/§6.7/§6.8/§7、§6.16移动门户域、三份任务卡（17/18/19）、《08-后端接口文档》、**后端源码实测**。
> **核心结论**：**后端三端 API 已基本齐备（customer 8 / courier 5 / driver 4 个 Controller），前端从 0 开始**；开工前须补 **2 个 API**（异常上报、在途上报）。

## 一、技术栈与工程脚手架

### 1.1 技术栈（已拍板，SRS §2.3）
| 项 | 选型 | 说明 |
|---|---|---|
| 框架 | **uni-app（Vue3 + Vite 模式）** | 单工程三端分包 |
| UI | **uview-plus**（Vue3 版） | 100% 组件化，禁裸 `<div>`+`<style>` |
| 状态 | **Pinia** | 三端共享登录态/角色 |
| 构建 | **Vite** | 禁 `NODE_OPTIONS=--openssl-legacy-provider`（Vite5 无此问题） |
| 样式 | **SCSS + Token** | Token 真源 `uni.scss` + `common/styles/variables.scss` |

### 1.2 工程结构（单工程三端分包）
```
pinda-uni-app/
├── common/               # 三端共用
│   ├── request/index.ts   # uni.request 封装（JWT自动附加/401清token/统一错误）
│   ├── api/               # customer.ts / courier.ts / driver.ts（路径常量化）
│   ├── utils/             # coord.ts(BD-09↔GCJ-02) / date.ts / offline.ts
│   ├── store/user.ts      # Pinia：登录态 + token + 角色（DRIVER/COURIER/CUSTOMER）
│   └── styles/            # variables.scss（Token）
├── components/            # 地图轨迹、扫码、POD签名、异常上报、离线队列
├── pages/
│   ├── customer/          # 寄件/地址簿/查单/轨迹/回单
│   ├── courier/           # 取派任务/扫码签收/POD/异常上报/实名
│   └── driver/            # 运输任务/位置上报/到站交付/离线队列
├── manifest.json          # 各端Key（高德AppKey、微信AppID、包名）⚠️ 待备
└── pages.json             # subPackages 三端分包 + 条件编译入口
```
- 三端通过 **`#ifdef MP-WEIXIN` 等条件编译 + `subPackages`** 共享登录/地图/扫码/POD
- ⚠️ **强约束**（红线第 12/13/21 条）：① 后端存 BD-09，**小程序 `<map>` 需前端做 BD-09→GCJ-02转换**（`utils/coord.ts`）；② 禁裸 `uni.request`，必过 `common/request/index.ts`；③ 手机号/证件**脱敏**展示

## 六、风险与建议

| 风险 | 影响 | 建议 |
|---|---|---|
| 🔴 **三端从 0 开始**（非"补前端"） | P0 内11 条需求全靠新建 App；体量大 | 严格按M-B0~M-B4 分期，**不并行三条线**；先做客户端（最简单，10-15）建立信心，再快递员、司机 |
| 🔴 **Driver 强定位必须 App 形态** | 小程序切后台 30s 停，**小程序无法满足** | 司机端**只做 App**（`plus` 原生），不做小程序；已在SRS §6.7 明确 |
| ⚠️ **两个 API 未补就开工** | 前端做到一半发现无接口 | **M-B0 先补 API 再写前端** |
| ⚠️ **Key 申请周期不可控** | 阻塞真机调试 | **今日就去申请**，不等代码 |
| ⚠️ **POD 三类凭证**（签名+照片+时间） | 拒收码值映射易错 | 严格按 SRS DIS-02 规则；上线前 curl 验证 `status=0` 映射 |
