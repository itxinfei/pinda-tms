## 一、计费契约（运价）

### 1.1 调用链（唯一算价路径）

```
客户端 POST /api/web-customer/mailing/totalPrice（试算） 或 /mailing（下单）
  → pd-web-customer MailingController
  → Feign → pd-oms OrderController
      · POST /order            （下单）      OrderController.java:60  → calculateAmount
      · POST /order/orderMsg   （试算）      OrderController.java:112 → calculateAmount
      · PUT  /order/{id}/reprice（服务端改价） OrderController.java:204 → calculateAmount
  → OrderServiceImpl.calculateAmount(OrderDTO)   OrderServiceImpl.java:239
      ① getDistance(orderDTO)  —— 百度地图地址解析 + 里程计算
      ② Drools KieSession 跑 rules/orderAmountCalc.drl
      ③ DroolsRulesServiceImpl.calcFee(AddressRule) 出金额字符串
```
> 🔴 三条入口都**只信服务端算价**：`updateById` 不接受客户端传入的 `amount`，改价必须走 `/{id}/reprice`（`OrderController.java:141`、`:198` 注释明示）。重构时若删掉 `reprice` 端点，管理端改价能力即失去落点。
> 🔴 **步骤③ 的调用点在 .drl 里，不在 Java 里**：`calcFee` 由 `orderAmountCalc.drl:33/50/67` 的 `then` 块 `new DroolsRulesServiceImpl().calcFee(addressRule)` 调用。Drools 把 `then` 编译进规则字节码，**Java 侧 grep 查不到任何引用**——因此《21》《06》《08升级方案》《36》曾一致误判其为"死代码、可清理"。删该类 → 三条续重规则运行期失败 → 全站无法算价。唯一死代码是 `main`（`DroolsRulesServiceImpl.java:34-42`）。四份文档已于 2026-10-09 订正（⚠️ 其中《36-需求文档体检报告》已于同日随 C 层归档一并从工作区删除；同一教训仍保留在《06》line408 与《21》line38，故未失传）。

### 1.2 费率卡（`pd-oms/src/main/resources/rules/orderAmountCalc.drl`，包 `rules`，dialect java）

| 规则 | 命中条件 | 首重 | 首重价 | 续重单价 | salience |
|---|---|---|---|---|---|
| 「1千克以内20元」 | `totalWeight != null && totalWeight <= 1.00` | — | **结果直接 = `"20"`** | — | 10 |
| 「200 公里以下」 | `totalWeight > 1.00 && distance <= 200.00` | 1.00 kg | 20.00 元 | **6.00 元/kg** | 9 |
| 「200~500 公里」 | `totalWeight > 1.00 && distance <= 500.00` | 1.00 kg | 20.00 元 | **9.00 元/kg** | 8 |
| 「500 公里以上」 | `totalWeight > 1.00 && distance > 500.00` | 1.00 kg | 20.00 元 | **15.00 元/kg** | 7 |

**必须照搬的规则语义（文档其他处零记载）**：
1. 四条规则同属 `activation-group "mygroup"` → **只有一条会执行**（按 salience 高者优先，组内首个命中即结束整组）。重构若漏掉 activation-group，会出现多条规则互相覆盖 `result`。
2. 距离档位是**上界闭区间 + 下界开间**：`<=200` / `<=500` / `>500`。第二档的实际语义是"200 以上至 500"，靠 activation-group 保证，**不是**独立区间判断。
3. `totalWeight` 或 `distance` 为 null 时**四条规则全不命中** → `postCodeResult=false` → 服务返回 `null`。

### 1.3 金额公式与进位口径（`DroolsRulesServiceImpl.java:17-31`）

```java
BigDecimal lost = totalWeight.subtract(firstWeight);
lost = lost.setScale(0, BigDecimal.ROUND_DOWN);   // ← 关键：向下截断，不是四舍五入、不是向上取整
return continuedFee.multiply(lost).add(firstFee).toString();
```

| 口径 | 事实 | 重构风险 |
|---|---|---|
| **续重计费单位** | 按**整千克**计，**不足 1kg 部分直接舍去**（`ROUND_DOWN`） | 常见误写成"向上取整"（顺丰式），会全线涨价 |
| 首重 | 固定 1.00 kg / 20.00 元 | — |
| 返回值类型 | **`String`**（`toString()`），非 BigDecimal | 前端/落库若按数值解析需自行转换 |
| ≤1kg 分支 | 返回字符串 `"20"`（**不是 `"20.00"`**） | 与 `calcFee` 的 `20.0` 类字符串格式不一致，展示层不要按小数位对齐 |

**算例（照此做单测，可验证实现等价）**

| 重量 | 距离 | 计算 | 金额 |
|---|---|---|---|
| 0.8 kg | 任意 | 命中规则 1 | `20` |
| 1.0 kg | 任意 | `<=1.00` 命中规则 1 | `20` |
| 1.9 kg | 150 km | 20 + 6 × trunc(0.9)=0 | `20.0` |
| 3.7 kg | 150 km | 20 + 6 × trunc(2.7)=2 | `32.0` |
| 3.7 kg | 400 km | 20 + 9 × 2 | `38.0` |
| 3.7 kg | 900 km | 20 + 15 × 2 | `50.0` |
| 5.0 kg | 200 km | 20 + 6 × 4 | `44.0` |
| 5.0 kg | 200.01 km | 20 + 9 × 4 | `56.0` |

### 1.4 距离来源与失败语义（`OrderServiceImpl.java:239-247`、`getDistance()`）

| 场景 | 返回 | 说明 |
|---|---|---|
| 地址解析失败（寄/收任一侧） | `Map{amount:"0", errorMsg:"无法计算订单距离和订单价格，请输入真实地址", orderDto:...}` | 判定依据是哨兵字符串 `"sender error msg"` / `"receiver error msg"` 被写进 `senderAddress`/`receiverAddress`（脆弱实现，重构应改为显式错误字段，但**前端已依赖 `amount=0 + errorMsg` 形态**） |
