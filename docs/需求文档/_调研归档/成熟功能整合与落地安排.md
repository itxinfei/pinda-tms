# 成熟功能整合与落地安排（总纲）

> **文档定位**：把历轮调研的**成熟功能需求**（G7 财运通 + 开源/商用 TMS 行业基准 + 联云专研 + 顺丰/京东/菜鸟/满帮/货拉拉友商对比）**整合进本项目**，并按**当前技术栈**给出合理安排（可行性分级 / 优先级 / 落点 / 排期）。
> **参照优先级（用户定案）**：G7 第一 → 联云等商用 TMS → 开源 TMS → 顺丰/京东等仅借鉴。
> **开发以各任务卡为准**；本文是**总览与安排**（跨文档引用），不重复写实现细节。
> **硬约束（技术栈锁死）**：JDK 1.8 / 不升级依赖 / **不引新中间件**（MongoDB/HBase/RocketMQ/XXL-JOB 等） / Zuul 1.x / 移动端 uni-app(Vue3)+uview-plus / 管理端 Vue2.6 / **不对接外部厂商 API** / 地图锁定百度 JS API GL（BD-09 零转换）/ 支付测试不接真实微信（mock 兜底）/ 发票不接真实税控。
> **配套**：《对标G7功能差距与补充清单.md》（已并入主文档并归档删除，备份见 `docs/.deleted_20261007/`）＝差距来源；《开源与商业TMS需求调研对标报告.md》（已删除，备份见该目录）§4.4/§4.5 =调研溯源与逐项并入映射。

## 0. 整合原则

1. **G7 优先**：G7 的"三大利润中心 / 每趟盈亏 / 老板看数 / 在途异常 / 费用管控 / 可控运力"为本项目业务对齐主线。
2. **技术栈适配优先于照搬**：同类能力若受技术栈/硬件/外部依赖约束，用现有技术等价实现（见 §2），不引新组件。
3. **可落地**：每项必须有明确落点——现有表/服务扩展、或新 DDL（已给）、或任务卡页面（已含）、或排期归属。
4. **避免重复建设**：已由现有代码覆盖的功能（状态机/Drools 计费/自动调度/POD/轨迹/证照预警等）不再立项。

## 2. 技术栈适配专项（受约束功能的等价实现）

| 外部能力（原方案） | 技术栈约束 | 适配方案（等价实现） |
|---|---|---|
| AI 告警/费用异常识别 | 不引 AI 服务 | 规则+统计阈值：均值±2σ / 上下限 yml 可配，`@Scheduled` 扫描（N-4/OPS-1） |
| 电子围栏（地图围栏 API） | 不引付费地图 API | 现有 `scope` 多边形（pd-base）+ 轨迹点判定，点是否在多边形内（N-3/OPS-1 §3.7） |
| PDA/蓝牙秤/自动分拣硬件 | 硬件投入边界 | 司机/快递员端手机扫码（`uni.scanCode`）+ 拍照上传替代（N-1/L-5） |
| 实时消息推送（WebSocket 长连） | 不引新中间件 | Kafka/RabbitMQ 现有通道 + 轮询 + Spring WebSocket（多端契约已锁） |
| 外部 API（ERP/WMS/税控/微信支付） | 不对接外部厂商 API | 内部闭环 + mock 兜底（支付 FIN、发票 FIN-1.2 均已定案） |
| 北斗/JT-T 808 完整接入 | 需硬件终端 | P0 最小改造（`LocationRecord` coordSystem/source + 车辆在线标记），P1 完整接入（R2-1） |
| 报表/BI 引擎 | 不引 BI 组件 | 固定报表 SQL 聚合 + ECharts 前端渲染（OPS/经营大屏） |
| 承运商门户独立系统（SLMS 级） | 不新增端/工程 | 复用司机端 App 承运商身份视图（L-1） |
