## 二、P0 阻断级技术风险（W1 必须解决）

> 这 4 项不解决，司机提货/送达/管理端构建/客户地址簿加载会直接挂。

### 2.1 Seata 未部署 → 司机提货/交付直接抛异常

**现状**：
- `CargoController.pickUp` / `finish` 标了 `@GlobalTransactional`
- 部署侧 Seata 标"可选"，未实际部署
- 后果：司机点"确认提货"时，Seata Client 找不到 TC Server，事务注解拦截器直接抛 `TransactionException`，**提货/送达功能完全不可用**

**处置（T-02 已记录，W1 必须二选一）**：
- 方案 A：部署 Seata Server（注册到 Nacos）
- 方案 B：Nacos 下发 `seata.enabled=false` + `seata.service.enable-degrade=true`，降级为本地事务（牺牲跨服务一致性，P0 阶段可接受）

**建议**：W1 先选 B（降级），保证业务跑通；P1-9 再补 A。**不要等司机端开发到一半才发现这个坑**。

### 2.2 token 2h 过期 + 验证码登录 → 司机长途必掉线

**现状**：
- Nacos 配 token 有效期 7200s（2h）
- 司机端 401 后要重新登录，登录接口要验证码（`/anno/captcha`）
- 司机在途 4 小时，到送达时 token 已过期，要下车输验证码——**真实会被司机骂死**

**处置**：
- W1 Nacos 把司机端 token 有效期改到 **43200s（12h）**（一行配置）
- 司机端 App `onLaunch` 检查 token 未过期则不跳登录页（已规划，强调）
- 不做 refreshToken（后端没这个字段，D-16 已定案）

### 2.3 node-sass 4.14.1 已废弃 → 管理端在新 Node 上构建失败

**现状**：`pd-admin-ui/package.json` 同时有 `node-sass: ^4.14.1`（2020 年已废弃）和 `sass: ^1.32.13`（dart-sass）。
- node-sass 依赖 libsass，Node 16+ 编译失败
- 用户的 dev 命令加了 `--openssl-legacy-provider`，说明在新 Node 上跑
- 后果：CI/CD（Gitea Actions）上 `npm install` 会卡在 node-sass 编译

**处置**：
- 从 package.json 移除 `node-sass`，保留 `sass`（dart-sass，纯 JS 无编译）
- sass-loader 7.x 兼容 dart-sass，不需要动
- **这不是升级业务依赖，是修复构建前置**，10 分钟活

### 2.4 分页参数名不一致 → 客户地址簿加载不出来

**现状**（任务卡已记录但前端封装要强调）：
- 大部分接口分页参数是 `pagesize`（全小写）
- 客户地址簿 `GET /address/page` 是 `pageSize`（驼峰）
- 前端如果统一封 `pagesize`，地址簿会拿不到数据

**处置**：在 `common/request/index.ts` 封装层做参数归一，或在 `address.ts` service 层单独处理。任务卡已写，开发时注意。

## 六、关键判断

1. **不要加新功能模块**：现有 P0 10 项已经够多，本报告的补丁都是"在已有页面上加按钮/加数字"，不新起页面。
2. **W1 先排掉 4 个阻断风险**：Seata/token/node-sass/分页参数，不然后面前端开发全是坑。
3. **一线体验 > 花哨功能**：司机能在 App 上看到"这趟挣多少"、一键拨号、一键报异常，比任何 AI 大模型都实在。
4. **客户要的是透明**：货到哪了、什么时候到、出问题找谁——三件事做好，客户满意度就上来了。
5. **调度员要的是工作台**：打开系统就知道今天干什么、哪里要处理，而不是看一堆图表。
