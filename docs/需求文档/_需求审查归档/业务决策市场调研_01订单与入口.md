## Q-2 上门取件任务由谁派发（自动派单 / 手动指派 / 抢单）

### ① 行业主流做法

行业并非三选一，而是**按业务场景区分**，主流产品普遍同时提供多种方式、按场景默认其一：

1. **C 端散单 / 众包寄件 → 抢单 + 兜底指派**
   - 菜鸟裹裹（C 端）：用户下单后基于 LBS 实时推送给附近快递员由其**抢单**；当订单无人接应时，再**指派**给离用户最近的配送站点；特殊件（如 20kg 以上大件）指派给对应物流商（德邦等）。（来源：36 氪报道）✅
   - 天天快递 App 内置"裹裹抢单"：附近寄件需求推送，快递员抢单后上门。（来源：央广网）✅

2. **B 端商家寄件 → 物流服务商指派服务人员**
   - 菜鸟裹裹商家寄件：用户下单后，"菜鸟以技术手段为用户匹配物流服务商，并由**物流服务商指派并回传**服务人员上门揽收"。即平台匹配承运商，具体揽件人由承运商（网点）自己安排。（来源：菜鸟官方服务协议）✅

3. **加盟快递网络（中通/圆通等）→ 区域责任制，网点/站长手动安排揽件**
   - 圆通：快件揽收"主要由发件人所属区域的**加盟商**进行，揽件加盟商通过上门揽件、门店收取等方式进行快件揽收"；信息化平台负责路由与全程跟踪，末端派送由"行者系统"提供建议路径并调度管控。（来源：圆通速递 2021/2025/2026 半年报及公告）✅
   - 即：揽件派给谁，是**网点（加盟商）在自己责任区内人工/按片区分给业务员**，不是全网司机抢单。

4. **TMS 调度层（oTMS / G7 易流）→ 自动派单为主 + 手动委派兜底**
   - oTMS：通过电子合同设置实现**自动运单分配**，支持多级分配到下游分包商和司机，可按最低成本、最短时效、自定义字段匹配、路线/地区默认等动态优先规则；同时**也可通过比较报价手动分配**。（来源：oTMS 官网）✅
   - G7 易流 TMS：支持**直接派车、排班派车、智能找车**三种调度方式；商超/便利店/**加盟网点配送**场景每日截单后可"手动/自动将当日送货门店订单与运输线路匹配"，自动生成线路并自动派车。（来源：华为云 G7 易流 TMS 实施文档）✅
   - 厂商侧经验：常规干线/城配/零担订单可实现 90%+ 自动调度，但大额、紧急、特殊设备单仍需人工二次复核。（来源：万信物流 TMS 科普）⚠️

5. **抢单模式的产品设计前提**
   - 抢单 = 把符合条件的单放进资源池由司机自选自抢；要求司机端产品完善、司机愿意用、且公司对司机有较强管控（撤单率/履约评分挂钩），适合**有固定运力、司机管控较完善**的运输公司。（来源：人人都是产品经理《智能调度让物流更高效》）✅
   - 吉客云 TMS：市内配送"由制单员批量将配送单分配到多个车辆"（手动派工），同时提供"司机领单"入口。（来源：云巴巴产品页）⚠️

### ② 中小客户（10-50 辆车）通常怎么定

- 该规模车队**没有专职算法调度条件**，现实中以**调度员/老板手动派单（按线路、区域、熟悉司机指派）为主**，系统把"电话派车"搬到线上（一键派单下发），自动智能派单是锦上添花而非默认。
- 抢单模式在中小自有车队里用得少：司机多为固定合作/挂靠，线路相对固定，抢单更常见于**平台型/众包型**（货拉拉、满帮、菜鸟裹裹 C 端）。
- 行业经验：每天配送点到 10-15 个以上、或同时管理 3-5 个承运商时，纯人工派单才会明显吃力，才值得上自动调度。（来源：通天晓 TMS 文章）⚠️

### ③ 推荐默认值 / 默认做法

- **默认：手动指派（调度员派单）为主，系统内置"按线路/区域/默认司机"的半自动推荐**；
- **预留但不默认开启：司机抢单池**（面向未来扩展众包/临时运力）；
- **自动派单作为可配置的增强项**（截单后按预设规则自动配载派车），默认关闭或仅对标准化线路开启，特殊单保留人工确认。
- 即：手动指派为默认、自动派单为可选项、抢单为扩展项。

## Q-3 加盟/网点在管理系统中的账号模式（平台统一账号 vs 独立网点门户）

### ① 行业主流做法

主流做法是**"同一套系统、一个登录入口，靠多级组织 + 角色权限 + 数据范围做隔离"**，而不是给每个网点独立部署一套门户：

1. **快递加盟网络（极兔/中通）→ 总部统一系统，网内各层级共用，权限区分**
   - 极兔：自主研发 **JMS 系统**，"在线集成管理快件从下单、收取到结算的全生命周期，**为网内各层级操作人员**提供高效的终端管理运营工具"。即一套系统服务总部-网点-末端各层级。（来源：极兔官网）✅
   - 中通：开放平台支持"**商家身份**接入"和"**网点身份**接入"两种；网点身份"只能由网点负责人注册"；网点管理员在内部客户管理系统中录入/管理本网点人员与电子面单账号；存在"多网点账号"机制（加盟网点人员需网点管理员先在神州系统录入）。即：统一认证体系下，网点作为系统内一个**组织节点**，网点负责人管本网点账号与权限。（来源：中通开放平台文档）✅

2. **国内 TMS 多机构/多租户 → 多级组织架构 + 角色权限 + 数据隔离**
   - 临科 TMS：满足"总公司、分公司、子公司、**各地代理**整体管控"，**各级数据隔离、独立开展业务**；权限分用户权限（角色授权）、视图权限（按钮级，总公司→分公司→员工逐级授权）、数据权限（运营数据隔离、关联组织查看）。（来源：云巴巴产品页）✅
   - 物通云 TMS：支持"分公司、分拨中心、**网点**自主添加，快速搭建多级组织架构"，并按**调度/财务/司机/网点经理**做精细化人员权限分配。（来源：物通网资讯）✅
   - 闪道云/金蜘蛛 TMS：预设超级管理员、系统管理员、运营经理、调度员、财务人员、司机等角色，可自定义。（来源：闪道云帮助中心）✅
   - 国外同类（ARK TMS / Alvys / Cadenax）同样是"角色权限 + Team/Office 数据归属"模式：用户既要有权限、又要有对应 team/office 的数据范围。（来源：各产品官方文档）✅

### ② 中小客户（10-50 辆车）通常怎么定

- 中小加盟型物流通常只有"总部 + 少数几个网点/代收点"，**没有预算也没有必要给每个网点独立门户/独立部署**；
- 主流是在一套系统里建"总部—网点"两级组织，网点用同一入口登录，登录后只能看到本网点的数据与单据，总部可看全部；
- 网点侧账号由总部（或网点负责人）在系统内开通，靠角色（网点经理/网点制单/网点司机）区分能做什么。

### ③ 推荐默认值 / 默认做法

- **默认：平台统一账号体系（同一管理端入口）+ 多级组织（总部/网点）+ 角色权限 + 网点级数据隔离**；
- 不做"每网点独立门户/独立登录域名"；网点账号由总部统一开通、按组织节点授权，网点只能看本网点数据；
- 预留"网点管理员"子角色，允许其在本网点内自助加人。

## Q-4 运费结算 / 对账 / 开票是否独立岗位、独立模块

### ① 行业主流做法

1. **中大型 TMS 产品 → 结算是独立模块、有独立"财务/结算"角色**
   - 科箭 TMS 云：内嵌场景化**计费引擎**，"为货主、客户、承运商一键生成同一本账单"，与承运商**在线对账**，运费结算时间节省 90%；并与 SRM Portal、SAP 打通——"承运商在 TMS 对账、在 SRM Portal 打印**开票通知单**、在 SAP 应付凭证付款"。即 TMS 内完成计费/对账，开票与付款落在外部财务系统。（来源：科箭官网/方案 PDF/案例）✅
   - oTMS：提供自动计费、**在线对账**、FAP（Freight Audit and Pay，运费审计与支付）、按产品线/BU 成本分摊；账单一键导出、合同报价自动带出。（来源：oTMS 官网）✅
   - 闪道云/金蜘蛛 TMS：系统预设"**财务人员**（负责费用管理和结算）"作为独立角色，与调度员、司机并列。（来源：闪道云帮助中心）✅
   - 满帮/运满满（平台型）：运费走"满运宝"担保交易——货主预付运费到平台、司机承运完成后平台结算到司机账户；并陆续上线税务/财务/结算/调度等功能模块。（来源：运满满官网/满运宝）✅

2. **大型企业（货主/制造）→ 物流算费 与 财务开票 分离**
   - 宝钢运输电子商务门户：物流部根据实绩+合同费率产生**结算单**→经确认后送**财务服务中心**→财务审核通过后**开票**并回传。即"物流算费、财务开票"是两个环节、两个部门。（来源：宝钢运输门户）✅

3. **中小物流企业的现实 → 一人多岗，财务常 1 人甚至兼岗**
   - 招聘市场实况：中小物流"客服专员"岗位职责已含"客户/供应商账务核对、**开票**、回款跟踪、TMS 处理、临时车运费处理"（盛丰物流）；专线物流招"会计/结算"3 人，且该会计同时负责"日常车辆调度安排"。（来源：智联招聘/蒙阴在线招聘）⚠️
   - 小微企业财务通用配置 1-3 人、一人多岗（出纳管钱不管账），中小物流通常配 1 名会计/出纳，对账与调度、客服交叉。（来源：抖音财务科普 + 上述招聘）⚠️

### ② 中小客户（10-50 辆车）通常怎么定

- 该规模企业**通常没有专职"运费结算专员"岗位**：对账/开票/回款多由 1 名会计（或客服/文员）兼做，老板或老板娘常亲自管钱；
- 因此系统层面**必须有独立的"财务/结算"角色与对账/账单/开票模块**（否则账算不清），但**不要求在客户企业里配齐多个独立财务岗位**——一个"财务"账号即可覆盖。

### ③ 推荐默认值 / 默认做法

- **系统侧：设置独立"财务/结算"角色 + 独立模块**（运单计费、应收应付对账、账单生成、开票/回款登记、成本分摊），与调度/司机/客服角色权限分离；
- **默认角色数**：超管 + 调度 + 财务 + 司机 四件套起步（与金蜘蛛/临科预设一致）；
- **不强求**为中小客户拆"应收会计/应付会计/出纳"多岗，预留扩展即可；开票对接外部财务软件（用友/金蝶），TMS 内做对账与账单，不做完整账务。
