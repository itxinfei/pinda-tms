## 决策① 合单/并单条件 与 拆单运费分摊

### 1. 行业主流做法（含来源佐证）

**（1）合单/并单的触发条件——行业普遍按"同址 + 同方向线路 + 时间窗"三个维度叠加**

| 产品/来源 | 合单条件做法 |
|---|---|
| oTMS（货主端培训文档） | 整合标准为"计划提货日期"；在分配承运商前按车整合订单时打"合并计费标识"，**同一收货地址数字相同才合并计费**；基于四级地址库（县/市/省/大区级）在不同层级做线路整合 |
| oTMS 官方"订单集约"文章 | 同一线路、同一区域的订单在前端整合，以获取更优价格阶梯（如上海→北京两个工厂订单合成一个运单分配） |
| 罗戈网《物流履约全链路数字化解析》 | 合单核心：**装货地址相同或相近**的订单合并为一个车次派发，以降低配送成本、提高装载率 |
| 物通云 TMS | 系统自动识别**同方向、同区域、就近装卸、时效相近**的零散订单智能拼车；同城场景下自动合并**同一区域、同一时间段**订单 |
| 万里牛 TMS | "同址合单策略"：针对**同一收货地址或同城邻近网点**的多笔零散订单自动合单；超长超重跨温区订单自动拆专运单 |
| 跨境电商合单惯例（Easyship / TikTok Shop 官方） | 合单前提：同一收货地址、下单在特定时间窗内（通常 24 小时）、同仓/就近仓可发 |

**归纳**：行业合单条件并非单一维度，而是组合校验——**①同收货地址（最刚性）；②同线路/同方向区域；③同时间窗（同日提货/同城同时间段）；④货物属性相容（不超车型载重体积、非易碎/危险品混装禁忌）**。同计费协议（同线路价格阶梯）是合单后能否省钱的前提，而非合单的触发条件。✅已查证

**（2）拆单的行业做法**
- 唯智 vTradEx TMS：运单拆分分**横向拆分（按数量，适用多次发货/拆分运输）**与**纵向拆分（按段，适用中转/多式联运）**；支持按计划预分拆，也支持按实际装车现场分拆。✅已查证
- oTMS 拆量模块：大经销商订单（如 100 吨）按整车/柜拆分，按车分配、按车追踪；尾数装剩由仓管确认。✅已查证

**（3）合单后运费如何分摊——主流是"按计费货量占比回摊"**
- oTMS（官方文章明确描述）：多个订单整合后适用更低的价格阶梯，但**"并没有把三个订单真正合成一张"，回单仍按原订单；系统通过价格引擎把整合后的成本分摊到这三个订单上**；多工厂场景"把相应运费回摊给各个工厂，不影响原来的核算"。✅已查证
- 零担拼整车行业惯例（八方资源网从业者文章）：按凑成整车载重或体积算总价，**再按各货主的货量占比分摊**，整体比单发零担便宜两到三成。⚠️一方称（从业者经验，未见官方标准）
- 零担计费本身（道旭物流、佳豪鑫物流等多家专线报价页一致）：**重货按重量（元/公斤）计费，泡货按体积（元/方）计费，两者取大值**；体积重换算常见 1 方≈167–333 公斤（÷6000 或 ÷3000）。这意味着分摊的天然分母是"计费重量（重量/体积重取大）"，而非简单件数。✅已查证
- 快递集包（菜鸟华东集运仓 / 淘宝新疆集运）：不同店铺同地址包裹合为一个大包走干线，干线运费大幅下降后按包裹计入各商家账单——合单省干线、分摊回原单。⚠️一方称（官方有集运仓报道，具体分摊比例未公开）

**按件数分摊**在公开资料中未见作为主流做法出现——件数只适合同城派送点位起步价场景，干线合单分摊不按件数。✅已查证（反向：未见主流采用）

### 2. 中小客户（10–50 辆车）通常怎么定
- 区域商贸配送/加盟专线场景下，订单以"同一线路方向、当日装车、收货点邻近"为主，合单主要由调度员在配载台上人工完成（先排线、后并车），系统多为"提供建议+人工确认"。
- 运费分摊多沿用各客户原合同计费协议：合单只是减少车次成本，对客户结算仍**按各票原计费重量/原报价独立计**，合单省下的运费归承运方（或按约定让利），极少在中小专线里做复杂的"整车载价按占比分摊"——那是大货主集团（oTMS 服务的美的/博世级别）的玩法。

### 3. 推荐默认值/默认做法
- **合单触发条件（默认开启，可配）**：同收货地址（最优先自动合）＋ 同方向线路 + 同计划提货日（时间窗默认当日）；合单前校验车型载重/体积上限与货物混装禁忌。
- **拆单**：默认支持横向按数量拆（分批配送），纵向按段拆留给多式联运客户后做。
- **合单运费分摊（默认策略）**：
  - 对客户结算：**各票仍按原计费协议独立计费**（重量/体积重取大值），不把整车价摊给客户；
  - 对内成本核算：整车载价按**各票计费重量占比**回摊到原单，供成本分析；
  - 件数分摊仅作为可选，不做默认。
- 回单、签收状态始终挂回原始订单（学 oTMS：合车不合票）。

## 决策② 派单默认模式（自动派单 / 手动派单 / 抢单）

### 1. 行业主流做法（含来源佐证）
- **TMS 合同物流域：手动派单与自动派单并存，自动派单靠"规则"而非平台算法。**
  - 罗戈网：派单分手动派单（运营商从有合作关系的承运商中选择并推送）与自动派单（TMS 设派单规则，生成任务时系统自动选承运商并推送司机，无需人工选）。✅已查证
  - 科箭 TMS 云：同样定义手动/自动两种，并配"优化引擎"基于运输距离、环节、工具、时间、费用运算输出运单。✅已查证
  - oTMS：通过电子合同实现自动运单分配，支持多级分配到下游分包商和司机；动态规则含**最低成本、最短时效、自定义字段匹配、线路/地区默认承运商**，同时保留手动比价分配。✅已查证
  - 唯智：按线路/线路包设置承运份额分配策略，自动平衡份额、履约合同条款。✅已查证
- **同城即时配送域：系统自动就近派单为主。**
  - 中国经济网 2026-05《生活服务类平台算法负面清单》实施报道：滴滴/T3 出行以距离为首要派单因素，绝大多数订单由最近司机接单；美团外卖派单按规则；**货拉拉不指派订单，全部由司机自主抢单，"就近优先"接单比例达 93%**。✅已查证（权威官方媒体）
- **干线整车域：满帮/运满满为公开货源大厅+司机自主看单/打电话谈价（类抢单）；传统专线干线则是调度电话派车（手动）。**
- 调度模式从业者总结（人人都是产品经理）：调度分抢单与派单两种；抢单要求司机端产品完善且司机愿配合；派单由货与车匹配规则驱动。⚠️一方称

**归纳**：行业没有"全 TMS 统一默认"，而是分场景——**合同物流/专线干线 = 手动派单（调度员指派）为基础，规则自动派单为效率升级；同城即时 = 系统自动派单；货运平台（货拉拉/运满满）= 司机抢单/自主接单**。✅已查证

### 2. 中小客户（10–50 辆车）通常怎么定
- 10–50 辆车的区域车队，司机和线路相对固定，调度员（往往就是老板/老调度）对每条线配哪台车、哪个司机门儿清，**手动派车+电话/微信通知是事实上的默认**；系统在这里的价值是把派单动作线上化（一键派到司机 App、自动同步地址货物运费），而不是算法自动分。
- 自动派单一般在订单量上来、线路标准化之后才逐步开（先按"线路默认司机/默认车辆"做半自动推荐）。
- 抢单在自营固定车队里很少用——固定工资/固定线路司机不需要抢，抢单是开放运力池/外协车才用的。

### 3. 推荐默认值/默认做法
- **默认派单模式 = 手动派单（调度员指派）为默认**，系统辅助：配载台按线路/车型/距离给出"推荐车辆 Top N"，调度一键下发到司机 App。
- 同时提供可配置的**自动派单规则开关**（按线路绑定默认车辆/默认司机、按就近原则），默认关闭或仅对标准化线路开启。
- 抢单模式不在默认派单路径内，作为外协/加盟运力池的能力（见决策③）。

## 决策③ 司机端"抢单大厅/抢单列表"是否为标配

### 1. 行业主流做法（含来源佐证）
**在开放货运平台/城配/即时配送里——抢单大厅是标配；在合同物流自营车队 TMS 里——司机端标配的是"任务接单/执行"，抢单大厅不是标配。**

| 产品 | 司机端抢单情况 |
|---|---|
| 货拉拉司机端（App Store 官方） | "海量订单固定活自由抢"，线上单自由抢——抢单即核心模式 ✅已查证 |
| 运满满司机端 | 公开货源大厅，司机按出发/到达城市、车型、载重、时间筛选货源后一键抢单/电话对接 ✅已查证（应用商店介绍+从业者视频） |
| 顺丰同城骑士 | **系统推单 + 自己抢单结合**：在线会派单，"新任务"里展示可抢单列表，距离近的更好抢 ✅已查证 |
| 科箭 TMS 云司机端 | 司机可执行运单，也可在**订单市场做运力发布和自由竞价抢单** ✅已查证（应用汇介绍） |
| 联信 TMS（网络货运平台）司机端 | 功能含发布行程、**扫码抢单**、运费提现 ✅已查证（招聘 JD） |
| 飞扬 TMS | 司机端支持系统派单、**热点抢单模式** ✅已查证 |
| 高德 TMS 解决方案 | 明确"具备**抢单、派单、竞价、招标**多种接单模式，可按业务形式设置" ✅已查证 |
| 物牛帮 TMS 司机端 | 功能为仓配任务/长途任务/**任务接单**/确认装货/签收/回单——无抢单大厅描述 ✅已查证（自营车队型 TMS 典型） |

**归纳**：抢单大厅是"开放运力平台（货拉拉/运满满）+ 即时配送（顺丰同城）+ 网络货运/竞价运力池"的标配；而**固定车队的合同物流 TMS，司机端主流功能是"接收派单 → 接单确认 → 到厂装货确认 → 在途 → 签收回单"**，抢单大厅并非必需模块。✅已查证

### 2. 中小客户（10–50 辆车）通常怎么定
- 纯自营车队（车=公司自有/固定挂靠司机）：调度统一排线派车，司机等任务即可，抢单大厅用不上，反而会打乱排线——司机端先做"派单接收+执行闭环"就够。
- 加盟/外协占比高的区域物流：存在松散运力池（临时调车、返程车、加盟司机），这时抢单大厅（或订单竞价）能帮调度快速补车，有实际价值。
- 品达 TMS 定位是"自营+加盟"，建议抢单能力**做成面向加盟/外协运力的可选模块**，而非全体司机默认页。

### 3. 推荐默认值/默认做法
- **司机端一期标配：派单接收页（待执行任务列表）+ 接单确认 + 装货/在途/签收状态回传 + 回单上传。**
- **抢单大厅：作为加盟/外协运力场景的二期可选模块**，默认不对自营司机开放；开放时按"就近优先+信用评分"排序（学货拉拉就近 93% 的逻辑），并配抢单后取消率/履约率考核（从业者经验：对高撤单率司机降权）。
- 若目标客户中"开放社会运力/返程车撮合"占比高，则提前到一期。

## 附：三项决策一句话结论速览
1. **合单/拆单**：行业按"同址+同线路+同时间窗"合车、回单仍挂原票；运费对内按计费重量（重货重量/泡货体积取大）占比回摊、对客户按原协议独立结算——✅合单条件与分摊逻辑已查证，中小落地形态⚠️。
2. **派单默认模式**：合同物流/专线默认调度员手动派单（系统给推荐），自动派单按线路规则后置开启，抢单属开放运力场景——✅手动/自动定义与平台派单规则已查证，中小默认值⚠️。
3. **抢单页标配度**：开放货运平台/即时配送标配抢单大厅，自营车队 TMS 标配的是任务执行页而非抢单大厅；品达建议一期做派单接收+执行闭环，抢单大厅作为加盟/外协运力可选模块二期上——✅各产品形态已查证，是否提前到一期⚠️。
