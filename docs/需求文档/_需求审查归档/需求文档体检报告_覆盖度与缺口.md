## 二、核心缺口：代码有、文档零覆盖（5 块）

> 已逐条 grep 验证（SRS 命中数=0），并核实对应代码真实存在。

###缺口1：`pd-user` 整模块（会员/地址簿/缓存）— SRS 零覆盖
- **代码事实**：`pd-user` 有 3 个 Controller
  - `AddressBookController`（地址簿）
  - `MemberController`（会员）
  - `J2cacheController`（缓存 set/get/evict/keys/regions/clear）
- **SRS 现状**：`pd-user`、"会员"、"个人中心"、"消息中心" 全部 0 命中
- **影响**：地址簿是客户下单前置（§5.1 有端点但§6 无功能条目）；J2cache 15 个端点无任何条目
- **建议**：新增 `USR 用户与地址簿域`（SYS-07 会员/个人中心、BASE-08 地址簿、MON-01 缓存运维）

### 缺口 2：支付与退款（SRS 仅 ORD-01 一句带过）
- **代码事实**：`pd-oms/.../PayController.java` 有 4 个方法 `create/callback/query/refund`，三通道 `alipay/wechat/mock`；`PayChannel` 三实现
- **SRS 现状**："支付"仅 5 次、"退款" 3 次，**无独立条目、无支付域**；退款能力**完全没有能力条目**
- **影响**：支付/退款是资金链路，验收无标准
- **建议**：新增 `PAY 支付与退款域`（PAY-01 下单支付、PAY-02 回调、PAY-03 退款、PAY-04 三通道适配）

### 缺口 3：报表/成本/趟次油耗（SRS 零覆盖，但任务卡已立项）
- **SRS 现状**："报表"、"趟次"、"油耗" 全部 **0 命中**
- **但任务卡已有**：`20-运营可视化与成本管控任务卡` 的 **OPS-4 趟次成本与油耗**；`21-财务结算…任务卡` 的 **FIN-3 账期回款坏账 / FIN-4 每趟利润**
- **影响**：**任务卡有、SRS 无** → 违反"需求层是唯一真源"，排期与验收无需求依据
- **建议**：新增 `RPT 报表与成本域`（RPT-01 趟次成本、02 油耗、03 每趟利润、04 账期回款、05 坏账）

### 缺口 4：监控运维域（Druid + 心跳 + Swagger 聚合）
- **代码事实**：`pd-druid/DruidController` 3 端点（全部车辆末位置/单车轨迹/参数批量）；`TruckController` 有 `/heartbeat`、`/heartbeat/mark-offline`、`/count`；`DriverController#/count`
- **SRS 现状**：`pd-druid` 0 命中；"心跳"仅 1 次
- **建议**：新增 `MON 监控运维域`（MON-01 Druid 时序监控、02 车辆心跳在线状态、03 网关 Swagger 聚合）

### 缺口 5：BASE-06 判定方向错误（需改，不是补）
- **原写法**：SRS BASE-06 写"数据字典 pd-base 零实现，须新建字典服务"
- **代码事实**：网关 `GeneratorController` **已提供** `dictionary/enums` 与 `/enums` 端点；`pd-auth-server` 的 `AuthorityGeneralController#/enums` 也提供枚举
- **结论**：枚举真源**已在网关/鉴权侧存在**，不是"零实现"。BASE-06 应改为"**对接现有 enums 端点**"，而非"新建字典服务"
- **影响**：方向性错误会让后续开发重复造轮子
