# 友商产品定位对比 & 本项目优化完善清单

> 目的：回答两件事——① 顺丰青龙 / 京东物流 / 菜鸟 / 满帮 / G7 / 货拉拉 **和品达有什么区别**；② 据此**品达该优化完善哪些功能**。
> 原则：只学"同定位、能落地、有业务价值"的部分；**不模仿巨头体量带来的能力，不做花架子**。

---

## 0. 先厘清身份：品达到底是哪种系统？（一切对比的前提）

国际上 TMS 分两类，名字一样、东西完全相反：

- **Shipper TMS（货主 TMS）**：有货要运，用来**采购**承运商服务、比价、审计运费账单。
- **Carrier TMS（承运商 TMS）**：**自己有车有人**，用来规划路线、派车派司机、管理资质合规、采集 POD、核算成本。

还有两类常被误当成 TMS：

- **Freight Aggregator（车货撮合平台）**：中间市场，一边收货源一边收运力，做匹配。**是生意本身，不是管理系统**。
- **Carrier-Connectivity Platform（承运商对接平台）**：对接多家快递公司的电子面单/轨迹，解决"一家商家对十家承运商"。

### 品达的定位

> **Carrier TMS —— 承运商（自营/加盟）运输管理系统**。
> 管自己的订单、网点、车辆、司机、线路，跑通「下单 → 调度 → 干线运输 → 末端派送 → 签收 → 结算」闭环。
> 用户已明确：**自营/加盟，不对接任何外部厂商/三方物流 API**。

**这个定位决定了：**
- ✅ 该学：**G7 易流**（同为"货运经营者管车/管人/管财"）、顺丰/京东的**自营履约质量**（时效预警、路由动态调整、可视化）。
- ❌ 不该学：满帮/货拉拉的**撮合平台模式**、菜鸟的**行业数据平台模式**、京东的**仓配一体化重投入**、顺丰的**跨境/国际网络**。

## 1. 六家逐一定位对比

| 产品 | 本质定位 | 谁在用 | 核心能力 | 与品达相似度 | 结论 |
|---|---|---|---|---|---|
| **顺丰（青龙/丰智云）** | 自营快递·快运·冷运·同城·国际的**全链路履约系统** | 顺丰自己（四网融通：大网/快运/丰网/仓网） | 时效分层产品体系、智能路由、**运力与中转场地融通**、**时效预警**、**路由动态调整**、削峰平谷资源预测 | **中** | 同为自营履约。业务形态不同（顺丰海量小件快递 vs 品达运输管理），但**"时效预警 + 路由动态调整 + 资源融通 + 可视化"值得学** |
| **京东物流（青龙/与图/超脑）** | **仓配一体化供应链**服务商 | 京东自营 + 外部客户 | 仓储+运输+配送一体、数智地图 SaaS「与图」（日处理千万包裹/数万运力）、大模型+数字孪生「超脑」全局优化 | **中低** | 品达**无仓储**，仓配一体是重投入，不做。可学**数智地图 / ETA / 决策仿真**的思路 |
| **菜鸟** | **不是物流公司**，是**数据协同平台**，自称快递行业"水电煤" | 通达系快递公司、商家、消费者 | **电子面单**（统一标准串联商家/快递/消费者/干支线数据）、路由分单、物流预警雷达、菜鸟驿站、裹裹 | **低** | 品达自营、不做行业平台整合。可学**电子面单式的数据口径统一**与**预警雷达**（大数据预测+预警） |
| **满帮（运满满+货车帮）** | 干线整车**车货撮合平台**（Aggregator） | 货主 + 社会卡车司机（350万活跃司机） | 货源池/运力池、AI 匹配（找货 2–3 天 → 分钟级）、统一电子运单 + 线上支付、**双向信用评分**、全国通用履约准则、纠纷调解（一次性解决率 96.5%） | **低** | 品达自营不撮合。可学**统一电子运单 + 线上支付交易标准 + 双向信用 + 履约准则（权责界定）** |
| **G7 易流** | 公路货运**物联网 SaaS**，给货运经营者用 | 3.5 万+ 货运经营者（有车/管车的中小企业） | **IoT**：位置轨迹、驾驶安全(ADAS/DSM)、冷链温控、货物流向、重量+视频防盗；**财运通**：订单/车辆/运力三大利润中心打通、**在途成本精细到每趟**、水印相机在途报销、油耗在线审批、能源结算、**每趟盈亏实时可见**、"老板看数" | **高（最该对标）** | 同为"货运经营者管车/管人/管财"。**这是品达最直接的参照系** |
| **货拉拉** | 同城货运**即时撮合** | C 端/小 B + 司机 | 车型全覆盖、会员制、五大引擎（分单/供需/营销/定价/大数据地图）、百万级订单实时匹配（精准匹配率 92%） | **低** | 品达不做同城即时撮合。可学**定价引擎 / 供需预测**概念 |

### 一句话总结区别

> 顺丰/京东 = **自己送快递/做供应链的巨头基础设施**；
> 菜鸟 = **给快递行业定标准、做数据协同的平台**；
> 满帮/货拉拉 = **撮合车和货的交易市场**；
> G7 = **卖工具给货运经营者，帮他管车管人管财**；
> **品达 = 一家物流公司自己的 Carrier TMS（自营/加盟运输管理）**。
>
> 所以：**品达不是要做"下一个满帮/菜鸟"，而是要把"自己公司的运输业务"管得比现在更细、更透明、更能算清账。**

## 3. 优化完善清单（按梯队，实用优先）

> 遵守硬约束：JDK 1.8 锁死、不升级技术栈、不引入新中间件、不对接外部厂商 API、实用不花架子。

### 第一梯队 P0 —— 先把闭环跑通（最大缺口）

| # | 功能 | 对标 | 说明/现状 |
|---|---|---|---|
| 1 | **三端移动前端**（客户/快递员/司机） | 各家全端 | 品达只有后端 API，无任何移动端界面——**当前最大缺口**（任务卡已就绪） |
| 2 | **POD 电子签收**（含部分签收/拒签） | G7/顺丰 | 现在只有状态位，无签名/拍照/水印凭证 |
| 3 | **多端数据打通**（统一状态机 + 轨迹凭订单号查） | 各家 | 见《多端数据打通与统一领域模型》，含 2 个真实断点修复 |
| 4 | **统一登录**（❗修正：账号登录**已存在** `POST /anno/login`，缺的是移动端免密入口） | 各家 | P0-0 改为"对接+适配"，复用 `AuthManager`/JWT，不引依赖（见核查报告 §一.1） |
| 5 | **支付闭环**（到付 P0 / 在线支付 P1） | 满帮线上支付 | 现状只有 paymentMethod/paymentStatus 字段，无闭环 |

### 第二梯队 P0/P1 —— 补"运营过程管理"（对标 G7 财运通核心）

这部分是品达**最该补、性价比最高**的能力，且大多不需要新中间件：

| # | 功能 | 对标来源 | 解决什么实际问题 |
|---|---|---|---|
| 6 | **在途可视化 + 时效预警/异常告警** | 顺丰"及时预警、路由动态调整"；G7"在途实时可视+异常自动告警" | 现在调度黑盒、超时无人知 → 降客诉、降延误。可复用 Quartz 定时任务 + 现有轨迹数据，**零新中间件** |
| 7 | **ETA 预计送达** | 京东「与图」/顺丰时效 | 现状无 ETA → 客户不知道何时到 |
| 8 | **车辆看板（利用率/调度/效率）** | G7 车辆 Dashboard | 现状 pd-base 有档案但**未与运输任务联动展示** |
| 9 | **每趟成本 / 在途费用 / 油耗** | G7"在途成本精细到每趟""每发生一笔业务利润当时就能看到" | 品达**成本侧完全空白** → 不算账就不知道哪条线赚钱 |
| 10 | **司机趟次绩效 + 驾驶行为** | G7 ADAS/DSM | 复用已规划的**北斗定位 + 司机视频**需求（手机/北斗终端替代专业硬件，不引新中间件） |

### 第三梯队 P1 —— 补"财务结算"（TMS 闭环终点）

| # | 功能 | 对标 | 说明 |
|---|---|---|---|
| 11 | 运费结算 / 多维对账 | G7 财运通、满帮结算 | 现在完全无结算域 |
| 12 | 司机工资 / 趟次结算 | G7 | 趟次是司机结算天然单位 |
| 13 | 账期 / 回款 / 坏账预警 | 通用 TMS | 已在 §10.4 |
| 14 | **每趟/每单利润可见**（"老板看数"） | G7 核心卖点 | 把成本+收入打通，管理层一眼看盈亏 |

## 4. 明确"不做"（避免误学巨头，这块很重要）

| 不做的方向 | 为什么不做 |
|---|---|
| **车货撮合 / 货源池 / 竞价 / 百万司机生态**（满帮、货拉拉模式） | 品达是**自营/加盟**运输管理，自己有货有车有司机，**不需要做交易市场**。做撮合 = 完全不同的生意 |
| **行业数据平台 / 给第三方输出电子面单标准**（菜鸟模式） | 菜鸟的定位是"行业水电煤"，需要接入通达系几十家快递公司；品达自营，无此生态位 |
| **仓配一体化重投入 WMS**（京东模式） | 品达无仓储（"入库/出库"只是订单状态节点）。除非真有中转仓/分拨，否则只做轻量 |
| **跨境 / 清关 / 国际网络**（顺丰国际） | 业务不涉及 |
| **自动驾驶 / 无人配送 / 数字孪生**（各家前沿） | 花架子，与当前业务阶段不匹配 |

## 5. 落地建议顺序

```
第 1 步（P0 闭环）
  三端移动前端 → 统一登录 → POD 签收 → 多端数据打通 → 支付闭环

第 2 步（P0/P1 运营可视）★ 最高性价比
  在途可视 + 时效告警 → ETA → 车辆/司机看板 → 趟次成本与油耗

第 3 步（P1 财务）
  运费结算 → 司机趟次工资 → 对账 → 每趟利润（"老板看数"）

第 4 步（P1/P2 调度运力）
  多约束 VRP → 外协运力池 → 抢派双模

第 5 步（P2 按需）
  IoT 增值（冷链/货损/能源）
```

> **核心判断**：品达最该补的不是"更炫的算法"，而是**三端没有界面**（最大缺口）、**数据不通**（本轮已出契约）、**成本与结算空白**（不算账）、**在途没有告警**（黑盒）。把这几块补上，就是一家能真正跑起来的运输管理系统。
