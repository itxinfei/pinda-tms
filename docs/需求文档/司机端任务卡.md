## 0. 总纲与红线（不可逾越）

本任务卡只做**司机端 App 前端 + 一个缺失的登录后端接口 + 复用既有轨迹上报/查询接口**，不得：
- 升级/改动任何后端依赖、JDK、技术栈（红线 §1.x）；
- 引入任何新中间件、新 UI 库、第二套组件体系（红线 §12.x / UI §7）；
- 新建平行后端服务或重写既有 `pd-web-driver` 接口（§5 已盘点，必须复用）；
- 页面随意写 `<div>`+`<style>`、硬编码色值、自创间距（UI §7 禁止清单）。

**司机端以 App 形态交付**（非小程序）：后台持续 GPS/北斗定位、视频推流只有 App 原生能力能胜任（小程序切后台 30s 即停）。

**所有页面必须套用 `UI设计规范与页面模板.md` 的对应模板**；司机端强调「单手大按钮 + 强对比 + 阳光下可读」（角色化 UI §5）。

> **北斗（BDS）与司机视频**属 spec §6.9 的 P1 新增需求：
> - 定位上报复用 `POST /netty/push`，前端上报原始经纬度 + `source` 标识（北斗/GPS）；坐标系字段 `coordSystem` 的后端落库增强见 spec BDS-01/02（后端改动，不在本卡前端范围，但前端需预留 `source` 参数）。
> - 司机视频（VID-01/02）后端实时音视频基础设施当前不存在，本卡仅做**前端推流入口 + 管理端查看的对接约定**，真实可用需后端按 GB/T 28181 / JT/T 1078 或云厂商 RTC SDK 补齐，标记为「后端待建」。

## 3. 复用 + 新增公共能力

### 复用（来自客户小程序任务卡 P0-1~5）
- `common/request/index.ts`、`stores/user.ts`、`common/utils/coord.ts`、`common/api/*`、`u-navbar/u-tabbar/三态组件` 全部复用，不重复实现。

### D-P0-1 · 后台定位服务 `common/utils/location.ts`（司机端核心）
- 调用 `uni.getLocation({type:'gcj02', isHighAccuracy:true})` 获取位置；App 端用 `plus.geolocation` 实现**切后台持续定位**（需 `manifest.json` 配 `Geolocation` 模块 + Android 前台服务权限）。
- 定时（默认 **10s**）调用 `common/api/trace.ts` 的 `pushLocation({lng, lat, orderId, source})` → `POST /netty/push`。
- `source` 取值：`'bds'`（北斗双模）/ `'gps'`（GPS）/ `'network'`（仅兜底，privacy 策略禁用纯网络定位，见 spec BDS-02）。
- 无网时写入本地队列（`uni.setStorageSync` 离线缓冲），恢复网络后补传（离线优先，spec DRV-02）。
- **红线**：禁止纯网络定位作为主源；禁止在页面里裸调 `uni.getLocation`，一律走此服务。

### D-P0-2 · 视频推流封装 `common/utils/video.ts`（P1，依赖后端）
- 封装云厂商 RTC（TRTC/声网/阿里 RTC，按 spec VID-01 选型）或国标 28181 推流 SDK 的初始化/开始/停止。
- 以 `driverId` 作为房间/通道标识，供管理端按 `businessId` 实时查看。
- 后端未就绪时，本文件仅导出接口占位 + 明确 `TODO(后端待建: VID-01)`，不得自行引入 RTC npm 包以外的依赖。

### D-P0-3 · API service `common/api/driver.ts` / `attachment.ts`
- 每个方法对应 §6 契约表端点，入参/出参据 DTO 标注；页面只调 service。

## 4. 页面任务卡（逐张执行）

> 每张卡字段：ID / 模板 / 路由 / 调用接口 / 字段映射 / 交互 / 验收 DoD / 红线提醒

### D-1 · 登录页 `pages/driver/login/index.vue`
- **模板**：自定义（大按钮）；若支持微信授权登录，调 `wx.login` 取 code；也可用「手机号 + 短信验证码」。
- **路由**：`pages/driver/login/index`
- **调用**：P0-0 新增 `POST /driver/login`（入参 `{code}` 或 `{phone, smsCode}` → 出参 `{token, driverId}`）
- **交互**：获取 code/验证码 → 调登录 → 存 token → 跳 home；已登录直接进。
- **DoD**：冷启动无 token 自动登录；断网给错误态重试；不出现明文密码框。
- **红线**：token 仅存 `uni.getStorageSync` + Pinia；不落日志；不引新鉴权依赖。

### D-2 · 首页 `pages/driver/home/index.vue`（tabBar）
- **模板**：任务大厅类（大入口卡片 + 状态色 + 计数）
- **路由**：`pages/driver/home/index`
- **调用**：`GET /business/cargo/wait?page=1&pagesize=1`（取待提货计数）、`GET /business/cargo/onTheWay`（在途计数）、`GET /user/profile`

- **DoD**：计数正确；定位开关可启停并触发上报；无硬编码色值；状态用 UI §2 状态色。
- **红线**：首页保持极简，不堆无关功能；定位开关必须显式可控（隐私合规）。

### D-3 · 待提货列表 `pages/driver/task/wait.vue`（任务大厅，tabBar）
- **模板**：**列表页（任务大厅变体，UI §4.5）**——卡片大按钮、突出起止网点/时间/距离
- **路由**：`pages/driver/task/wait`
- **调用**：`GET /business/cargo/wait?page&pagesize`（返回 `PageResponse<DriverJobDTO>`）
- **字段映射（DriverJobDTO）**：`id` / `startAgencyId`(起运网点) / `endAgencyId`(目的网点) / `status`(司机作业状态) / `taskTransportId`(运输任务id) / `planDepartureTime`(计划发车) / `actualDepartureTime` / `planArrivalTime`
- **交互**：下拉刷新、上拉分页；点击进 D-5 详情；「一键导航」用 `plus` 或地图 scheme 唤起。
- **DoD**：列表来自接口；分页正常；状态色映射（待处理=橙/进行中=蓝/完成=绿/异常=红）；空态三态组件。
- **红线**：分页走接口；网点名需后端已关联（`startAgencyId` 解析为名称，前端仅展示，不自行查库）。

### D-4 · 在途任务 `pages/driver/task/onTheWay.vue`

### D-5 · 运输任务详情 `pages/driver/task/detail.vue`
- **模板**：**详情页（含时间轴，UI §4.2）**

## 5. 后端新增任务卡（P0-0，唯一允许的后端改动）

### P0-0 · 司机端登录（❗ 2026-10-05 修正：**鉴权体系已存在，不是从零新建**）

> **修正说明**：实测 `pd-auth-server` 已有 `POST /anno/login`（`AuthManager` + `ValidateCodeService` + JWT，配置 `authentication.user.header-name: token`）。
> 因此 P0-0 的真实范围是「**移动端适配**」而非「新建登录服务」。

- **首选方案（零新建，推荐）**：App 直接调 `POST /anno/login`（入参 `{account, password, key, code}`），验证码用 `GET /anno/captcha?key={uuid}` 取图。司机账号由管理端在权限系统预置。
- **备选方案（仅当业务确需免验证码）**：在 `pd-auth-server` 的 `LoginController` **同目录内**新增 `POST /anno/loginMobile`（入参 `{account, password}` 或 `{phone, smsCode}`），**复用 `AuthManager.login()`**，只跳过验证码校验，**不得另起 JWT 签发逻辑**。
- **位置**：绝不新建模块；新接口只加在 `pd-auth-server`（权限服务）或 `pd-web/pd-web-driver`。
- **实现约束（严格遵守红线）**：
  1. 短信/微信能力用现有 `EntCoordSyncJob.loadJSON` 同款 `HttpURLConnection` + 超时，**不引新依赖**。
  2. JWT 签发**复用 `AuthManager` / `JwtTokenServerUtils`**，禁止自造签名；token 有效期沿用配置 7200s。
  3. 移动端请求头固定 `token: <token>`；网关解析后向下游注入 `userid`，业务侧用 `RequestContext.getUserId()` 取。
- **DoD**：App 能登录拿 token；`GET /user/profile` 带 `token` 头返回正确资料；`mvn -o -q compile`（JDK1.8）通过。
- **红线**：不得引入 Spring Security/OAuth 新依赖；不改 JDK/依赖版本；不引新 ORM；**不得实现 refreshToken**（后端 `Token{token,expire}` 无该字段），401 即清 token 重登。
- **北斗/视频后端**：BDS-01/02（LocationRecord 加 `coordSystem`+`source`）、VID-01/02（实时音视频后端）属 spec §6.9 P1，不在本卡 P0-0 范围，按阶段计划另行排期，前端已预留 `source` 与推流入口。
