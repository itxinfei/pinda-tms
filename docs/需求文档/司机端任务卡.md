## 0. 总纲与红线（不可逾越）

本任务卡只做**司机端 App 前端 + 复用既有轨迹上报/查询接口**。
> ❗登录接口**已存在**（`pd-auth-server` `POST /anno/login` + `GET /anno/captcha`），**严禁新建登录服务**。
> ❗**禁止把登录口加在 `pd-web-driver` 上**：该模块 `ConfigurationSupport` 对 `/**` 全量注册 `TokenAuthInterceptor` 且**无 exclude 配置**，登录请求无 `userid` 头 → **必然 401**。移动端免密入口须加在 `pd-auth-server`（`/anno/*` 已在网关放行）。
- 升级/改动任何后端依赖、JDK、技术栈（红线 §1.x）；
- 引入任何新中间件、新 UI 库、第二套组件体系（红线 §12.x / UI §7）；
- 新建平行后端服务或重写既有 `pd-web-driver` 接口（§5 已盘点，必须复用）；
- 页面随意写 `<div>`+`<style>`、硬编码色值、自创间距（UI §7 禁止清单）。

**司机端以 App 形态交付**（非小程序）：后台持续 GPS/北斗定位、视频推流只有 App 原生能力能胜任（小程序切后台 30s 即停）。

**所有页面必须套用 `UI设计规范与页面模板.md` 的对应模板**；司机端强调「单手大按钮 + 强对比 + 阳光下可读」（角色化 UI §5）。

> **北斗（BDS）与司机视频**属 spec §6.9 的 P1 新增需求：
> - 定位上报复用 `POST /netty/push`，前端上报原始经纬度 + `source` 标识（北斗/GPS）+ `coordSystem` 原始坐标系；这两个字段后端**已落库**（2026-10-07，见 `LocationEntity`/`LocationRecord`，BDS-01/02），消费侧统一转换为 BD-09 存储。
> - 司机视频（VID-01/02）后端实时音视频基础设施当前不存在，本卡仅做**前端推流入口 + 管理端查看的对接约定**，真实可用需后端按 GB/T 28181 / JT/T 1078 或云厂商 RTC SDK 补齐，标记为「后端待建」。

### D-P0-1 · 后台定位服务 `common/utils/location.ts`（司机端核心）
- 调用 `uni.getLocation({type:'gcj02', isHighAccuracy:true})` 获取位置；App 端用 `plus.geolocation` 实现**切后台持续定位**（需 `manifest.json` 配 `Geolocation` 模块 + Android 前台服务权限）。
- 定时（默认 **10s**）调用 `common/api/trace.ts` 的 `pushLocation(...)` → `POST /netty/push`。
- ❗**入参按 `LocationEntity` 字段填写**（多传字段会被静默丢弃，Jackson 配了 `FAIL_ON_UNKNOWN_PROPERTIES=false`）：
  `{businessId, name, phone, licensePlate, type, lng, lat, currentTime, team, transportTaskId, coordSystem, source}`
  - **没有 `orderId`**（用 `businessId`/`transportTaskId`）。
  - `source`（`'bds'`北斗 / `'gps'`）与 `coordSystem`（`WGS84` / `GCJ02` / `BD09` / `CGCS2000`）**已于 2026-10-07 落库**；前端如实上报设备来源与原始坐标系，后端消费时统一转 BD-09。
- 无网时写入本地队列（`uni.setStorageSync` 离线缓冲），恢复网络后补传（离线优先，spec DRV-02）。
- **红线**：禁止纯网络定位作为主源；禁止在页面里裸调 `uni.getLocation`，一律走此服务。
- **合规约束（R6-2 · P0 上线前闸口 · 依据《合规开发优先级清单》#5 /《物流行业合规与监管要求》R6/R7/R8）**：后台定位服务启动前**必须获得用户单独授权**（位置信息属敏感个人信息）；`manifest.json` 配 `Geolocation` 权限的同时，UI 须在首次启动显式请求定位授权并说明用途，**禁止静默采集**。授权状态与《数据分类分级目录》(R6-1) 对齐；仅在"开始定位上报"开关显式开启后采集（呼应 D-2 首页隐私合规红线）。

## 4. 页面任务卡（逐张执行）

> 每张卡字段：ID / 模板 / 路由 / 调用接口 / 字段映射 / 交互 / 验收 DoD / 红线提醒

#### 真实发车 / 交付状态机链路（2026-10-07 源码核实，前端一律按此对接）

| App 动作 | 端点 | DriverJob | TransportTask | TransportOrder | Order |
|---|---|---|---|---|---|
| 提货 | `PUT /business/cargo/pickUp` | PENDING→PROCESSING | →PROCESSING(2) | →LOADED | →**23005 运输中** |
| 交付（终点网点） | `PUT /business/cargo/finish` | →COMPLETED | →COMPLETED(4) | →ARRIVED_END(4) | →**23006 网点出库**，并创建 / 复用 DISPATCH 派件任务 |
| 交付（中转网点） | `PUT /business/cargo/finish` | →COMPLETED | →COMPLETED | →ARRIVED | 保持 **23005 运输中** |

- 两个端点均标注 `@GlobalTransactional`：作业单 / 运输任务 / 运单 / 订单跨服务一致更新，任一 Feign 写失败即整体回滚。⚠️ 依赖 **Seata**；未部署时须由 Nacos 下发 `seata.enabled=false` 降级，否则提货 / 交付会抛异常。
- 提货含**断点续提**：上次提货在运输任务推进前失败、作业单残留 PROCESSING 时，允许对同一单重试（见 pickUp 内在途判断）。
- 交付含 **COMPLETED 幂等**：作业单已完成时 App 重试直接返回成功，不重复创建派件任务。
- ⚠️ `pd-work` `TaskTransportServiceImpl.depart/arrive/deliver` 三个方法**全仓无任何 Java 调用方**，是与 App 链路平行的保留方法，**不是**司机端真实发车 / 交付入口；不得据其判定"客户看不到运输中"。真实回写 23005 / 23006 的是 `CargoController.pickUp/finish`。
- 订单进入 **23009 签收**后自动生成应收结算单，发生在 pd-oms（由快递员签收 / 交付事件触发），**不在**司机 finish 环节。

## 5. 后端新增任务卡（P0-0，唯一允许的后端改动）

### P0-0 · 司机端登录（❗ 2026-10-05 修正：**鉴权体系已存在，不是从零新建**）

> **修正说明**：实测 `pd-auth-server` 已有 `POST /anno/login`（`AuthManager` + `ValidateCodeService` + JWT，配置 `authentication.user.header-name: token`）。
> 因此 P0-0 的真实范围是「**移动端适配**」而非「新建登录服务」。

- **首选方案（零新建，推荐）**：App 直接调 `POST /anno/login`（入参 `{account, password, key, code}`），验证码用 `GET /anno/captcha?key={uuid}` 取图。司机账号由管理端在权限系统预置。
- **备选方案（仅当业务确需免验证码）**：在 `pd-auth-server` 的 `LoginController` **同目录内**新增 `POST /anno/loginMobile`（入参 `{account, password}` 或 `{phone, smsCode}`），**复用 `AuthManager.login()`**，只跳过验证码校验，**不得另起 JWT 签发逻辑**。
- **位置**：绝不新建模块；新接口只加在 `pd-auth-server`（权限服务）或 `pd-web/pd-web-driver`。
- **实现约束（严格遵守红线）**：
  1. 短信/微信能力用现有 `EntCoordSyncJob.loadJSON` 同款 `HttpURLConnection` + 超时，**不引新依赖**。
  2. JWT 签发**复用 `AuthManager` / `JwtTokenServerUtils`**，禁止自造签名；token 有效期沿用配置 7200s。
  3. 移动端请求头固定 `token: <token>`；网关解析后向下游注入 `userid`，业务侧用 `RequestContext.getUserId()` 取。
- **DoD**：App 能登录拿 token；`GET /user/profile` 带 `token` 头返回正确资料；`mvn -o -q compile`（JDK 21 LTS）通过。
- **红线**：不得引入 Spring Security/OAuth 新依赖；不改 JDK/依赖版本；不引新 ORM；**不得实现 refreshToken**（后端 `Token{token,expire}` 无该字段），401 即清 token 重登。
- **北斗/视频后端**：属 spec §6.9 P1，不在本卡 P0-0 范围。**BDS-01（`LocationRecord` 加 `coordSystem`+`source`）已落地（✅ 2026-10-07 P0-4，含 `CoordTransform` 转换工具）；BDS-02（JT/T 808 车载终端接入）与 VID-01/02（实时音视频）仍待建**，按阶段计划另行排期，前端已预留 `source` 与推流入口。
