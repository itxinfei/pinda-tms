## 0. 总纲与红线（不可逾越）

本任务卡只允许做**客户小程序（C 端）前端**（登录接口**已存在** `POST /anno/login`，**严禁新建登录服务**，仅做移动端适配），不得：
- 升级/改动任何后端依赖、JDK、技术栈（红线 §1.x）；
- 引入任何新中间件、新 UI 库、第二套组件体系（红线 §12.x / UI §7）；
- 新建平行后端服务或重写既有 `pd-web-customer` 接口（§5 已盘点，必须复用）；
- 页面随意写 `<div>`+`<style>`、硬编码色值、自创间距（UI §7 禁止清单）。

**所有页面必须套用 `UI设计规范与页面模板.md` 的对应模板**，设计 Token 全部来自 `uni.scss` + `common/styles/variables.scss`，禁止页面内写死颜色/尺寸。

## 3. 公共能力任务卡（P0 级，先于页面）

### P0-1 · 网络层 `common/request/index.ts`
- 封装 `uni.request`，**baseURL 固定为 `http://192.168.20.130:8760/api/web-customer`**（开发与生产**统一走网关**；禁止直连 8164，`TokenAuthInterceptor` 缺 `userid` 头即 401，8164 仅供健康检查）。
- 请求拦截：自动附加 **`token: <token>`**（取自 Pinia / `uni.getStorageSync('token')`）。❗**禁止用 `Authorization: Bearer`** —— 网关 `authentication.user.header-name: token`，用错则全部请求 401。
- 响应拦截：`code===0 || code===200` 视为成功，返回 `res.data`；否则 `uni.showToast` 报错；`code===401` 跳转 login。
- 若阶段 0 实测 `Result` 与 `R` 字段不同，在此层归一化为 `{code, data, msg}`。
- **红线**：禁止在页面里裸调 `uni.request`，一律走此封装。

### P0-2 · 用户态 `stores/user.ts`（Pinia）
- state：`token`、`memberId`、`profile`、`openid`。
- actions：`login(code)`（调 P0-0 接口）、`fetchProfile()`（GET /user/profile）、`logout()`。
- 持久化：`uni.setStorageSync` 存 token；App 启动 `onLaunch` 若有过期则静默刷新或跳 login。

### P0-3 · 坐标转换 `common/utils/coord.ts`
- 实现 `bd09ToGcj02(lng, lat)`（标准公式，约 30 行），所有要在 `<map>` 上标点/画线时先转换。
- 原因：后端 `pd-oms` 存百度 BD-09；微信小程序 `<map>` 组件固定腾讯 GCJ-02，不转换会偏移数百米。

### P0-4 · API service 层 `common/api/*.ts`
- `mailing.ts`、`address.ts`、`agency.ts`、`goodsType.ts`、`common.ts`、`user.ts`、`trace.ts`，每个方法对应 §7 契约表的一个端点，入参/出参类型据 DTO 标注。
- 禁止在页面里拼 URL，页面只调用 service 方法。

### P0-5 · 全局 UI 壳（引用 UI §3）
- 统一 `u-navbar`（标题 + 返回）、`u-tabbar`（仅 3 个 tab）、三态组件 `AppStateLoading/Empty/Error`（加载中骨架 / 空态插画 / 错误重试）。
- 所有页面顶部必须有 `u-navbar`，禁止绕过。

## 4. 页面任务卡（按优先级排序，逐张执行）

> 每张卡字段：ID / 模板 / 路由 / 调用接口 / 字段映射 / 交互 / 验收 DoD / 红线提醒

### P1-1 · 登录页 `pages/customer/login/index.vue`
- **模板**：自定义（表单/按钮类，套 UI Token，单按钮大操作）
- **路由**：`pages/customer/login/index`
- **调用**：P0-0 新增 `POST /member/wxlogin`（入参 `{code}` → 出参 `{token, memberId, openid}`）
- **交互**：进入即 `wx.login()` 取 code → 调登录 → 存 token → 跳 home。已登录则直接进 home。
- **DoD**：冷启动无 token 自动登录并拿到 token；断网给出错误态重试；不出现明文密码输入框。
- **红线**：禁止自建账号密码体系；token 仅存 `uni.setStorageSync` + Pinia，不落日志。

### P1-2 · 首页 `pages/customer/home/index.vue`
- **模板**：首页/门户类（大入口卡片 + 状态色）
- **路由**：`pages/customer/home/index`（tabBar）
- **调用**：无（纯导航）；可展示 `GET /mailing/count` 的"进行中/已完成"数。
- **交互**：三大入口——「我要寄件」→ mailing/create；「查快递」→ mailing/list；「我的」→ profile。
- **DoD**：三个入口可达；进行中订单数正确展示；无硬编码色值。
- **红线**：禁止堆砌无关功能；保持极简三步可达核心。

### P1-3 · 寄件表单 `pages/customer/mailing/create.vue`
- **模板**：**表单页**（UI §4.3）
- **路由**：`pages/customer/mailing/create`
- **调用**：
  - `GET /goodsType/all` —— 物品类型下拉
  - `GET /agency/page` —— 网点**仅供展示/自提参考**，⚠️ **下单网点不可由前端指定**：`MailingSaveDTO` 无 agency 字段，后端在 `save()` 里用发件地址调百度地图**自动计算** `currentAgencyId`。**不要做「选网点回传 id」的页面**。
  - `GET /address/page?page=&pageSize=&keyword=` —— 地址簿选择（跳 address/list，选中回传）。⚠️ 该接口**无 `type` 参数**；且分页参数名是 **`pageSize`（驼峰）**，其余接口是 `pagesize`（全小写），不可混用
  - `POST /mailing/totalPrice`（入参 `MailingSaveDTO`）—— 实时运费试算
  - `POST /mailing`（入参 `MailingSaveDTO`）—— 提交下单
- **字段映射（MailingSaveDTO）**：
  `sendAddress`(发件地址簿id) / `receiptAddress`(收件地址簿id) / `pickUpTime`(取件时间) / `pickupType`(取件方式 **1网点自寄 / 2上门取件**，见 `OrderPickupType.java`) / `payMethod`(1预结2到付) / `goodsType`(物品类型id) / `goodsName` / `goodsWeight`
- **交互**：选地址簿 → 选网点 → 填物品 → 实时显示试算运费（防抖 300ms 调 totalPrice）→ 提交。提交成功跳 mailing/detail。
- **DoD**：运费随输入实时刷新无误；提交后生成订单并跳详情；表单校验用 uview-plus `u-form` + 规则；地址/网点从列表选，不手填经纬度。
- **红线**：试算与提交共用同一 DTO；禁止把坐标写死或手填经纬度（由地址簿/网点提供）。

### P1-4 · 我的运单 `pages/customer/mailing/list.vue`
- **模板**：**列表页**（UI §4.1，含筛选 tab）
- **路由**：`pages/customer/mailing/list`（tabBar）
- **调用**：`GET /mailing/page`（入参 `MailingQueryDTO{keyword,page,pagesize,mailType}`）
- **交互**：顶部 tab 按状态/类型筛选（待揽收/运送中/已签收…）；下拉刷新、上拉分页（pagesize 默认 10）；点击进 detail。
- **DoD**：列表数据来自接口；分页正常；空态用三态组件；状态用 UI §2 状态色映射（待处理=橙/进行中=蓝/完成=绿/异常=红）。
- **红线**：分页参数走接口，禁止前端全量拉取再切片。

### P1-5 · 运单详情 `pages/customer/mailing/detail.vue`
- **模板**：**详情页**（UI §4.2，含时间轴）
- **路由**：`pages/customer/mailing/detail?id=xxx`
- **调用**：
  - `GET /mailing/detail?id=` → `CustomerOrderDetailDTO{id,status,tranOrderId,planPickUpTime,actualDispathedTime,cancelTime,name,mobile,avatar}`
  - `GET /mailing/route?id=` → `RouteDTO[]{msg,time,status,quantity}`（时间轴节点）
- **交互**：展示订单号/状态/运单号/取派时间/收件人；时间轴展示 route 节点；底部「查看实时轨迹」→ track 页；「取消」(status 允许时)→ `PUT /mailing/cancel/{id}`；「去支付」→ `PUT /mailing/pay/{id}`。
- **DoD**：详情与轨迹节点均来自接口；状态用状态色；取消/支付按钮按当前状态显隐；时间轴按 `time` 升序。
- **红线**：status 为枚举（见后端 `OrderStatus`），页面用映射表转文案+色，禁止魔法数字。

### P1-6 · 实时轨迹 `pages/customer/mailing/track.vue`

- **路由**：`pages/customer/mailing/track?id=xxx&tranOrderId=xxx`

## 5. 后端新增任务卡（P0-0，唯一允许的后端改动）

### P0-0 · C 端登录（❗ 2026-10-05 修正：**账号登录已存在，只缺微信免密**）

> **修正说明**：实测 `pd-auth-server` 已有 `POST /anno/login` + `GET /anno/captcha?key={uuid}`。
> 真正需要新增的**只有**微信小程序的 `code2Session` 免密登录（原 `/member/wxlogin` 方案保留，但必须复用既有 JWT 签发）。

- **已有能力（直接复用）**：`POST /anno/login`（`{account, password, key, code}`），返回 `R<LoginDTO>{user, token:{token,expire}, permissionsList}`。
- **需新增**：`POST /member/wxlogin`，入参 `{code}`，出参 `{token, memberId, openid}`。
- **位置**：`pd-web/pd-web-customer`（或 `pd-user` 的 `MemberController` 增方法），**不新建模块**。
- **实现约束（严格遵守红线）**：
  1. 用 `wx.login` 的 code 调微信 `code2Session`（`HttpURLConnection` + 超时，或 `RestTemplate`，**不引新依赖**）。
  2. 拿 `openid` → 查/建 `Member`（复用 `IMemberService`）；**JWT 必须复用 `AuthManager` / `JwtTokenServerUtils`**，禁止自造签名。
  3. 移动端请求头固定 `token: <token>`；网关解析后注入 `userid`，业务侧 `RequestContext.getUserId()`。
- **DoD**：小程序能静默登录拿到 token；`GET /user/profile` 带 `token` 头返回正确资料；`mvn -o -q compile`（JDK1.8）通过。
- **红线**：不得引入 Spring Security/OAuth 新依赖；不改 JDK/依赖版本；不引新 ORM；**不得实现 refreshToken**（后端无该字段），401 即重登。
