## 第 1 章 项目约束与红线（宪法级，必须最先读）

> **本章是最高优先级约束。任何开发任务都必须先满足本章，违反本章的改动一律视为不合格、必须回退。**

### 1.1 技术栈硬约束（不可变更）
1. **JDK 固定 21 LTS（Eclipse Temurin）**，不得降级到 8/11/17，不得升级到 22+。**任何 `pom.xml` 必须 `<release>21</release>`，Dockerfile 必须 `eclipse-temurin:21-jdk`**。
2. **后端依赖锁定到升级后基线**（见 §2.1）：全栈已迁至 JDK21/SB3.3/Cloud2023/Alibaba2023 等，**未经人工显式同意，禁止在基线之上再擅自升级依赖**（含 Spring Boot、Cloud、Alibaba、MyBatis Plus、Druid、Shiro、Drools、Lombok、FastJSON2 等）。（**2026-10-08 修订**：原"禁止升级任何依赖"已废止——全栈升级本身即依赖升级，本条款现约束"不超出已定基线的额外升级"。）
3. **安全 CVE 随全栈升级一并解决**：FastJSON 1.x→2.x、Shiro 升级至安全版本等随第2条迁移自然消除；升级后若仍有未覆盖的高危 CVE，须登记并评估。（**2026-10-08 修订**：原"安全问题不考虑"已废止——见《红线》第3条。）
4. **业务代码不降级/不重写**：保持现有分层（controller / service / service.impl / mapper / entity）与 MyBatis Plus 用法；使用 jakarta.* 命名空间（非 javax.*）。

### 1.2 架构与边界红线
5. **新增功能优先复用现有能力**：三端 REST API（`pd-web-customer/driver/courier`）已存在，移动端直接调用，**后端能不改则不改**。
6. **后端"未实现的中间件"是用户路线图，不是缺失 bug**：MongoDB/HBase/Spark/Hive/ES/RocketMQ/MapStruct/Sentinel/SkyWalking/XXL-JOB 等，当前未落地是"计划内"，**不得把它们当成问题去补齐或"顺手"引入**。
7. **网关现状 = Spring Cloud Gateway**（在 `pd-authority/pd-apps/pd-gateway`），**不是 Zuul 1.x、无 Sentinel**。Gateway 是 WebFlux 响应式编程模型；路由配置走 Nacos `pd-gateway.yml`（DiscoveryClientRouteDefinitionLocator 自动按服务名路由）。不得回退到 Zuul。
8. **模块职责严格不越界**：订单只在 `pd-oms`、调度只在 `pd-dispatch`、作业只在 `pd-work`、基础数据只在 `pd-base`、轨迹只在 `pd-netty`。新增实体/接口放到对应模块，不跨模块写业务。

### 1.3 开发行为红线（AI 编码代理最易犯的错误）
9. **禁止过度设计（YAGNI）**：不引入当前需求用不到的抽象层、设计模式、配置中心、消息队列、缓存框架。能用现有 Drools/Kafka/RabbitMQ/Quartz 解决的，不换方案。
10. **禁止"顺手"重构**：不重命名既有类/方法、不改既有接口签名；**「管理端 Vue3 升级专项」任务下允许改动 `pd-admin-ui` 源码与结构**，非专项仍不得随意重构 `pd-admin-ui`（管理端）既有文件，除非任务明确要求。
11. **禁止重复造轮子**：轨迹、鉴权、坐标/距离计算、状态机、运费等已有实现，新增功能必须调用既有实现；不得另写一套。
12. **禁止硬编码**：cron、阈值、地图 Key、坐标等配置必须外部化到 `bootstrap.yml` / Nacos / 配置文件；不写死在 Java/JS 中。
13. **禁止破坏编译/契约**：每次改动后必须保证受影响的模块 `mvn -o -q compile` 通过（本地用 JDK 21 LTS）；对外接口字段变更须同步更新本文档 §5、§6。（**2026-10-08 修订**：编译 JDK 由 1.8 改为 21。）
14. **先读后写**：改动任何文件前，必须先用 Read/搜索确认其现状与调用关系；禁止凭记忆或猜测写代码。

### 1.4 明确不做的"花架子"（本期一律不启动）
- 不盲目上 MongoDB / HBase / Spark / Hive / Elasticsearch / RocketMQ / XXL-JOB / Sentinel（路线图里有，但当前无对应痛点）。
- **管理端 `pd-admin-ui` 升级到 Vue3 列为本期专项**（目标栈：Vue3 + Vite + Element Plus + Pinia + ECharts 5，取代既有 Vue2.6 + Element UI 2.12 + Vuex 3 + Webpack 4）。纯 UI 迁移不再视为"零收益"——它解除技术债：Webpack4/OpenSSL3 构建阻断（Node17+ 必现 `ERR_OSSL_EVP_UNSUPPORTED`）、Vue2 已 EOL（2023-12）、响应式与组合式 API 红利、为后续移动端同源复用打底。
- 不建重型 WMS（波次/上架策略/AGV）、不建多租户 SaaS、不建复杂 BI。
- 不对接外部厂商 / 三方物流 API（EDI/ERP/顺丰·三通一达/多式联运/国家合规）—— 本项目为自营 / 加盟运输管理，业务模式不涉及（详见 §6.9）。
- 不引入 GraphQL、不引入微服务网格、不做容器编排改造（除非用户单独指令）。

### 1.5 需求优先级定义
| 优先级 | 含义 | 退出标准 |
|---|---|---|
| **P0** | 首期必做，业务闭环必需 / 最大缺口 | 功能可用 + 走通端到端链路 |
| **P1** | 重要补齐，明显提升时效/成本/差错 | 功能可用 + 数据正确 |
| **P2** | 增强/按需，出现真实痛点再做 | 单点验证通过 |
| **路线图** | 仅规划，本期不做 | — |

> **执行层子标记 P0a/P0b/P0c（2026-10-08 二轮审查回写：EC-16）**：导入 CSV 与子任务 DoD 中出现的 `P0a`/`P0b`/`P0c` 为 P0 内部的执行层拆分，非新优先级：
> - **P0a** = 业务主链路 P0（三端移动 + POD + 看板）；
> - **P0b** = 底座阻塞 P0（环境/鉴权/资源注册/网关等联调前置，如 T-001/T-002）；
> - **P0c** = 合规闸口 P0（M1 上线硬闸，如 T-005/T-006/T-007 R1-1/R2-2/R2-3）。
> 三者同属 P0 大档，退出标准与本表 P0 一致；R6-1/2/3/5 已于 2026-10-08 EC-01 口径统一降为 P1 限期补、不阻塞 M1，不再标 P0c。

### 3.2 前后端职责
- **前端（uni-app / 管理端）**：页面、交互、表单校验、本地缓存、离线队列、坐标转换、轮询。
- **后端**：业务规则、状态机、数据持久化、鉴权、计费、轨迹接入。
- **禁止**：把业务规则（运费、状态流转、计费）放到前端硬编码；前端只调用、不计算核心规则。

### 3.3 统一响应与错误处理（沿用既有）
- 沿用项目既有 `R` / `Result` 包装类（以源码实际为准）。新增接口返回结构须与既有接口一致。
- 错误码沿用既有枚举；新增错误码须追加到既有枚举，不新建一套。

### 3.4 鉴权契约（移动端必须遵守）
- 鉴权 = **JWT**。移动端登录后持 JWT，请求经拦截器自动附加 **`token` 头**（配置 `authentication.user.header-name: token`，**不是 `Authorization`**）。
- 拦截器处理 401（**清 token 重登**，后端 `Token{token,expire}` 不返回 refreshToken，不要实现刷新流程）。
- **登录端点已实测确认（2026-10-05）**：`pd-auth-server` 提供 `POST /anno/login`（`{account,password,key,code}`）+ `GET /anno/captcha?key={uuid}` + `/anno/check` + `/anno/verify`；**不存在"需要新建登录"的情况**。
- **请求入口（实测修正）**：生产与开发**统一走网关** `http://<host>:8760/api`（前缀 `/api`）；网关由 Zuul 1.x 迁移至 Spring Cloud Gateway 为本期升级内容（端口 8760 不变）。（**2026-10-08 修订**：原"Zuul 网关"表述随升级迁移更新。）
  ❗ **开发期不可直连 `pd-web-*` 8161~8164** —— `TokenAuthInterceptor` 已全部注册，缺 `userid` 头返回 401。仅 `/swagger`、`/error`、`/actuator` 放行。
- 各 `pd-web-*` 服务的 Zuul 路由前缀**已实测固化**（2026-10-06 curl Nacos `pd-gateway-test.yml` 复核，共 13 条）：

  | 前缀 | 目标服务 | 端口 |
  |---|---|---|
  | `/web-manager/**` | pd-web-manager | 8161 |
  | `/web-driver/**` | pd-web-driver | 8162 |
  | `/web-courier/**` | pd-web-courier | 8163 |
  | `/web-customer/**` | pd-web-customer | 8164 |
  | `/netty-service/**` | pd-netty | 8192 |
  | `/auth/**` 与 `/authority/**`（两条并存，等价可用） | pd-auth-server | 9000 |
  | `/oms/**` `/work/**` `/dispatch/**` `/base/**` `/user/**` `/aggregation/**` | 内部 Feign 服务 | 8185~8191（其中 **8188 预留/未分配**，2026-10-08 二轮审查回写：EC-11，原 8185~8191 区间缺 8188 归属，仓库内无服务占用） |

### 3.5 鉴权链路与已知坑（2026-10-06 实测，开发必知）

**请求链路**：
```
前端(token 头) → 网关8760
  ├─ [pre] TokenContextFilter  解析 JWT，向下游注入 userid/account/name/orgid/stationid
  └─ [pre] AccessFilter        关卡1 需鉴权资源清单 / 关卡2 用户资源权限（均走 j2cache）
  → 下游服务 TokenAuthInterceptor 检查 userid 头（缺 → 401）
```

**四个已踩过的坑**（改代码前务必确认）：

| 坑 | 现象 | 正确做法 |
|---|---|---|
| **j2cache 配置指向不存在文件** | 所有走鉴权的接口 `500 pre:AccessFilter` | `j2cache.config-location` 必须是**仓库真实存在**的 `classpath:j2cache.properties`；Nacos 配置里凡指向 `classpath:` 的都要核对文件存在 |
| **菜单接口 userId 为 null** | 登录成功但**左侧菜单为空** | `MenuController.myRouter` 用 `StrUtil.isBlank(userId)` 时 `getUserId()` 取当前登录人；⚠️ `userId` 是 String，**不可用 `userId <= 0` 判断**（抛 NumberFormatException） |
| **菜单脏缓存** | 改完代码仍空菜单 | `redis-cli DEL "user_menu:null"` |
| **资源表 url 填法** | 接口永远"未知请求" | 填**服务内路径**（`/user/profile`），**不能带 `/api` 和 `web-driver` 段** |

> ⚠️ **AccessFilter 特性（易误判）**：源码 `if (resourceNeed2Auth != null)` 包裹关卡1，若 Feign 拉取清单返回 null，**关卡1整段跳过 → 所有请求放行**。因此"接口返回 200"**不等于**"鉴权生效"；判断鉴权是否真正工作，要对比**已注册接口**与**未注册接口**的返回是否一致。

> 📖 **接口不工作时的标准排查流程**见《环境故障排障手册.md》（含探活、直连对比、过滤器定位、缓存清理四步法）。

## 第 4 章 编码规范

1. **命名**：类 PascalCase、方法/变量 camelCase；接口名以 `XxxService`、实现 `XxxServiceImpl`；Mapper 沿用 `XxxMapper`；实体在 `entity`。
2. **分层**：controller（入参/出参/鉴权）→ service（业务）→ mapper（持久化）；不在 controller 写业务，不在 mapper 写业务。
3. **事务**：写操作加 `@Transactional`（沿用既有）；跨服务用既有 Seata 注解（见 §6.12），不新造分布式事务方案。
4. **日志**：用项目既有日志门面（slf4j）；禁止 `System.out.println`；敏感信息（手机号/证件）脱敏。
5. **异常**：业务异常抛 `RuntimeException` 子类或既有业务异常；全局异常处理器沿用既有，不新建。
6. **配置外部化**：cron、阈值、地图 Key、坐标类型、上报间隔等一律进配置文件/配置中心；不硬编码。
7. **SQL/MyBatis**：复杂查询用 MyBatis Plus 或 XML；禁止在循环内逐条查库（N+1），批量用 `in` 或批量接口。
8. **前端**：页面放 `pages/<角色>/`；公共能力放 `common/`；API 调用放 `api/`；状态放 `store/`；禁止在页面里写裸 `uni.request`（必须过拦截器）。
9. **数据层软删除 / 归档约定（P1 落 · 参照 Open TMS/EvolveTMS · 2026-10-07 并入）**：
   - 核心业务表（`pd_order` / `pd_transport_order` / `pd_task_transport` / `pd_task_pickup_dispatch`）**新增 `deleted` 状态位约定**（`tinyint(1)` 默认 0，删除=置 1，**物理删除仅限运维 SQL 且留审计**），所有查询默认 `deleted=0`。
   - **归档**：按 R6-3 审计保留期（审计≥6 月 / 业务≥3 年）归档，归档走现有备份/清理任务，不新引归档组件。
   - **禁止**：业务代码 `DELETE` 核心业务表（历史教训：软删缺失导致对账/审计断链）；导出"已删除"数据须审计留痕。

## 第 12 章 UI 设计规范（强制引用）

> 移动端页面样式与结构受《UI设计规范与页面模板.md》约束，与本章同等强制力。核心红线摘录：

6. **统一反馈**：加载/空/错/提示/确认/刷新分页全部走 uview-plus 组件，禁止自造。
7. **禁止清单**（详见 UI 规范 §7）：禁裸 HTML 布局、禁硬编码色值、禁第二套 UI/图标库、禁 emoji 图标、禁缺三态、禁绕过 `u-navbar`、`uni.request` 必须过拦截器。
8. **主题一处改全端生效**：`uni.scss`（覆盖 uview-plus 主题）+ `common/styles/variables.scss`（业务 Token）为唯一真源。
