## 0. 总纲与红线（不可逾越）

本任务卡只做**快递员端前端（App / 小程序均可，以 App 为主做重操作）+ 一个缺失的登录后端接口 + 复用既有取派/签收接口**，不得：
- 升级/改动任何后端依赖、JDK、技术栈（红线 §1.x）；
- 引入任何新中间件、新 UI 库、第二套组件体系（红线 §12.x / UI §7）；
- 新建平行后端服务或重写既有 `pd-web-courier` 接口（§5 已盘点，必须复用）；
- 页面随意写 `<div>`+`<style>`、硬编码色值、自创间距（UI §7 禁止清单）。

**快递员端核心价值 = POD 电子签收**（扫码 + 手写签名 + 拍照 + GPS 水印），按 spec POD 要求纳入第一期。所有页面套用 `UI设计规范与页面模板.md`，快递员端强调「扫码为主操作 + 大按钮」（角色化 UI §5）。

## 3. 复用 + 新增公共能力

### 复用（来自客户小程序任务卡 P0-1~5）
- `common/request/index.ts`、`stores/user.ts`、`common/utils/coord.ts`、`common/api/*`、`u-navbar/u-tabbar/三态组件` 全部复用。

### C-P0-1 · POD 工具 `common/utils/pod.ts`（快递员端核心）
- `signToImage()`: 用 `<canvas>` 手写签名 → 导出图片 base64。
- `addGpsWatermark(image, {lng, lat, time})`: 在签名/拍照图片上叠加 GPS 坐标 + 时间文字水印（canvas 绘制），满足 spec POD「GPS 水印」。
- 依赖 `uni.getLocation` 取点（禁纯网络定位，优先北斗/GPS 双模，与司机端一致）。
- **红线**：水印在端上完成，不把裸图直传后再让后端加水印（避免隐私坐标明文落库风险）；不引第三方签名库，用原生 canvas。

### C-P0-2 · API service `common/api/courier.ts` / `attachment.ts`
- 每个方法对应 §6 契约表端点；`attachment.upload(file)` 封装上传拿回 id/url。

## 4. 页面任务卡（逐张执行）

> 每张卡字段：ID / 模板 / 路由 / 调用接口 / 字段映射 / 交互 / 验收 DoD / 红线提醒

### C-1 · 登录页 `pages/courier/login/index.vue`
- **模板**：自定义（大按钮）；支持「手机号 + 短信验证码」或微信授权 `wx.login` code。
- **路由**：`pages/courier/login/index`
- **调用**：P0-0 新增 `POST /courier/login`（入参 `{phone, smsCode}` 或 `{code}` → 出参 `{token, courierId}`）
- **交互**：取验证码/code → 登录 → 存 token → 跳 home；已登录直进。
- **DoD**：冷启动无 token 自动登录；断网给错误态重试；无明文密码框。
- **红线**：token 仅存 `uni.setStorageSync` + Pinia；不落日志；不引新鉴权依赖。

### C-2 · 首页 `pages/courier/home/index.vue`（tabBar）
- **模板**：任务大厅类（取件/派件双标签 + 计数 + 状态色）
- **路由**：`pages/courier/home/index`
- **调用**：`GET /courier/count?taskType&status`（取件/派件各自计数）、`GET /user/profile`
- **交互**：顶部切换「取件 / 派件」；展示待办计数；大入口「扫码接单」→ 调 `uni.scanCode` 解析运单号 → 跳 detail。
- **DoD**：双标签计数正确；扫码可跳详情；状态色正确；无硬编码。
- **红线**：保持极简；扫码是主操作，按钮够大够醒目。

### C-3 · 取派任务列表 `pages/courier/task/list.vue`（tabBar）
- **模板**：**列表页（含筛选 tab，UI §4.1）**
- **路由**：`pages/courier/task/list`
- **调用**：`GET /courier/pickupDispatch?page&pagesize&taskType&status&keyword&date`（返回 `PageResponse<PickupDispatchDTO>`）
- **字段映射（PickupDispatchDTO，以阶段0实测为准）**：`orderNumber`(运单号) / `tranOrderId`(运输任务id) / `taskType`(1取件2派件) / `status`(任务状态) / `receiver.name`+`receiver.phone`+`receiver.address`(收件人) / `sender.*`(寄件人) / `goodsTypeName` / `weight` / `quantity` / `paymentMethod` / `amount`
- **交互**：顶部按 `taskType`(取/派) + `status` 筛选；下拉刷新、上拉分页；点击进 detail；支持 `keyword` 搜运单号。
- **DoD**：列表来自接口；分页/筛选/搜索正常；空态三态；状态用 UI §2 状态色映射。
- **红线**：分页走接口，禁止前端全量切片；`taskType`/`status` 为枚举，用映射表转文案+色。

### C-4 · 任务详情 `pages/courier/task/detail.vue`
- **模板**：**详情页（含时间轴，UI §4.2）**
- **路由**：`pages/courier/task/detail?id=`
- **调用**：
  - `GET /courier/detail?id=` → 任务详情
  - `GET /courier/route?id=` → 路由节点
  - `POST /courier/totalPrice`(@RequestBody MailingSaveDTO) → 运费（展示用）
- **交互**：展示寄/收件人、货物、运费、路由时间轴；底部按 `taskType`/`status` 显隐「入库」「交接」「电子签收」按钮（→ C-5/C-6/C-7）；「身份证核验」→ C-8；「查看路由」→ C-9。
- **DoD**：详情/路由/运费来自接口；按钮按状态显隐；时间轴升序。
- **红线**：`status` 枚举用映射表；不臆造状态值。

### C-5 · 电子签收 POD `pages/courier/pod/sign.vue`（**核心**）
- **模板**：**POD 签收页（UI §4.6，自定义大按钮布局）**
- **路由**：`pages/courier/pod/sign?tranOrderId=&orderNumber=`
- **调用**：
  - `POST /attachment/upload`（拍照 + 签名图，出参附件 id/url）
  - `PUT /courier/delivered/{tranOrderId}/{status}`（status=已签收，如后端支持传 location 则带当前 GPS）
- **交互**：
  1. `uni.scanCode` 或手动选任务进入；
  2. **拍照**：`uni.chooseMedia` 拍签收照片；
  3. **手写签名**：`<canvas>` 手写 → `pod.signToImage()`；
  4. **GPS 水印**：`uni.getLocation` 取点 → `pod.addGpsWatermark()` 在签名/照片叠加坐标+时间；
  5. 上传附件 → 调 `delivered` 置为已签收 → 返回列表并刷新。
- **DoD**：签收照片 + 手写签名均上传成功并关联；签名字片含可读 GPS 水印；状态流转为已签收；断网入离线队列、恢复补传。
- **红线**：水印在端上完成；照片/签名经 `attachment/upload`，禁止 base64 直塞业务请求体；经纬度来自定位服务禁手填；不引第三方签名/水印库。

### C-6 · 入库 `pages/courier/task/warehousing.vue`
- **模板**：操作页（大按钮 + 确认）
- **路由**：`pages/courier/task/warehousing?tranOrderId=`
- **调用**：`PUT /courier/warehousing/{tranOrderId}`
- **交互**：确认入库 → 调接口 → 状态更新 → 返回。
- **DoD**：入库状态流转正确；失败给错误态重试。
- **红线**：状态走后端，前端不臆造。

### C-7 · 交接 `pages/courier/task/handover.vue`
- **模板**：操作页（大按钮 + 交接人/网点输入）
- **路由**：`pages/courier/task/handover?tranOrderId=`
- **调用**：`PUT /courier/handover/{tranOrderId}`
- **交互**：选择交接网点/下一环节 → 确认 → 状态更新。
- **DoD**：交接成功；状态正确流转。

### C-8 · 身份证核验 `pages/courier/task/verify.vue`
- **模板**：操作页（扫码/输入单号 + 核验码）
- **路由**：`pages/courier/task/verify?orderNumber=`
- **调用**：`GET /courier/verifyIdCard?orderNumber=&code=`
- **交互**：输入/扫订单号 + 核验码 → 调接口 → 展示核验结果（通过/不通过）。
- **DoD**：核验结果正确展示；异常给错误态。
- **红线**：不存储身份证号明文；仅展示核验状态。

### C-9 · 路由/轨迹 `pages/courier/task/route.vue`
- **模板**：**地图页（UI §4.4）**
- **路由**：`pages/courier/task/route?id=`
- **调用**：`GET /courier/route?id=`（路由节点）、`GET /trace/latest?orderId=`（每 10s 轮询）
- **交互**：`<map>` 标点（经 `coord.bd09ToGcj02` 转换后端 BD-09 坐标）；展示路由节点与当前位置。
- **DoD**：地图偏移 < 50m；轮询 10s；无网络降级缓存点。
- **红线**：只轮询 latest，禁止改 WebSocket；坐标先转换。

### C-10 · 个人中心 `pages/courier/profile/index.vue`（tabBar）
- **模板**：门户类
- **路由**：`pages/courier/profile/index`
- **调用**：`GET /user/profile`
- **交互**：展示快递员资料；入口：我的任务、退出登录。
- **DoD**：资料来自接口；退出清 token 跳 login。

## 5. 后端新增任务卡（P0-0，唯一允许的后端改动）

### P0-0 · 快递员端登录接口（缺失，必须新增）
- **位置**：`pd-web/pd-web-courier`（**不新建模块**），复用项目现有 JWT 工具与 `RequestContext` 体系。
- **端点**：`POST /courier/login`，入参 `{phone, smsCode}` 或 `{code}`，出参 `Result<{token, courierId}>`。
- **实现约束（严格遵守红线）**：
  1. 微信授权用 `wx.login` code 调 `code2Session`（HTTP 用现有 `EntCoordSyncJob.loadJSON` 同款 `HttpURLConnection` + 已加超时，不引新依赖）；短信验证码复用既有短信能力（若无则本期用 code 方式）。
  2. 用 `courierId` 查/建快递员用户（复用既有快递员实体与 MyBatis Plus 体系），生成 JWT。
  3. 后续请求经 Zuul → Shiro/JWT 过滤器 → `RequestContext.getUserId()`。
- **DoD**：端能登录拿 token；`GET /user/profile` 带 token 返回正确资料；`mvn -o -q compile`（JDK1.8）通过；改动同步回 `开发规范与需求规格说明书.md` §5。
- **红线**：不得引入 Spring Security/OAuth 新依赖；不改 JDK/依赖版本；不引新 ORM。
- **POD 后端**：`courier/delivered` 与 `attachment/upload` 已存在，POD 落库（签收图/签名）若需新增字段，按 spec POD 走最小化后端扩展（不引新依赖），不在本卡 P0-0 范围。
