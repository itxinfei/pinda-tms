# 服务器中间件升级操作手册

> **服务器**：192.168.20.130
> **现状**：6 个中间件跑在 Docker 里，数据在 /data/ 下
> **目标**：升到 MySQL 8 / Redis 7 / Nacos 2.x / Zookeeper 3.9 / Kafka 3.x / RabbitMQ 3.12
> **原则**：先备份，再升级，每步验证，出问题可回滚

---

## 〇、升级前必做：全量备份

```bash
# SSH 到 192.168.20.130，切 root
mkdir -p /data/backup/pre-upgrade-$(date +%Y%m%d)
cd /data/backup/pre-upgrade-$(date +%Y%m%d)

# 1. MySQL 备份（最关键）
docker exec mysql57 mysqldump -uroot -p$MYSQL_ROOT_PASSWORD --all-databases --routines --triggers --events > mysql-all.sql
# 输入密码（从 /data/deploy/middleware/.env 里拿）

# 2. Nacos 配置导出（35 条配置）
curl -X GET "http://127.0.0.1:8848/nacos/v1/cs/configs?dataId=*&group=*&pageNo=1&pageSize=100" -o nacos-configs.json

# 3. 其他中间件数据目录直接打包（Redis/Zookeeper/Kafka/RabbitMQ）
tar czf redis-data.tar.gz /data/redis/
tar czf zookeeper-data.tar.gz /data/zookeeper/
tar czf kafka-data.tar.gz /data/kafka/
tar czf rabbitmq-data.tar.gz /data/rabbitmq/
tar czf nacos-data.tar.gz /data/nacos-data/

# 4. 记录当前镜像版本（回滚用）
docker inspect mysql57 redis nacos zookeeper kafka rabbitmq --format '{{.Name}}: {{.Config.Image}}' > current-images.txt
```

## 一、升级顺序（从最简单到最复杂）

### 1. Redis 5 → 7（最简单，直接换）

**为什么简单**：Redis 数据格式向前兼容，5.x 的 RDB/AOF 文件 7.x 能直接读。

```bash
# 1. 停 Redis
docker stop redis && docker rm redis

# 2. 改 compose 文件（deploy/middleware/docker-compose.infra.yml）
#    image: redis:5 → image: redis:7

# 3. 启动
cd /data/deploy/middleware
docker compose -f docker-compose.infra.yml up -d redis

# 4. 验证
docker exec redis redis-cli ping
# 应返回 PONG
docker exec redis redis-cli info server | grep redis_version
# 应显示 redis_version:7.x.x
```

**风险**：极低。出问题直接换回 redis:5 镜像。

---

### 2. Zookeeper 3.5 → 3.9（直接换）

```bash
# 1. 停 Zookeeper
docker stop zookeeper && docker rm zookeeper

# 2. 改 compose：image: zookeeper:3.5 → image: zookeeper:3.9

# 3. 启动
cd /data/deploy/middleware
docker compose -f docker-compose.infra.yml up -d zookeeper

# 4. 验证
docker exec zookeeper zkServer.sh status
# 应显示 Mode: standalone
```

**风险**：低。Kafka 依赖 Zookeeper，升级完要重启 Kafka。

---

### 3. RabbitMQ 3.8 → 3.12（直接换，注意 hostname）

```bash
# 1. 停 RabbitMQ
docker stop rabbitmq && docker rm rabbitmq

# 2. 改 compose：image: rabbitmq:3.8-management → image: rabbitmq:3.12-management
#    hostname 保持 rabbitmq（钉死节点名）

# 3. 启动
cd /data/deploy/middleware
docker compose -f docker-compose.infra.yml up -d rabbitmq

# 4. 验证
docker exec rabbitmq rabbitmq-diagnostics -q ping
# 应返回 ping succeeded
docker exec rabbitmq rabbitmqctl status | grep RabbitMQ
# 应显示 RabbitMQ version: 3.12.x
```

**风险**：中。现有 mnesia 目录是 rabbit@<旧容器ID>，钉死 hostname=rabbitmq 后会另起一份空库。**当前 5 个队列消息数都是 0，且 Spring AMQP 连接时会重新声明队列，所以不丢业务拓扑**。

---

### 4. Kafka 2.6 → 3.x（直接换 bitnami 镜像）

```bash
# 1. 停 Kafka（先停依赖它的 Zookeeper 已升级）
docker stop kafka && docker rm kafka

# 2. 改 compose：image: bitnami/kafka:2.6.0 → image: bitnami/kafka:3.7
#    数据目录 /bitnami/kafka 保持不变

# 3. 启动
cd /data/deploy/middleware
docker compose -f docker-compose.infra.yml up -d kafka

# 4. 验证
docker exec kafka kafka-topics.sh --bootstrap-server localhost:9092 --list
# 应列出现有 topic（轨迹相关的）
```

**风险**：中。bitnami Kafka 3.x 默认用 KRaft 模式（不依赖 Zookeeper），但现有数据是 Zookeeper 模式存的。**保持 KAFKA_CFG_ZOOKEEPER_CONNECT 配置不变**，继续用 Zookeeper 模式，不要切 KRaft。

---

### 5. Nacos 1.4 → 2.x（要导出配置再导入）

**为什么麻烦**：Nacos 1.4 用内嵌 Derby 数据库，2.x 数据格式变了，不能直接挂旧数据目录。

```bash
# 1. 先在 1.4 里导出所有配置（升级前已备份 nacos-configs.json）

# 2. 停 Nacos
docker stop nacos && docker rm nacos

# 3. 改 compose：image: nacos/nacos-server:1.4.1 → image: nacos/nacos-server:v2.3.2
#    端口要加 9848（gRPC）：
#    ports:
#      - "8848:8848"
#      - "9848:9848"   # 新增
#      - "9849:9849"   # 新增

# 4. 启动空的 Nacos 2.x
cd /data/deploy/middleware
docker compose -f docker-compose.infra.yml up -d nacos

# 5. 登录控制台 http://192.168.20.130:8848/nacos（默认 nacos/nacos）
#    手动导入配置：配置管理 → 导入配置 → 选 nacos-configs.json

# 6. 验证
curl "http://127.0.0.1:8848/nacos/v1/cs/configs?dataId=pd-gateway.yml&group=pinda-tms"
# 应返回网关配置内容
```

**风险**：中。配置要手动导入，导入后逐条核对 35 条配置是否完整。

---

### 6. MySQL 5.7 → 8.0（最麻烦，要导出再导入）

**为什么最麻烦**：MySQL 5.7 和 8.0 的数据文件格式不兼容，不能直接挂 /data/mysql 目录启动 8.0 镜像。必须先 mysqldump 导出 SQL，再导入 8.0。

```bash
# 1. 确保已备份 mysql-all.sql（升级前已做）

# 2. 停 MySQL 5.7
docker stop mysql57 && docker rm mysql57

# 3. 把旧数据目录改名（不删，留着回滚）
mv /data/mysql /data/mysql-5.7-backup

# 4. 改 compose：
#    image: mysql:5.7 → image: mysql:8.0
#    服务名 mysql57 → mysql8（容器名也改）

# 5. 启动空的 MySQL 8.0
cd /data/deploy/middleware
docker compose -f docker-compose.infra.yml up -d mysql8

# 6. 等 MySQL 8.0 启动完成（约 30 秒）
sleep 30

# 7. 导入数据
docker exec -i mysql8 mysql -uroot -p$MYSQL_ROOT_PASSWORD < /data/backup/pre-upgrade-$(date +%Y%m%d)/mysql-all.sql

# 8. 验证
docker exec mysql8 mysql -uroot -p$MYSQL_ROOT_PASSWORD -e "show databases;"
# 应看到所有旧库（pd_auth / pd_base / pd_oms / pd_dispatch / pd_work 等）

docker exec mysql8 mysql -uroot -p$MYSQL_ROOT_PASSWORD -e "use pd_auth; select count(*) from pd_auth_resource;"
# 应返回 383（菜单资源表条数，和旧库一致）
```

**风险**：高。注意事项：
- MySQL 8.0 默认认证插件是 caching_sha2_password，JDBC 连接串要加 `allowPublicKeyRetrieval=true&useSSL=false`
- MySQL 8.0 不支持旧的 sql_mode（如 NO_AUTO_CREATE_USER），导入时可能有 warning
- 字符集 utf8mb4 兼容，不用改

## 三、回滚方案（出问题时）

```bash
# 停所有新中间件
cd /data/deploy/middleware
docker compose -f docker-compose.infra.yml down

# MySQL 回滚：改 compose 回 mysql:5.7，把 /data/mysql-5.7-backup 改回 /data/mysql
mv /data/mysql /data/mysql-8.0-backup
mv /data/mysql-5.7-backup /data/mysql

# 其他中间件回滚：改 compose 镜像版本回旧版，数据目录不用动

# 重启
docker compose -f docker-compose.infra.yml up -d
```

## 五、一句话总结

| 中间件 | 能不能直接换镜像 | 要做什么 |
|---|---|---|
| Redis 5→7 | ✅ 直接换 | 改镜像版本，重启 |
| Zookeeper 3.5→3.9 | ✅ 直接换 | 改镜像版本，重启 |
| RabbitMQ 3.8→3.12 | ✅ 直接换 | 改镜像版本，重启（队列空，不丢数据） |
| Kafka 2.6→3.x | ✅ 直接换 | 改镜像版本，重启（保持 Zookeeper 模式） |
| Nacos 1.4→2.x | ⚠️ 要导配置 | 先导出配置 JSON，升级后手动导入 |
| MySQL 5.7→8.0 | ❌ 不能直接换 | 先 mysqldump 导出 SQL，升级后导入 |
