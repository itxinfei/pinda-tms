# 品达物流 TMS — 页面功能审查报告

> 审查对象：`pd-admin-ui`（Vue 2.6.10 + Element UI 2.12 + ECharts 4.2）管理端，以及三端移动端（司机/快递员/客户）现状。
> 审查方式：源码静态分析（未修改文件）。日期：2026-10-06。
> 事实来源：pd-admin-ui 实际页面 + 三端任务卡规划 + 《物流项目功能需求分析.md》《运营可视化与成本管控任务卡.md》《财务结算与调度运力IoT任务卡.md》《UI设计规范与页面模板.md》。

---

## 一、核心结论

1. **管理端是"权限/RBAC + 系统运维工具"骨架，物流业务页面基本空白。** 清点 74 个 `.vue` 页面，与"物流运营业务"直接相关的仅 **6 个**（轨迹 1 + 支付 5），且 ofpay 有 2 个占位、trace 用 ECharts 模拟地图。订单/运单/调度/运输任务/车辆/司机/成本/结算/绩效/告警等核心业务页面**完全缺失**。
2. **移动端（司机/快递员/客户）代码为零**：全仓无 `pages.json`/`manifest.json`/`uni.scss`，无 uni-app/Vue3 工程；仅有 3 份任务卡规划（共 **31 个页面**）。审查对象目前是任务卡本身，尚未落到代码。
3. **UI 规范仅覆盖移动端**：《UI设计规范与页面模板.md》是 uni-app/uview-plus 规范，管理端缺少对应的 Element UI 版设计 Token，现有页面普遍存在硬编码色值（抽查 8 页仅 1 页较符合）。

## 二、管理端路由与菜单机制

| 文件 | 作用 | 状态 |
|---|---|---|
| `src/router/index.js` | 静态路由 + 导航守卫拉取**后端动态路由**（`loginApi.getRouter()`） | 在用 |
| `src/router/avue-router.js` | Avue 路由桩 | **死文件** |
| `src/router/views/index.js` | 旧 BladeX/Avue 模板路由，引用**不存在**的页面 | **死配置** |
| `src/router/page/index.js` | 同上，引用 `@/page/index/` | **死配置** |

- 真实菜单由**后端 `getRouter` 下发**，前端 `filterAsyncRouter` 把后端 `component` 字符串映射为 `@/views/${path}.vue`。菜单呈现取决于后端菜单表。
- 接口网关：`.env.development` 中 `VUE_APP_BASE_API=/api`，开发代理到 `:8760` → **请求统一走 `/api` 网关前缀**（正确）。例外：`pinda/ofpay/customer` 用裸 `fetch` 直连 `/api/pay/callback/mock`，**绕过拦截器**（建议整改）。
- 存在 3 个遗留死文件 + 若干死 API（`api/Dashboard.js`、`api/Tenant.js` 无引用），建议清理。

## 五、UI 规范符合性抽查（8 页）

> 前提：《UI设计规范与页面模板.md》正文是移动端（uview-plus）规范，其 Token（`--c-primary:#2B6CFF`、`u-*` 组件）面向移动端。本报告按规范"只用组件库/设计 Token 集中/禁止硬编码"的**通用精神**平移到管理端评估。
> 管理端实际主色：`src/styles/element-variables.scss` `$--color-primary: #1890ff`（Ant 蓝），**并非**规范的 `#2B6CFF`；源码还散落 `#E05635`、`#409EFF` 等第三、第四种"主色"。

| # | 抽查页面 | 符合 | 主要问题 |
|---|---|---|---|
| 1 | `dashboard/index.vue` | ❌ | 数字全静态；硬编码 hex 约 30 处；px 硬编码 |
| 2 | `pinda/user/org/Index.vue` | ❌ | 按钮硬编码 `#E05635`/`#DCDFE6`/`border-radius:5px`/`height:40px`（非主题色、非 type） |
| 3 | `pinda/auth/role/Index.vue` | ❌ | 同 org：按钮 `#E05635`；`header-cell-style` 内嵌 `#FCFBFF` |
| 4 | `pinda/trace/index.vue` | ⚠️ | 主要用组件库，仅少量图表配色；但**轨迹非真实地图**（能力缺口） |
| 5 | `pinda/ofpay/customer/Index.vue` | ⚠️ | 用组件库；但裸 `fetch` 绕过拦截器、仅 mock |
| 6 | `pinda/ofpay/send`/`platform` | ❌ | **纯占位页**，违背"不做花架子" |
| 7 | `febs/system/user/Index.vue` | ✅ | 用 `type="primary"/warning"`（走 Element 主题），无硬编码 |
| 8 | `pinda/developer/Index.vue` | ⚠️ | 导航卡片，图标色 `#409EFF`（可接受），无集中 Token |

**抽查结论**：8 页仅 1 页较符合，2 页基本符合，**5 页不符合**；全站硬编码 hex 色值遍布（dashboard 30 处、user/Index 19 处、auth/role 14 处、auth/menu 14 处…），设计 Token 未落地；品牌主色三处不一致（`#1890ff`/`#409EFF`/`#E05635`/规范 `#2B6CFF`）。

## 七、关键发现与建议

1. **业务功能几乎为零**：74 页中仅 6 页与物流运营相关且均为边缘。订单/运单/调度/运输任务/车辆/司机/成本/结算/绩效/告警等核心页面**完全缺失**——这是与需求文档最大的结构性缺口，需按 §4 P0 清单优先补齐。
2. **路由后端驱动 + 死配置**：删除 `avue-router.js`、`router/views/index.js`、`router/page/index.js`；清理 `api/Dashboard.js`、`api/Tenant.js` 等死 API；确认 `febs/system/*` 与 `pinda/*` 重复页取舍。
3. **地图能力缺失**：`package.json` 无地图库，trace 用 ECharts 折线模拟地理轨迹，无法支撑 OPS-3 看板与"可视化调度一张图"。需引入地图能力（注意 OPS 卡的"零表改动"仅针对数据，前端渲染需单独评估）。
4. **支付仅 mock**：ofpay 走 mock 渠道、裸 `fetch` 绕过拦截器，与需求分析 §10.1「在线支付 P1 必做」差距明显。
5. **设计 Token 不统一**：管理端缺 Element UI 版设计 Token 文件；建议 (a) 在 `src/styles` 落地面向管理端的 design token（对齐规范 §2）；(b) 全局替换硬编码色为 Token/Element 变量；(c) 补充《管理端 UI 规范》文档（当前规范只覆盖移动端）。
6. **接口走网关基本合规**：仅 `ofpay/customer` 的 mock 回调用裸 `fetch` 直连，应改为经统一拦截器，保证 token/错误处理一致。
